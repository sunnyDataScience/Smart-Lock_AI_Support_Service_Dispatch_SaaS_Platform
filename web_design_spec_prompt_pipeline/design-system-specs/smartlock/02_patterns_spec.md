## 1. Form Patterns

### 1.1 工單建立表單（Work Order Creation Form）

**When to use**：
- Admin Panel 新增工單時
- 從 LINE Bot 轉入的客戶報修需人工補充時

**Structure**：
```
┌─────────────────────────────────────┐
│ 建立工單                             │
│ 填寫客戶報修資訊，系統將自動推薦技師     │
├─────────────────────────────────────┤
│ ── 客戶資訊 ──                       │
│ 客戶姓名 *                           │
│ ┌─────────────────────────────────┐ │
│ │ 陳先生                           │ │
│ └─────────────────────────────────┘ │
│ 聯絡電話 *         聯絡地址 *         │
│ ┌──────────────┐ ┌────────────────┐ │
│ │ 0912-345-678 │ │ 台北市信義區...  │ │
│ └──────────────┘ └────────────────┘ │
│                                     │
│ ── 鎖具資訊 ──                       │
│ 品牌 *             型號 *             │
│ ┌──────────────┐ ┌────────────────┐ │
│ │ [Yale     ▼] │ │ [YDD-424   ▼] │ │
│ └──────────────┘ └────────────────┘ │
│ 問題分類 *                           │
│ ┌─────────────────────────────────┐ │
│ │ [安裝 / 維修 / 保養 / 其他   ▼] │ │
│ └─────────────────────────────────┘ │
│ 問題描述 *                           │
│ ┌─────────────────────────────────┐ │
│ │ (textarea)                      │ │
│ │                                 │ │
│ └─────────────────────────────────┘ │
│ 0/500                               │
│                                     │
│ ── 服務等級 ──                       │
│ SLA 等級 *          預約時段          │
│ ┌──────────────┐ ┌────────────────┐ │
│ │ [一般 4hr ▼] │ │ [Date Picker] │ │
│ └──────────────┘ └────────────────┘ │
│                                     │
│ ── AI 推薦技師 ──（建立後顯示）       │
│                                     │
│   ┌────────┐  ┌─────────────────┐   │
│   │ 取消   │  │   建立工單 ▶     │   │
│   └────────┘  └─────────────────┘   │
└─────────────────────────────────────┘
```

**Behavior rules**：
- 欄位間距：`space-5`（20px）
- 區塊標題：`text-sm font-semibold text-slate-500 uppercase`，上方 `mt-6`
- 品牌 → 型號聯動：選擇品牌後，型號 Select 過濾為該品牌的型號
- 型號來源：必須使用 `BRAND_MODEL_LIST.md` 定義的品牌型號，禁止自由輸入
- 問題描述：textarea，max 500 字，顯示字數統計
- SLA 等級選項：緊急（2hr）/ 一般（4hr）/ 排程（24hr）
- Validation timing：
  - 首次：submit 時驗證全部
  - 修正後：onChange 即時驗證（已觸發過的欄位）
- Submit：
  - 未修改 → disabled
  - 送出中 → loading spinner + disabled
  - 成功 → success toast「工單 WO-{id} 已建立」+ 導向工單詳情
  - 失敗 → error toast + 保留表單內容

**Copy rules**：

| 場景 | 模板 | 範例 |
|------|------|------|
| 必填未填 | `請輸入{欄位名稱}` | 「請輸入客戶姓名」 |
| 格式錯誤 | `{欄位名稱}格式不正確` | 「電話號碼格式不正確」 |
| 建立成功 | `工單 {工單號} 已建立` | 「工單 WO-2026-0421-001 已建立」 |
| 建立失敗 | `工單建立失敗，請稍後再試` | — |

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 品牌/型號用聯動 Select | 讓用戶自由輸入型號（容易打錯） |
| 問題描述用 textarea + 字數統計 | 用 text input 寫長描述 |
| 建立後顯示 AI 推薦技師 | 建立後只顯示工單號，要另外找技師 |

### 1.2 範圍變更表單（Scope Change Form）

**When to use**：
- 技師到場後發現問題範圍與原報修不同
- 需要追加零件或服務項目

**Structure**：
```
┌─────────────────────────────────────┐
│ 範圍變更申請 — WO-2026-0421         │
├─────────────────────────────────────┤
│ 原始問題：指紋辨識異常               │
│ 原始費用：$2,400                     │
│                                     │
│ 變更原因 *                           │
│ ┌─────────────────────────────────┐ │
│ │ [零件損壞 / 型號不符 / 追加服務 ▼]│ │
│ └─────────────────────────────────┘ │
│                                     │
│ 變更描述 *                           │
│ ┌─────────────────────────────────┐ │
│ │ (textarea)                      │ │
│ └─────────────────────────────────┘ │
│                                     │
│ 追加零件                             │
│ ┌────────────┬──────┬────────┬───┐ │
│ │ [Select ▼] │ [1]  │ $800   │ 🗑 │ │
│ └────────────┴──────┴────────┴───┘ │
│ [+ 新增零件]                         │
│                                     │
│ ┌─────────────────────────────────┐ │
│ │ 原始費用    $2,400              │ │
│ │ 追加費用    +$800               │ │
│ │ ───────────────────             │ │
│ │ 變更後總計  $3,200              │ │
│ └─────────────────────────────────┘ │
│                                     │
│  ┌────────┐  ┌──────────────────┐   │
│  │ 取消   │  │ 提交變更申請 ▶   │   │
│  └────────┘  └──────────────────┘   │
└─────────────────────────────────────┘
```

**Behavior rules**：
- 顯示在 Modal（md size，520px）或 Tech PWA BottomSheet（full）
- 費用試算：追加零件即時計算，顯示差額
- 提交後：工單狀態自動變為 `scope_changed`
- 需管理員確認：scope change → 通知 Admin → Admin 確認或拒絕

**Edge cases**：
- 離線提交：存入 sync queue，上線後自動送出
- 管理員拒絕：技師收到通知 + 恢復原始範圍

### 1.3 完工報告表單（Completion Report Form）

**When to use**：
- 技師完成服務後提交完工報告
- Tech PWA 專用

**Structure**：參見 `01_components_spec.md` → `CompletionReportForm` 元件

**Behavior rules**：
- 5 區段依序填寫：檢核清單 → 零件明細 → 照片 → 功能測試 → 簽名
- 每區段獨立驗證，可跳躍填寫但不可跳過必填
- 草稿每 30 秒自動儲存至 IndexedDB
- 離線可完整填寫，上線自動同步
- 提交前顯示摘要確認：
  ```
  ┌─────────────────────────────────┐
  │ 確認提交完工報告？                │
  │                                 │
  │ 工單：WO-2026-0421              │
  │ 檢核：6/6 項完成                 │
  │ 零件：2 項，$1,900              │
  │ 照片：5 張                       │
  │ 功能測試：5/5 通過               │
  │ 簽名：已簽                       │
  │                                 │
  │  ┌────────┐  ┌───────────────┐  │
  │  │ 返回   │  │ 確認提交 ▶    │  │
  │  └────────┘  └───────────────┘  │
  └─────────────────────────────────┘
  ```
- 提交成功 → 工單狀態變 `completed` + success 畫面

**Copy rules**：

| 場景 | 模板 |
|------|------|
| 照片不足 | `請至少拍攝 {minCount} 張照片（目前 {current} 張）` |
| 簽名空白 | `請取得客戶簽名` |
| 提交成功 | `完工報告已提交，工單 {工單號} 已更新為「已完工」` |
| 草稿已儲存 | `草稿已自動儲存` |

### 1.4 Inline Edit（行內編輯）

**When to use**：
- 工單詳情頁修改單一欄位（如客戶電話、備註）
- Admin Panel 快速修改不需開完整表單

**Structure**：
```
View 模式：
  王技師 (指派技師)  [✏️]

Edit 模式：
  ┌──────────────────┐ ┌──┐ ┌──┐
  │ [技師 Select ▼]   │ │✓ │ │✕ │
  └──────────────────┘ └──┘ └──┘
```

**Rules**：
- 點擊 Edit icon → 元件切換為 input/select + auto focus
- Enter 確認、Esc 取消
- 儲存成功 → 恢復 View + 短暫綠色 flash（`bg-green-50` 2s fade）
- 儲存失敗 → error toast + 保留 edit 模式

## 2. Data Table Patterns

### 2.1 工單列表表格（Work Order Data Table）

**When to use**：
- Admin Panel 主要工單管理介面
- 支援 13 狀態篩選、SLA 欄位、批次指派

**Structure**：
```
┌──────────────────────────────────────────────────────┐
│ 📋 工單管理                      [+ 建立工單] [📥 匯出]│
├──────────────────────────────────────────────────────┤
│ 🔍 搜尋工單號/客戶...                                 │
│ [狀態 ▼] [品牌 ▼] [技師 ▼] [日期範圍 ▼] [清除篩選]    │
│ Active: [● 進行中 ✕] [● 已指派 ✕]                    │
├────┬──────────┬────────┬────────┬──────┬──────┬─────┤
│ ☐  │ 工單號 ↕  │ 客戶   │ 鎖具型號│ 狀態 │ SLA  │技師 │
├────┼──────────┼────────┼────────┼──────┼──────┼─────┤
│ ☐  │WO-0421-01│陳先生  │Yale    │● 進行│🟢2:30│王技師│
│    │          │        │YDD-424 │  中  │      │     │
├────┼──────────┼────────┼────────┼──────┼──────┼─────┤
│ ☐  │WO-0421-02│林小姐  │Gateman │● 待指│🔴0:15│未指派│
│    │          │        │WF-20   │  派  │      │     │
├────┼──────────┼────────┼────────┼──────┼──────┼─────┤
│ ☐  │WO-0420-05│張先生  │Samsung │● 已完│ ── │李技師│
│    │          │        │DP609   │  工  │      │     │
├────┴──────────┴────────┴────────┴──────┴──────┴─────┤
│ 顯示 1-25 / 共 156 筆        < 1 2 3 ... 7 >       │
└──────────────────────────────────────────────────────┘
```

**Behavior rules**：
- **排序**：點擊 column header 切換 asc → desc → none
  - 預設排序：SLA 剩餘時間 ascending（最緊急在上）
- **篩選**：
  - 狀態：multi-select dropdown，13 狀態可複選，勾選後即時篩選
  - 品牌：multi-select，來源 `BRAND_MODEL_LIST.md`
  - 技師：combobox（可搜尋），支援「未指派」選項
  - 日期範圍：date range picker，預設「本週」
- **搜尋**：toolbar search，300ms debounce，搜尋工單號 + 客戶姓名 + 電話
- **選取**：Checkbox + Shift 多選
- **Row click**：導向工單詳情頁
- **Row action（⋮）**：查看 / 編輯 / 指派 / 複製工單 / 取消（Danger）
- **分頁**：底部分頁器，每頁 10/25/50/100
- **URL 同步**：所有篩選條件同步至 URL query string

**批次指派（Bulk Assign）**：
```
選取 3 筆後頂部浮出：
┌──────────────────────────────────────────────────────┐
│ ✓ 已選取 3 筆工單  [批次指派 ▶] [匯出] [✕ 取消選取]    │
└──────────────────────────────────────────────────────┘

批次指派 Dialog：
┌──────────────────────────────────┐
│ 批次指派 — 3 筆工單               │
├──────────────────────────────────┤
│ 指派技師 *                        │
│ ┌──────────────────────────────┐ │
│ │ [搜尋技師...            ▼]   │ │
│ └──────────────────────────────┘ │
│                                  │
│ 🤖 AI 推薦  AI 推薦               │
│ ┌──────────────────────────────┐ │
│ │ 👤 王技師 ★★★★☆             │ │
│ │    距離最近 + Yale 認證       │ │
│ │                    [選擇]    │ │
│ └──────────────────────────────┘ │
│                                  │
│ 已選工單：                        │
│ • WO-0421-01 — 陳先生 (SLA 🟢)  │
│ • WO-0421-02 — 林小姐 (SLA 🔴)  │
│ • WO-0420-05 — 張先生 (SLA 🟡)  │
│                                  │
│  ┌────────┐  ┌───────────────┐   │
│  │ 取消   │  │ 確認指派 ▶    │   │
│  └────────┘  └───────────────┘   │
└──────────────────────────────────┘
```

**Edge cases**：

| 狀態 | 處理 |
|------|------|
| 載入中 | 5 行 skeleton rows，含 SLA 欄位骨架 |
| 無工單 | 插圖 +「目前沒有任何工單」+ [建立工單] CTA |
| 搜尋無結果 | 「找不到符合 "{keyword}" 的工單」+ [清除搜尋] |
| 篩選無結果 | 「目前的篩選條件沒有符合的工單」+ active filters 列表 + [清除篩選] |
| API 錯誤 | 「工單列表載入失敗」+ [重試] |
| 批次指派失敗 | 「{N} 筆指派成功，{M} 筆失敗」+ 失敗列表 |

**Mobile（< 768px）**：
- 轉為 WorkOrderCard List（垂直堆疊）
- Toolbar 收合為 icon buttons
- 篩選轉為 Filter BottomSheet
- 不支援批次選取（太難操作）

## 3. Search & Filter Patterns

### 3.1 工單搜尋（Work Order Search）

**When to use**：
- Admin Panel 工單列表頂部搜尋
- 快速查找特定工單

**Structure**：
```
┌──🔍──────────────────────────────────┐
│   搜尋工單號、客戶姓名、電話...    [✕] │
└──────────────────────────────────────┘
↓ 輸入 2+ 字元後出現建議
┌──────────────────────────────────────┐
│ 最近搜尋：WO-0421, 陳先生            │
├──────────────────────────────────────┤
│ 🔍 WO-2026-0421-001 — 陳先生        │
│ 🔍 WO-2026-0421-002 — 陳太太        │
│ 🔍 陳先生 — 3 筆工單                 │
└──────────────────────────────────────┘
```

**Rules**：
- Debounce 300ms
- 最少 2 字元觸發搜尋
- 搜尋範圍：工單號、客戶姓名、客戶電話、鎖具型號
- 最近搜尋：max 5 筆，存 localStorage
- 搜尋結果分類：工單匹配 / 客戶匹配
- No result：「找不到 "{keyword}" 的結果，請調整關鍵字」

### 3.2 工單篩選面板（Work Order Filter Panel）

**When to use**：
- 工單列表多條件篩選

**Structure（Desktop — Inline Filter）**：
```
┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
│ 狀態    ▼  │ │ 品牌    ▼  │ │ 技師    ▼  │ │ 日期範圍 ▼ │
└────────────┘ └────────────┘ └────────────┘ └────────────┘
Active filters:
[● 進行中 ✕] [● 已指派 ✕] [Yale ✕] [本週 ✕]  [清除全部]
```

**Structure（Mobile — Filter BottomSheet）**：
```
┌─────────────────────────────────┐
│ ──── (pull indicator) ────      │
│ 篩選條件              [清除全部] │
├─────────────────────────────────┤
│ 狀態                             │
│ [已建立] [已指派] [已接受]        │
│ [進行中] [範圍變更] [待料中]      │
│ [延遲] [已完工] [需返工]          │
│ [已確認] [已歸檔] [已取消] [爭議] │
│                                  │
│ 品牌                             │
│ [Yale] [Gateman] [Samsung] ...  │
│                                  │
│ 技師                             │
│ ┌────────────────────────────┐  │
│ │ 搜尋技師...                │  │
│ └────────────────────────────┘  │
│                                  │
│ 日期範圍                         │
│ [今天] [本週] [本月] [自訂]      │
│                                  │
│ ┌────────────────────────────┐  │
│ │      套用篩選 ({N} 項)      │  │
│ └────────────────────────────┘  │
└─────────────────────────────────┘
```

**Behavior**：
- Desktop：選擇條件後立即篩選（不需「套用」按鈕）
- Mobile：BottomSheet 模式，有「套用篩選」按鈕
- Active filter 顯示為可關閉的 Tag
- 「清除全部篩選」按鈕
- URL 同步：篩選條件反映在 URL query string（方便分享/書籤）
- 狀態篩選：chip toggle 模式（點擊切換選中/未選中）
- TanStack Query：篩選變更 → 新的 queryKey → 自動 refetch

**Copy rules**：

| 場景 | 文案 |
|------|------|
| 有 active filter | 「顯示 {N} 筆結果」 |
| 無結果 | 「目前的篩選條件沒有符合的工單」 |
| 清除後 | 「已清除所有篩選條件」（toast） |

## 4. Navigation Patterns

### 4.1 Admin Panel 側邊導航（Sidebar Navigation）

**Structure（展開 240px）**：
```
┌──────────────────────┐
│ 🔒 SmartLock         │  ← Logo + 平台名
│    Admin Panel       │
├──────────────────────┤
│                      │
│ 📊 儀表板            │  ← active: bg-blue-50 + border-l-blue-600
│ 📋 工單管理          │
│ 🗂️ 派工看板          │
│ 🗺️ 即時地圖          │

**Structure**：

│┌─────────┐│┌─────────┐│┌─────────┐│┌─────────┐│┌────────────┐│
││WO-0421  ││ │WO-0420  ││ │WO-0419  ││ │WO-0418  ││ │WO-0417     ││
││陳先生   ││ │林小姐   ││ │張先生   ││ │李太太   ││ │周先生      ││
││Yale     ││ │Gateman  ││ │Samsung  ││ │Yale     ││ │Gateman     ││
││🔴 0:15  ││ │🟢 3:45  ││ │🟡 1:20  ││ │ ──     ││ │⚠️ 需返工    ││
│└─────────┘│└─────────┘│└─────────┘│└─────────┘│└────────────┘│
│┌─────────┐│┌─────────┐│┌─────────┐│           │┌────────────┐│
││WO-0421  ││ │WO-0420  ││ │WO-0419  ││           ││WO-0416     ││
││...      ││ │...      ││ │...      ││           ││...         ││
│└─────────┘│└─────────┘│└─────────┘│           │└────────────┘│
│           │           │           │           │              │
│ ┆ ┆ ┆ ┆ ┆│           │ ┆ ┆ ┆ ┆ ┆│           │              │
│(scroll)  │           │(scroll)   │           │              │
└───────────┴───────────┴───────────┴───────────┴──────────────┘
```

**Behavior rules**：

**拖曳規則**：
- 引擎：`@dnd-kit/core` + `@dnd-kit/sortable`
- 啟動：mouse press 150ms / touch long-press 300ms
- 拖曳中視覺：
  - 拖曳卡片：`shadow-kanban` + `scale(1.02)` + `rotate(2deg)` + `opacity(0.9)`
  - 原位 placeholder：`border-2 border-dashed border-slate-300 bg-slate-50`
  - 有效目標欄：`bg-blue-50` + 藍色 drop indicator 線
  - 無效目標欄：`bg-red-50/30` + `cursor-not-allowed`
- 有效轉換：見 `01_components_spec.md` KanbanBoard 拖曳規則表
- 無效拖曳：卡片回彈原位 + shake 動畫（`translateX(-5px, 5px)` × 3，200ms）

**Optimistic UI**：
```
拖曳放下
  └→ 卡片立即移至新欄（opacity: 0.7）
  └→ API 呼叫
       ├→ 成功：opacity 恢復 1.0 + 綠色 flash 0.5s
       └→ 失敗：卡片動畫回彈原位 + error toast
```

**即時更新（WebSocket）**：
- 其他用戶操作 → 服務端推播 → 卡片平滑動畫移動至新欄
- 移動中卡片有 2s 高亮（`ring-2 ring-yellow-400`）
- 衝突處理：如果用戶正在拖曳的卡片被其他人移動 → toast 通知 + 卡片更新

**Column 互動**：
- Header 點擊數量 Badge → 摺疊/展開欄位
- 摺疊後：只顯示 header + 數量
- 超過 max-height → 欄位內垂直 scroll

**Edge cases**：

| 情境 | 處理 |
|------|------|
| 拖曳途中網路斷線 | 卡片回彈 +「網路中斷，請稍後再試」toast |
| 拖曳到「已派工」 | 觸發指派 Dialog（選擇技師），取消 → 回彈 |
| 卡片被其他人移走 | 正在拖曳的卡片消失 + toast「此工單已被 {user} 更新」 |
| 大量工單（>50/欄） | 虛擬滾動（virtualized list） |
| 看板全空 | 所有欄位顯示 empty state |

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| Optimistic UI — 先移後驗 | 等 API 才移動（用戶覺得卡） |
| 無效拖曳有 shake + 紅底回饋 | 無效拖曳靜悄悄地回彈 |
| WebSocket 外部更新有動畫 + highlight | 卡片突然跳位不知為何 |
| 拖至「已派工」觸發指派 Dialog | 拖曳即指派不經確認 |
| 摺疊少用欄位節省空間 | 5 欄全展開擠爆螢幕 |

| 地圖 Pin | MapView | Pin 色彩對應 SLA 級別（未指派工單） |
| Tech PWA 工單卡 | WorkOrderCard | 底部 SLA 進度條 + SLACountdown |
| LINE Bot 推播 | 文字訊息 | emoji + 文字「⚠️ SLA 即將逾時，剩餘 15 分鐘」 |

**級別轉換動效**：
- Green → Yellow：色彩漸變 transition 300ms + 邊框脈動開始
- Yellow → Red：色彩漸變 300ms + pulse 開始 + 震動（Tech PWA）
- Red → Black：色彩切換至深底白字 + 閃爍開始 + 強震動 + dispatch toast

**SLA 計算邏輯**：
```
SLA 總時長 = SLA 等級時數（緊急 2hr / 一般 4hr / 排程 24hr）
已用時間 = now - 工單建立時間（扣除暫停時段）
剩餘百分比 = (SLA 總時長 - 已用時間) / SLA 總時長 × 100
暫停狀態 = material_pending / delayed 期間不計入
```

**Behavior rules**：
- 每秒更新（< 5 分鐘時）
- 每分鐘更新（>= 5 分鐘時）
- 暫停中顯示「⏸ 已暫停」+ 灰色底
- 逾時超過 24 小時：顯示「逾時 1 天 2 小時」

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 全系統統一使用此 4 級制 | 各處自定義 SLA 顏色 |
| 色彩 + 動效 + 文字三重指示 | 只靠顏色區分 |
| 暫停狀態清楚標示「已暫停」 | 暫停中還在倒數（誤導） |
| 逾時用深底白字 + 閃爍（最高警示） | 逾時跟紅色一樣處理 |
| Tech PWA 紅色/黑色級別加震動 | 緊急通知只有視覺沒有觸覺 |

## 11. Offline-First Pattern

**When to use**：
- Technician PWA 在地下室、電梯間等訊號差的場所
- 確保技師可以繼續操作不中斷

**Structure**：

**離線偵測**：
```
Online:
  (正常 UI)

Offline:
┌──────────────────────────────────┐
│ 📡 離線模式 — 操作將在恢復連線後同步 │
├──────────────────────────────────┤
│                                  │
│  (可操作的離線 UI)                │
│                                  │
└──────────────────────────────────┘
```

**技術架構**：

```
┌─────────────────────────────────────────┐
│ Service Worker (Workbox)                │
├─────────────────────────────────────────┤
│ Cache Strategy:                         │
│   • App Shell: Cache First              │
│   • API Data: Stale While Revalidate    │
│   • Images: Cache First (max 100)       │
│   • API Mutations: Network First        │
│     └→ 失敗 → Queue to IndexedDB       │
├─────────────────────────────────────────┤
│ IndexedDB Storage:                      │
│   • work_orders: 已接工單快取           │
│   • drafts: 完工報告草稿               │
│   • sync_queue: 待同步操作佇列          │
│   • photos: 待上傳照片 blob             │
├─────────────────────────────────────────┤
│ Sync Queue:                             │
│   • 操作時間戳 + 操作類型 + payload     │
│   • FIFO 順序同步                       │
│   • 最大佇列：50 筆操作                 │
│   • 每筆操作最多重試 3 次               │
├─────────────────────────────────────────┤
│ Conflict Resolution:                    │
│   • Last Write Wins (server timestamp)  │
│   • 衝突時彈出通知讓用戶決定            │
│   • 保留本地版本供比較                  │
└─────────────────────────────────────────┘
```

**Behavior rules**：

**離線可執行操作**：

| 操作 | 離線支援 | 儲存方式 |
|------|---------|---------|
| 瀏覽已接工單 | ✅ | IndexedDB cache |
| 填寫完工報告 | ✅ | IndexedDB drafts |
| 拍照 | ✅ | IndexedDB photos blob |
| 電子簽名 | ✅ | IndexedDB drafts |
| 接受新工單 | ❌（需即時確認） | — |
| 查看新派工 | ❌（需即時資料） | — |
| 變更工單狀態 | ✅ (queue) | sync_queue |

**離線模式 Banner**：
- 位置：頂部固定 Banner
- 背景：`#F1F5F9`（Slate-100）
- Icon：`WifiOff`（Slate-500）
- 文字：「離線模式 — 操作將在恢復連線後自動同步」
- 不可關閉（持續顯示直到恢復連線）

**恢復連線流程**：
```
偵測到網路恢復
  └→ Banner 更新：「正在同步 {N} 筆離線操作...」
  └→ FIFO 順序逐筆同步 sync_queue
       ├→ 成功：移除佇列項 + progress 更新
       ├→ 衝突：彈出衝突解決 Dialog
       └→ 失敗（重試 3 次後）：標記為失敗 + 通知用戶
  └→ 全部完成：Banner 消失 + success toast「離線操作已全部同步」
```

**衝突解決 Dialog**：
```
┌──────────────────────────────────┐
│ ⚠️ 資料衝突                       │
├──────────────────────────────────┤
│ 工單 WO-2026-0421 在你離線期間    │
│ 被其他人修改。                     │
│                                  │
│ 你的版本：狀態 → 已完工            │
│ 伺服器版本：狀態 → 需返工          │
│ 修改者：陳管理員 @ 14:30          │
│                                  │
│  ┌──────────────┐ ┌────────────┐ │
│  │ 使用伺服器版本 │ │ 使用我的版本│ │
│  └──────────────┘ └────────────┘ │
└──────────────────────────────────┘
```

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 離線 Banner 持續顯示（不可關閉） | 用戶不知道自己在離線 |
| 離線操作存入 sync queue，上線自動同步 | 離線時完全禁止操作 |
| 衝突讓用戶選擇（不自動覆蓋） | 自動覆蓋用戶的離線操作 |
| 同步進度可視化 | 背景靜默同步，用戶不知道狀態 |
| 草稿自動存 IndexedDB（30s interval） | 只存 memory，關閉 app 遺失 |

## 12. Swipe Action Pattern

**When to use**：
- Tech PWA 工單池（接受/跳過工單）
- Tech PWA 工單列表快速操作

**Structure**：
```
靜止狀態：
┌──────────────────────────────────┐
│ WO-2026-0421                     │
│ 陳先生 — Yale YDD-424           │
│ ● 待接  🟡 剩餘 01:20           │
└──────────────────────────────────┘

右滑 (Accept)：
     ┌──────────────────────────────┐
  ✅ │ WO-2026-0421                 │
接受 │ 陳先生 — Yale YDD-424        │  ← 綠色背景漸顯
     │ ● 待接  🟡 剩餘 01:20        │
     └──────────────────────────────┘

左滑 (Skip)：
┌──────────────────────────────┐
│ WO-2026-0421                 │ ❌
│ 陳先生 — Yale YDD-424        │ 跳過  ← 紅色背景漸顯
│ ● 待接  🟡 剩餘 01:20        │
└──────────────────────────────┘
```

**Behavior rules**：

**手勢閾值**：
- 觸發閾值：卡片寬度的 40%
- < 40%：釋放回彈
- >= 40%：觸發動作
- 滑動速度 > 500px/s：無論距離都觸發

**視覺回饋**：

| 滑動方向 | 背景色 | Icon | 文字 | 觸發動作 |
|---------|--------|------|------|---------|
| 右滑 | `#10B981` Green → 隨距離增加 opacity | `CheckCircle` | 「接受」 | 接受工單 |
| 左滑 | `#EF4444` Red → 隨距離增加 opacity | `XCircle` | 「跳過」 | 跳過工單 |

**動效時間軸**：
```
Touch Start
  └→ 卡片跟隨手指水平移動
  └→ 背景色 opacity 隨距離漸增（0% → 100%）
  └→ Icon scale 隨距離漸增（0.5 → 1.0）

達到閾值 (40%)
  └→ Haptic feedback（輕震動）
  └→ Icon scale 跳至 1.2 再回 1.0（bounce）
  └→ 背景色 opacity 100%

Release（已過閾值）
  └→ 卡片繼續滑出螢幕（300ms ease-out）
  └→ 觸發確認 callback

Release（未過閾值）
  └→ 卡片回彈原位（200ms spring）
  └→ 背景色消失
```

**確認邏輯**：
- 接受：即時 optimistic UI（卡片消失 + success toast）→ API 呼叫
- 跳過：卡片消失（無 toast）→ 工單回到工單池底部
- API 失敗（接受）：卡片動畫回來 + error toast「接受失敗，請重試」

**Edge cases**：

| 情境 | 處理 |
|------|------|
| 垂直 scroll 中誤觸水平 | 水平移動 > 10px 時才啟動 swipe |
| 快速連續 swipe | 每次只處理一張（queue） |
| 工單已被其他人接走 | error toast「此工單已被 {name} 接受」+ 移除卡片 |
| 離線 swipe | 接受存入 sync queue + toast「離線操作，將自動同步」 |

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 40% 閾值 + haptic feedback | 滑一點就觸發（太敏感） |
| 背景色漸顯 + icon 漸放大 | 只有卡片移動沒有背景回饋 |
| 達到閾值有 haptic bounce | 沒有觸覺回饋（不知道是否到閾值） |
| 垂直/水平手勢互斥 | 垂直 scroll 和水平 swipe 衝突 |

## 13. Completion Report Wizard Pattern

**When to use**：
- Tech PWA 技師完成服務後填寫完工報告
- 5 步驟引導式表單

**Structure**：
```
┌─────────────────────────────────────┐
│ 完工報告 — WO-2026-0421             │
│ ① ─ ② ─ ③ ─ ④ ─ ⑤                │
│ ✅    ✅   ●    ○    ○              │
│ 檢核  零件  照片  測試  簽名         │
├─────────────────────────────────────┤
│                                     │
│ 步驟 3：拍攝照片                     │
│ 請拍攝至少 3 張施工照片              │
│                                     │
│ ┌────┐ ┌────┐ ┌────┐               │
│ │ 📷 │ │ 📷 │ │ +  │               │
│ │施工前│ │施工後│ │    │              │
│ └────┘ └────┘ └────┘               │
│                                     │
│ 已拍 2 / 至少 3 張                  │
│                                     │
├─────────────────────────────────────┤
│ ┌──────────┐  ┌──────────────────┐  │
│ │ ← 上一步 │  │     下一步 ▶     │  │
│ └──────────┘  └──────────────────┘  │
└─────────────────────────────────────┘
```

**5 個步驟**：

| 步驟 | 名稱 | 必填 | 驗證規則 |
|------|------|------|---------|
| 1 | 服務檢核清單 | ✅ | 所有必要項目需勾選 |
| 2 | 使用零件 | 視情況 | 有用零件需填寫（可選「未使用零件」） |
| 3 | 施工照片 | ✅ | 至少 3 張照片 |
| 4 | 功能測試 | ✅ | 所有測試項目需有結果（Pass/Fail） |
| 5 | 客戶簽名 | ✅ | 簽名筆畫 >= 5 |

**Behavior rules**：

**步驟導航**：
- 步驟指示器：水平圓形 indicator + 連接線
  - 完成 ✅：`bg-green-500 text-white`
  - 當前 ●：`bg-blue-600 text-white` + 脈動光環
  - 未到 ○：`bg-slate-200 text-slate-500`
  - 連接線：完成 `border-green-500` / 未到 `border-slate-200`
- 可回退：已完成步驟可點擊 indicator 回去修改
- 不可跳躍：未完成當前步驟不能跳到下一步
- 按「下一步」時驗證當前步驟：
  - 通過 → 滑動到下一步
  - 未通過 → shake 動畫 + 錯誤標示

**草稿自動儲存**：
- 每 30 秒自動儲存至 IndexedDB
- 切換步驟時自動儲存
- App 關閉/切換後再打開 → 恢復草稿 + 提示「是否繼續上次的報告？」
- 草稿保留 7 天

**最終提交**：
- 第 5 步完成後顯示摘要確認（見 Form Patterns 1.3）
- 提交按鈕：CTA variant（琥珀色）
- 提交前驗證：所有步驟都 ✅
- 提交中：full overlay「正在上傳報告...」+ progress bar
  - 照片上傳進度（最耗時）
  - 資料送出進度
- 提交成功：
  ```
  ┌─────────────────────────────────┐
  │                                 │
  │          ✅                      │
  │                                 │
  │     完工報告已送出               │
  │     工單 WO-2026-0421           │
  │     等待管理員確認               │
  │                                 │
  │  ┌───────────────────────────┐  │
  │  │      返回工單列表          │  │
  │  └───────────────────────────┘  │
  └─────────────────────────────────┘
  ```

**Edge cases**：

| 情境 | 處理 |
|------|------|
| 離線提交 | 存入 sync queue + toast「離線模式，報告將在恢復連線後自動上傳」|
| 照片上傳失敗 | 重試 3 次 → 標記失敗照片 + 允許重新上傳 |
| 中途離開 | 確認 Dialog「報告尚未完成，草稿已自動儲存，確定離開？」|
| 草稿恢復 | Dialog「發現未完成的報告 (WO-xxx)，是否繼續？」[繼續] / [放棄] |
| 功能測試有 Fail | 警告「有測試項目未通過，是否仍要提交？」|

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 步驟指示器顯示進度 | 不知道共幾步 |
| 每步驗證再進下一步 | 最後才驗證（回頭修改很痛苦） |
| 草稿自動儲存 + 離開提醒 | 離開遺失所有進度 |
| 離線可填寫，上線自動提交 | 離線無法操作 |
| 照片上傳顯示進度 | 提交後不知道要等多久 |

**Behavior rules**：

**統一 AI 視覺標識**：
- 色彩：`#6366F1` Indigo（所有 AI 相關元素）
- Badge：`AIRecommendationBadge` 元件
- Icon：`Sparkles`（lucide-react）
- Tooltip：永遠提供推薦理由

**人工覆寫原則**：
- 所有 AI 推薦都必須有「手動覆寫」選項
- 覆寫不需要理由（降低摩擦）
- 覆寫後記錄到 audit log（供 AI 學習）
- 覆寫 UI：在 AI 推薦列表下方提供「手動搜尋」入口

**信心度顯示規則**：

| 信心度 | 顯示方式 | 說明 |
|--------|---------|------|
| >= 90% | 顯示百分比 + 「AI 推薦」badge | 高信心度，主動推薦 |
| 70-89% | 顯示百分比 + 「AI 建議」badge | 中信心度，建議參考 |
| < 70% | 不顯示信心度，只顯示「AI 參考」 | 低信心度，避免過度信任 |
| 無 AI 結果 | 不顯示 AI 區塊，直接手動搜尋 | AI 無法產生推薦 |

**Edge cases**：

| 情境 | 處理 |
|------|------|
| AI 推薦載入中 | Skeleton + 「AI 正在分析...」 |
| AI 無法產生推薦 | 隱藏 AI 區塊 + 直接顯示手動搜尋 |
| AI 推薦被覆寫 | 記錄覆寫 + 不再強調 AI（尊重人工決策） |
| AI 服務異常 | 靜默降級，不顯示 AI 區塊，不影響核心流程 |

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 統一使用 Indigo 色系標識 AI | AI 推薦用不同顏色 |
| 永遠提供推薦理由（tooltip 或 inline） | 只說「AI 推薦」不解釋為什麼 |
| 永遠有人工覆寫選項 | AI 推薦不可覆寫 |
| 低信心度不顯示百分比 | 顯示「AI 推薦 35%」（降低信任） |
| AI 異常時靜默降級 | AI 異常導致整個功能不能用 |
| 覆寫記錄到 audit log | 覆寫行為不記錄（AI 無法學習） |

## 15. Real-time Status Update Pattern

**When to use**：
- 所有需要即時反映狀態變更的場景
- WebSocket 事件驅動的 UI 更新

**Structure**：

**事件流架構**：
```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   Server     │    │  WebSocket   │    │   Client     │
│   Event      │───►│   Gateway    │───►│   Handler    │
│   Source     │    │              │    │              │
└──────────────┘    └──────────────┘    └──┬───────────┘
                                          │
                    ┌─────────────────────┤
                    │                     │
              ┌─────▼────┐         ┌──────▼─────┐
              │ UI Update │         │ Notification│
              │ Handler   │         │ Handler     │
              └─────┬────┘         └──────┬─────┘
                    │                     │
         ┌──────────┤                     │
         │          │                     │
   ┌─────▼───┐ ┌───▼─────┐        ┌─────▼──────┐
   │ Kanban  │ │ Table   │        │ Toast /    │
   │ Board   │ │ Row     │        │ Sound /    │
   │ Update  │ │ Update  │        │ Vibration  │
   └─────────┘ └─────────┘        └────────────┘
```

**Behavior rules**：

**事件類型與 UI 反應**：

| WebSocket 事件 | Admin Panel 反應 | Tech PWA 反應 |
|---------------|-----------------|---------------|
| `wo.created` | Kanban 待指派欄 + 新卡片 slide-in / 表格新行 highlight | — |
| `wo.assigned` | Kanban 卡片移至已派工 / 表格 StatusBadge 更新 | dispatch toast + 震動 |
| `wo.accepted` | Kanban 更新 / info toast | — |
| `wo.status_changed` | Kanban 卡片移動動畫 + 表格更新 + info toast | 工單卡片更新 |
| `wo.sla_warning` | warning toast + KPI 更新 | warning toast + 強震動 |
| `wo.sla_expired` | 全局 Banner + 聲音提示 | 強震動 + persistent toast |
| `wo.completed` | Kanban 卡片移至已完工 + success toast | — |
| `tech.location` | 地圖技師 pin 平滑移動 | — |
| `tech.status_changed` | 技師列表更新 | — |

**Optimistic UI vs Server-sent**：

| 類型 | 策略 | 說明 |
|------|------|------|
| 用戶自己的操作 | Optimistic UI | 立即更新 → 等 API 確認 → 失敗回彈 |
| 其他用戶的操作 | Server-sent | WebSocket 推播 → 動畫更新 + toast |
| 系統自動操作 | Server-sent | WebSocket 推播 → 動畫更新 + toast |

**UI 更新動效**：

| 更新類型 | 動效 | 持續 |
|---------|------|------|
| 新增項目 | slide-in + fade-in | 300ms |
| 移動項目（Kanban） | translateX/Y 平滑移動 | 400ms ease |
| 狀態變更 | StatusBadge 色彩 transition + 2s highlight | 2300ms |
| 移除項目 | fade-out + collapse | 300ms |
| 數值變更（KPI） | 數字 counter 動畫 | 500ms |
| 地圖 pin 移動 | 平滑位移 | 1000ms linear |

**通知優先級**：

| 優先級 | 觸發條件 | Admin 通知 | PWA 通知 |
|--------|---------|-----------|---------|
| Critical | SLA 逾時、系統異常 | Banner + 聲音 | 系統推播 + 強震動 + persistent toast |
| High | SLA 警告、新工單指派 | warning/dispatch toast | 推播 + 震動 + toast |
| Medium | 狀態更新、完工通知 | info toast | toast |
| Low | 技師位置更新、一般通知 | 靜默 UI 更新 | 靜默 UI 更新 |

**WebSocket 連線管理**：
```
連線成功
  └→ 正常運作

連線中斷
  └→ 頂部 Banner「即時更新暫時中斷」
  └→ 指數退避重連：1s → 2s → 4s → 8s → 16s → 30s(max)
  └→ 重連成功：
       └→ Banner 消失
       └→ 請求差異更新（missed events since disconnect）
       └→ UI 批次更新

5 次重連失敗
  └→ Banner 更新：「無法連線，請檢查網路」+ [手動重連] 按鈕
  └→ 降級為輪詢模式（30s interval）
```

**TanStack Query 整合**：
```typescript
// WebSocket 事件 → invalidate 相關 query
ws.on('wo.status_changed', (event) => {
  // 1. Optimistic cache update
  queryClient.setQueryData(['workOrders', event.woId], (old) => ({
    ...old,
    status: event.newStatus
  }));
  // 2. Invalidate list queries for refetch
  queryClient.invalidateQueries({ queryKey: ['workOrders', 'list'] });
  // 3. Invalidate KPI queries
  queryClient.invalidateQueries({ queryKey: ['dashboard', 'kpi'] });
});
```

**Edge cases**：

| 情境 | 處理 |
|------|------|
| 大量同時更新 | 批次處理（100ms debounce），合併動畫 |
| 用戶正在操作中收到更新 | 延遲顯示（等用戶操作完成），toast 通知 |
| 拖曳中收到該卡片的更新 | 等拖曳完成再更新，衝突時 toast 通知 |
| 離線後恢復 | 批次拉取 missed events → 合併更新 |
| WebSocket 無法連線 | 降級為 30s 輪詢 |

**Do / Don't**：

| ✅ Do | ❌ Don't |
|-------|---------|
| 自己的操作用 Optimistic UI | 所有操作都等 server 回來 |
| 外部更新有動畫 + highlight | 資料突然變了不知為何 |
| WebSocket 斷線有明確提示 | 靜默斷線用戶不知道 |
| 指數退避重連 + 降級輪詢 | 無限快速重連（耗資源） |
| 批次處理大量更新 | 100 個更新觸發 100 次 re-render |
| Critical 通知用聲音+震動 | SLA 逾時只有小 toast |
