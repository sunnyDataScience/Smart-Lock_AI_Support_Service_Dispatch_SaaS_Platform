# 進度報告 v1.0.7：llm_usage_log 新增 user_question / ai_reply 兩欄，5 個 LLM 呼叫點全面紀錄輸入輸出原文

- **版本**: v1.0.7（前版：v1.0.6 → 本版升級類型：MINOR）
- **Commit**: 待補（本次 commit）
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `agent/storage/`（DDL + logger）+ `agent/harness/`（5 call sites 中的 4 個）+ `agent/quality/`（quality_judge call site）+ `SQL/Schema_v2_extensions.sql`（doc-sync DDL）

## 變更摘要 (WHAT)

1. **DDL 升級** (`agent/storage/postgres_impl.py:208-232`)：`llm_usage_log` 表新增 `user_question TEXT` 與 `ai_reply TEXT` 兩欄；新增 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 升級區塊讓既有資料表自動補欄位。
2. **Logger 簽名擴充** (`postgres_impl.py:136-186`、`harness/llm_metrics.py:73-130`)：
   - `PostgresAuditStorage.log_llm_call()` 新增 `user_question`、`ai_reply` 兩個 kwargs。
   - `log_simple()` 同步擴充；若呼叫端未傳 `ai_reply` 但 `response.content` 有值會自動帶入（含 list-of-blocks 的 text 抽取）。
3. **5 個 call site 全部串上原文**：
   - `harness/debounce.py:_audit_agent_result()` — `_audit_agent_result(... user_question=display)`，逐 step 取 `ai_msg.content` 當 `ai_reply`（多模態 list 內容自動抽 text）
   - `harness/memory_manager.py` — `user_question=dialogue_text`
   - `harness/output_validator.py` — `user_question=prompt`（含原 AI 回覆 + 違規條款）
   - `harness/profile_updater.py` — `user_question="使用者: ...\\n客服: ..."`
   - `quality/quality_check.py` — `user_question=prompt`（judge prompt 含 case + answer）
4. **Schema doc-sync**：`SQL/Schema_v2_extensions.sql` 同步加上欄位定義 + COMMENT + ADD COLUMN IF NOT EXISTS。

## 背景與動機 (WHY)

`llm_usage_log` 原本只記 token / latency / success；要做 bad-case 回溯、看模型實際拿到什麼提示、回出什麼內容，得另外撈 audit_log 並交叉比對 timestamp，效率極差。

直接把使用者問題原文與 AI 回覆原文存進同一筆 `llm_usage_log`，後續 web admin dashboard `/admin/reports/llm-cost` 可以一站式 join token + latency + content；查 P95 慢回覆時也能立刻看內容，不必再跨表 join。

PII 處理對齊既有 `audit_log.content` 慣例：原文不截斷不遮罩，遮罩工具 `_mask_pii()`（`postgres_impl.py:30-34`）留給對外展示前再套。

## 影響評估 (IMPACT)

- **破壞性變更**: 無
  - DDL 用 `ADD COLUMN IF NOT EXISTS`，舊資料表自動升級
  - logger 兩個新參數都有 `= None` 預設值，舊呼叫端不傳也不會壞
  - `log_simple()` 對 `ai_reply` 自動取 `response.content`，既有 4 個呼叫端不改也能直接受惠
- **資料量影響**: `user_question` 在 react_agent 流程會在每個 step 重複塞同一份（reasoning + tool-call + final answer 約 1-3 筆），實測 query 平均 200-500 字，單筆 +1KB 級距；DB 容量增長可接受。
- **後續動作**: 無 migration 需求；下次部署啟動時 DDL 自動執行。

```bash
# 3. 抽查資料
psql $POSTGRES_URI -c "SELECT call_site, LEFT(user_question, 50), LEFT(ai_reply, 50) FROM llm_usage_log ORDER BY id DESC LIMIT 10;"

# 4. 編譯 / import 驗證（已執行通過）
python -m py_compile agent/storage/postgres_impl.py agent/harness/*.py agent/quality/quality_check.py
```
