- **Commit**: `8a8b236` (2026-05-05 00:42)

## 變更摘要 (WHAT)

- `agent/product_info/__init__.py`：新增 `_is_brand_common()` helper（識別 `{Brand}/_*` 檔名）；`filter_loadable()` 改為三段邏輯（品牌+型號齊備 / 只知品牌 / 都不知）。
- `agent/agent_tools/tools.py:load_product_info` 拒絕訊息新增「只知品牌但要載非允許文件」分支。
- `agent/prompts/system.md` 知識來源表新增 `{{Brand}}/_brand` 列與用法說明。
- `agent/product_info/Dormakaba/_brand.md`：**新檔**，收錄 WiFi 設定通用流程（從 v1.3.12 的 16 份重複內容集中而來）。
- `agent/product_info/Dormakaba/{16 個型號}.md`：移除重複的 `## Dormakaba WiFi 設定` 章節。

## 背景與動機 (WHY)

LINE 線上對話頻繁出現「客戶知道品牌但不知道型號」的情境（如「Dormakaba 怎麼設定 WiFi」）。原 product_info 載入器只認 `{Brand}/{Model}` 與 `_common/*`，型號未確認時只能退回到跨品牌通用文件，無法引用品牌共通知識。

前次 commit `ae39a4c`（v1.3.12）為 Dormakaba 16 款各自加上一份相同的 WiFi 章節，雖暫時解決問題但維護成本高——任何修正須同步 16 份。本次將該機制收斂到品牌通用文件 `_brand.md`，後續其他品牌可依此擴展。

## 影響評估 (IMPACT)

- 破壞性變更：無。loader 對既有「品牌+型號齊備」流程完全相容（額外多載一份品牌通用文件，原模型內容不變）。
- 行為變更：
  - 客戶說「Dormakaba 怎麼設定 WiFi」（不知型號）→ AI 可載入 `Dormakaba/_brand` 給出完整 WiFi 流程。
  - 型號齊備（如 `Dormakaba/AS701`）→ AI 可同時載入 `{Brand}/{Model}` + `{Brand}/_brand`，互補。
- 安全降級：未建 `_brand.md` 的品牌（Kaadas / AiLock 等）自動退回 `_common/*`，不報錯。
- 後續動作：需 `./agent/scripts/deploy.sh` 重新 build + deploy（loader / prompt 在 startup 載入）。

## 驗證方式

- 已執行 `python3 -c "from product_info import ..."` smoke test，確認三段 `filter_loadable` 邏輯回傳正確：
  - 都不知 → 4 份 `_common/*`
  - 只知 Dormakaba → +`Dormakaba/_brand`（5 份）
  - Dormakaba/AS701 → +型號 + 品牌通用（6 份）
  - 只知 Chatlock（無 `_brand.md`）→ 安全降級為 `_common/*`（4 份）
- 結構檢查：`grep -l "## Dormakaba WiFi 設定" agent/product_info/Dormakaba/*.md` 應只回傳 `_brand.md`。
