### 手動驗證

1. **進入點 A — T3 詳情頁**：`/my-orders/<id>` 工單在 active 狀態下，點「改期」進入
2. **進入點 B — A37 派工介入**：`/admin/dispatch-manual?work_order_id=<id>` 點底部「改期 + 通知客戶」（帶 `?from=staff_assist`）
3. **T11 主頁**：
   - [ ] header 顯示工單編號、地址、原預約時間
   - [ ] 客戶提示卡片顯示偏好時段（綠）/ 勿擾（紅）/ 已改期次數（>=2 黃字）
   - [ ] 7 日 strip 切換日期，今日粗框，選中藍底
   - [ ] 上/下週按鈕切換週
   - [ ] 時段網格 30 分鐘為粒度，4 欄
   - [ ] hard_conflict 時段灰且禁點
   - [ ] soft_conflict 時段黃框 + AlertTriangle icon
   - [ ] 點選時段加入 proposed list（最多 3 個）
   - [ ] 達 3 個再點別的不會加入
4. **soft conflict 流程**：選中 soft_conflict 時段 → 下方顯示黃色 warning banner，列出衝突原因；勾選 "我已了解" 才能送出
5. **送出**：
   - [ ] message textarea < 5 字按鈕 disabled
   - [ ] 送出方式單選（LINE / LINE+SMS）
   - [ ] 提交成功 → 綠色 toast → 1.5 秒返回 /my-orders/<id>
   - [ ] 422 RESCHEDULE_LIMIT_EXCEEDED → 顯示「24h 內已 3 次，請聯繫客服」
   - [ ] 409 → 顯示「時段或工單狀態衝突」
6. **取消按鈕**：返回 /my-orders/<id>

### Mock 驗證
若後端尚未實作 `proposeReschedule`：mock server 應回 200 + `WorkOrderEnvelope`。422 / 409 路徑可手動丟錯模擬。
