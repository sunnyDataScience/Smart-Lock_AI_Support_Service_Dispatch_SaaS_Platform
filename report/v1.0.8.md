# 進度報告 v1.0.8：scripts/view_llm_usage.py 同步 user_question / ai_reply 欄位

- **版本**: v1.0.8（前版：v1.0.7 → 本版升級類型：PATCH）
- **Commit**: 待補（本次 commit）
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `scripts/view_llm_usage.py`

## 變更摘要 (WHAT)

1. 內嵌 `CREATE TABLE IF NOT EXISTS` DDL（L229-245）補上 `user_question TEXT` + `ai_reply TEXT` 兩欄，並加 `ALTER TABLE ... ADD COLUMN IF NOT EXISTS` 升級既有資料表。
2. `recent_detail()` 查詢 SELECT 多撈 `user_question` / `ai_reply` 兩欄；新增 `show_content` 參數，啟用時於每筆明細下方印出 `Q> ...` 與 `A> ...` 各 120 字摘要。
3. CLI 新增 `--show-content` 旗標；help 行 + docstring 範例同步。

## 背景與動機 (WHY)

v1.0.7 把 `llm_usage_log` 表加了 `user_question` / `ai_reply` 兩欄並串連 5 個 call site，但 `scripts/view_llm_usage.py` 的內嵌 DDL 與 `SELECT` 沒一起升。結果：
- 第一次跑這支 script 對到舊 DB 會建出**沒有兩欄的舊版表**（DDL 不一致）
- 即使 DB 已升級，也沒有任何旗標可以從 CLI 端看到原文，需要直接下 `psql`，違背這支 script 「可讀性 query helper」的定位

## 影響評估 (IMPACT)

- **破壞性變更**: 無
  - DDL 用 `CREATE/ALTER ... IF NOT EXISTS`
  - `--show-content` 預設 False，現有用法不受影響
- **後續動作**: 無

## 驗證方式

```bash
python -m py_compile scripts/view_llm_usage.py        # ✅ pass
python scripts/view_llm_usage.py --help               # ✅ 顯示 --show-content
python scripts/view_llm_usage.py --since 1h --show-content
# 預期每筆下方多兩行 Q> / A> 摘要
```
