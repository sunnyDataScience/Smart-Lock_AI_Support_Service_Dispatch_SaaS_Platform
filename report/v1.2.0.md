## 變更摘要 (WHAT)

把 product_info 架構從 Dormakaba 試水溫擴展到全部 7 個品牌（Waferlock 因 config 無型號暫不納入）。新增 16 份 mega-doc：

- **Chatlock** 3 份：AI-99（24 部 YouTube）、A90（15 部 YouTube）、AI-88（無 bronze stub）
- **3E** 2 份：TX（4 部 YouTube）、F(T7)（6 部 YouTube）
- **Philips** 5 份 stub：7300、Alpha、702E、9200、9300（zero-bronze）
- **Kaadas** 2 份 stub：藍寶堅尼3D人臉辨識、藍寶堅尼門鈴款（zero-bronze）
- **Milre** 3 份 stub：6500F、6500S、7150+（zero-bronze）
- **AiLock** 1 份 stub：七合一旗艦款（zero-bronze）

product_info 總文件數：20 → 36（16 Dormakaba + 4 _common + 16 新增）

## 背景與動機 (WHY)

v1.1.0 完成 Dormakaba 試水溫，使用者要求擴展至其他品牌。bronze 來源狀況差異大：

- **有 bronze 內容**：Chatlock（AI-99 / A90 + 3 份 video txt）、3E（TX / F(T7)）→ 委派 subagent 整理為實質 mega-doc
- **零 bronze**：Philips / Kaadas / Milre / AiLock / Chatlock AI-88 → 用 stub 模板，明確標示「資料補充中」、引導查說明書或派工，**禁止編造按鍵步驟**

擴展目的：所有有資料的品牌走統一新流程；無資料品牌仍走新流程但 stub 強制 LLM 承認資料不足，避免 LLM 憑常識亂答。

## 影響評估 (IMPACT)

- **破壞性變更**：對 Chatlock 與 3E 用戶有行為改變——之前走舊 `load_skill` 看 `[可用技能]`，現在走新 `load_product_info` 看 `[可用產品資料]`。零 bronze 品牌（Philips/Kaadas/Milre/AiLock）也切換新流程
- **Waferlock 例外**：config.toml 中 models=[]，product_info 無對應檔，仍走舊 `[可用技能]` 流程。如需要可後續補一份 Waferlock 通用 stub
- **舊 skills 保留**：`agent/skills/data/` 完整保留作 fallback，未刪除
- **stub 設計考量**：zero-bronze stub 主動引導派工 + `_common/troubleshoot`，強迫 LLM 承認資料不足而非編造，這是降低錯誤回覆的保守策略
