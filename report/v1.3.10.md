# 進度報告 v1.3.10：開啟 [用戶資料] 注入修復品牌查詢失答

- **版本**: v1.3.10（前版：v1.3.9 → 本版升級類型：PATCH）
- **Commit**: `64b1286` (2026-05-04 21:13)

## 變更摘要 (WHAT)

- `agent/config.toml` `[user_profile] enabled` 從 `false` 改為 `true`
- `facts_enabled` 維持 `true`（DB 讀寫行為不變，僅新增訊息前綴注入）

## 背景與動機 (WHY)

正式環境 log：

```
[LINE] user=U3bc4ff5... text=你知道我的品牌嗎
[Agent] 思考完畢！回覆內容: 您好！請問有什麼可以協助您的嗎？
```

agent 完全沒回答「你知道我的品牌嗎」。根因：

1. `enabled=false` 時 `debounce.py:308` 的條件不成立，`profile_prefix` 為空字串，`[用戶資料]\n...` 不會 prepend 到 user message
2. system.md 第 168-175 行「## 用戶資料」整段是基於 `[用戶資料]` 區塊存在的假設；該區塊缺失時，agent 從 prompt 完全看不到 phone / address / device_brand / device_model
3. 唯一殘留線索是 `[可用產品資料]` header 那行「（用戶為 Dormakaba AS901，使用 load_product_info 載入）」——格式埋在工具清單裡，LLM 沒把它當 profile 解析

`facts_enabled=true` 與 `enabled=false` 並存代表：「DB 一直在記，但記下來的東西 LLM 看不到」。這是配置不一致。

## 影響評估 (IMPACT)

- **破壞性變更**：無
- **行為變更**：
  - 每次請求 user message 會多一段 `[用戶資料]\n...\n` 前綴（已記錄的 phone / address / device_brand / device_model 等欄位）
  - token 增加約 50-100 級別，對總 latency 影響可忽略
  - agent 現在可在不呼叫工具的情況下回答「我的品牌是什麼」「我電話幫我記得了嗎」這類詢問
  - system.md 第 168-175 行的指引真正派上用場，避免重複追問已知資訊
- **後續動作**：必須重新部署 Cloud Run（`./agent/scripts/deploy.sh`）才會生效

## 驗證方式

部署後實機測試：

1. 已記錄品牌的測試帳號發訊「你知道我的品牌嗎」
2. 預期回覆：「您的設備品牌是 X、型號是 Y，是嗎？」之類的具體答覆
3. 同樣帳號發訊「我電話幾號」 → 預期讀 [用戶資料] 中 phone 欄位回覆
