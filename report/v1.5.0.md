## 變更摘要 (WHAT)

- **共用元件** `web/src/components/tech/`：
  - `TechShell` 手機優先容器（max-w-480px 置中）+ sticky bottom nav
  - `TechBottomNav` 3 Tab 底部導航（案件池 / 我的工單 / 帳戶）
  - `StatusBadge` 16 種工單狀態中文 Badge
  - `UrgencyBadge` 緊急程度 Badge
- **三個頁面**：
  - `/pool` (T1)：案件池列表 + 接單（含 409 衝突）
  - `/my-orders` (T2)：3 Tab 分流（進行中 / 待確認 / 歷史）
  - `/my-orders/[id]` (T3)：詳情 + 完工回報表單
- 串接 5 個 OpenAPI endpoints

## 背景與動機 (WHY)

依使用者 workflow 盤點，技師端 11 頁規格（T0-T11）完全缺失，卡住 Flow 1 Happy Path（接單→作業→完工）這個最關鍵的端對端流程。本次以 MVP 模式補齊 T1+T2+T3 三頁，建立技師端骨架與共用元件，讓技師可以走完最小可行的接單→完工流程。

## 影響評估 (IMPACT)

- 破壞性變更：無，純新增。
- MVP 範圍刻意省略：地圖（Google Maps）、BottomSheet 三態手勢、WebSocket 即時推送、GPS 上報、Service Worker 離線、PWA manifest、照片上傳、簽章、零件清單、客戶電話（後端尚未在 WorkOrder 帶出）
- 解鎖 Flow 1 Happy Path 最小路徑：`/pool` → 接單 → `/my-orders/[id]` → 完工回報

### 手動驗證步驟

1. **啟動 dev server**：`cd web && npm run dev`，瀏覽 `http://localhost:3000/pool`
2. **登入流程**：先到 `/login` 登入（需有效 token + 對應 technician role）
3. **T1 案件池 `/pool`**：
   - [ ] 上方顯示「案件池」+ 可接工單數量
   - [ ] 列表顯示 brand/model/district/預估佣金
   - [ ] 急件顯示橘色左邊框 + 「急件」Badge
   - [ ] 點「接受工單」→ 跳轉 `/my-orders/<id>`
   - [ ] 同筆工單同時被他人接走 → 顯示「已被其他技師接走」
4. **T2 我的工單 `/my-orders`**：
   - [ ] 三個 Tab 切換正確分流（依 status）
   - [ ] 每個 Tab 上有數量 Badge
   - [ ] 空態顯示對應插圖與「前往案件池接單」CTA（active tab）
   - [ ] 點卡片進入 `/my-orders/<id>`
5. **T3 工單詳情 `/my-orders/[id]`**：
   - [ ] 5 區塊（地址 / 鎖具 / 服務資訊 / 客戶 / 完工回報）顯示完整
   - [ ] 「導航前往」開新視窗到 Google Maps
   - [ ] 點「完工回報」展開表單，填 summary 後送出
   - [ ] 提交成功 → 顯示綠色 toast + 狀態切到 `completed`
   - [ ] terminal 狀態下不顯示完工按鈕
6. **底部導航**：
   - [ ] 三 Tab 點擊跳轉，active 高亮 `#2563EB`
   - [ ] 在 `/pool` 時案件池 active；切到 `/my-orders` 時我的工單 active

### 已知限制（MVP 預期表現，不算 bug）
- 桌面瀏覽器顯示為手機尺寸（max-w-480px 置中），這是設計意圖（PWA 為純 Mobile）
- 客戶電話按鈕 disabled，因 WorkOrder schema 沒帶電話
- 無地圖、無即時推送、無照片上傳

### Mock server 驗證（如後端尚未 ready）
若後端 endpoints 尚未實作，可用 `./scripts/mock-server.sh` 啟動 Prism mock 在 port 4010，再設 `NEXT_PUBLIC_API_BASE_URL=http://localhost:4010` 跑 dev server。
