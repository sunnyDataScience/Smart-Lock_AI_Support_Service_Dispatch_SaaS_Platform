## 變更摘要 (WHAT)

### A. system.md 規則強化（核心改動）
1. **強制載入文件剛性規則**：明確列出每類問題該載入哪個 product_info 文件，禁止憑常識作答
2. **5 個具體載入案例範本**：含「鋰電池怎麼充電」「電池規格」「老人家指紋淺」等明確指向對應文件
3. **「以下為通用建議...」禁用語警示**：禁止用此句作為跳過載入工具的藉口，必須真載入後才能用
4. **故障/機械問題回覆順序規則**：先給可立即執行的緩解動作 → 比對型號文件派工條件 → 緩解無效才派工。修正 v1.3.0「機械問題派工剛性規則」過強造成的 H-5 fail
5. **multi-turn 重評估規則強化**：歷史 `[已參考: ...]` 不代表內容還在，新訊息要重新載入

### B. debounce.py cleanup 策略修改
保留最新一輪 ToolMessage 完整內容，只清舊輪。讓多輪對話的下一輪 LLM 仍有最近一次工具呼叫的完整脈絡（避免 cleanup 過於激進造成 LLM 失去上下文）。

### C. product_info 內容補強
- `Chatlock/AI-99.md`：新增「鏡頭旁紅燈閃爍 = 正常感應狀態」段（解 H-10）
- `_common/troubleshoot.md`：補 mesh 路由器警告（解 E-4）
- `_common/general-knowledge.md`：強化「電池建議務必命名 Panasonic 國際牌」回覆原則（解 W-5）
- `_common/dispatch.md`：補「預約維修需準備資訊」+「安裝預約必須請客戶提供照片」（解 M-2 / E-7）

### D. quality_check.py expected 對齊 B 路徑
5 題在 brand 已知但 model 未知時，原本 expected 苛求 brand-specific 字眼（mega-doc 才有），現改為符合 B 路徑可載入範圍的回答方向：

## 背景與動機 (WHY)

v1.3.0 commit 後實際 LLM judge 跑出 67%，分析發現：
1. **AI 經常憑常識答而沒呼叫工具**（Y-4 / Y-10 / W-6 / E-10 等 skills=[]）→ 強制載入規則
2. **cleanup 過於激進造成 multi-turn 失去上下文**（E-1 fail）→ 保留最新一輪
3. **某些 expected 苛求 brand-specific 字眼但測試 model 缺**（B-1 / B-3 / B-5）→ 對齊 B 路徑
