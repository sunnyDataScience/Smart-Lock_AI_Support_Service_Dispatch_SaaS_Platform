## 變更摘要 (WHAT)

- 新增 5 個 subflow 路由（mobile-first，共用 SubflowHeader 元件）：
  - `T5 /scope-change` — 範圍變更：事由 + 動態工項清單 + 追加總額
  - `T6 /material-request` — 缺料：缺件清單 + 急迫度 + 備註
  - `T7 /delay` — 延遲通知：時長 quick chips + 5 種原因 + 通知對象 + 改期連結
  - `T8 /door-check` — 門面檢核：作業前/後照片 + 6 項 checklist
  - `T9 /signature` — 雙方電子簽章：HTML5 Canvas 觸控+滑鼠 + GPS 自動帶入，串接 `submitWorkOrderSignature`
- T3 工單詳情頁 action_section 升級為 6 格 grid CTA（含原有「改期」+ 5 個新 subflow）

## 背景與動機 (WHY)

技師工作時遇到非 Happy Path 場景（範圍追加、缺料、延遲、外觀變更、簽章收尾）原本完全無入口。本次補齊 5 個關鍵 subflow，解鎖 user workflow Flow 3 / Flow 4 / Flow 5 / Flow 10 + Flow 1 收尾簽章。

## 影響評估 (IMPACT)

- 破壞性變更：無，純新增 + 既有 T3 action 升級為 grid（保留原行為）
- T9 簽章：實際串後端 `POST /api/v1/work-orders/{id}/signature`
- T5–T8：後端 API 待補，目前送出走 mock setTimeout 並顯示 amber「API 待補」banner
- T10 我的排班暫不做（需另開 `/account/schedule`）
- 媒體上傳（T8 photos）目前只記錄檔名 placeholder，實際上傳待後端確認 endpoint
