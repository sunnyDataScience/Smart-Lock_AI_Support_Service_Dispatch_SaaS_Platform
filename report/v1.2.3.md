# 進度報告 v1.2.3：剝除回覆中誤抄的 [已參考: ...] 引用標記

- **版本**: v1.2.3（前版：v1.2.2 → 本版升級類型：PATCH）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: agent/harness/debounce.py、agent/prompts/system.md

## 變更摘要 (WHAT)

- `debounce.py`：在提取 `ai_response` 後加入 regex 剝除步驟，移除任何 `[已參考: ...]` 或 `[已參考技能: ...]` 標記及其周邊空白／逗號
- `system.md`：新增明確禁令——「禁止輸出內部引用標記」，告知 LLM 即使在前情提要中看到也不要照抄

## 背景與動機 (WHY)

實測中發現 LLM 把 checkpoint cleanup 留下的 `[已參考: Chatlock/A90]` 當成回覆前綴輸出給客戶。

成因：`_cleanup_tool_checkpoint()` 為節省 context，把 ToolMessage 內容替換成 `[已參考: name]` 的 AIMessage。下一輪 LLM 看到歷史中有這類訊息，誤以為是回覆格式並抄寫。

## 影響評估 (IMPACT)

- 破壞性變更：無
- 雙保險設計：
  1. Prompt 層：明確禁令告知 LLM 不要輸出
  2. 程式層：regex 剝除作為兜底（即使 LLM 違規仍能保證客戶不會看到）
- regex 邊界處理：含半形／全形逗號與周邊空白，避免殘留 `, ` 或 `，`

## 驗證方式

### 單元測試（已通過）
- `[已參考: Chatlock/A90]好的` → `好的`
- `[已參考: A], [已參考: B]內容` → `內容`
- `[已參考: A]，[已參考: B]內容` → `內容`（全形逗號）
- 正常回覆無前綴 → 不變

### 真機驗證
重啟 server 後重現「我想設定指紋」場景，確認回覆不再含 `[已參考: ...]`。
