# 進度報告 v1.15.1：dispatch-queue patch state 效能優化

- **版本**: v1.15.1（前版：v1.15.0 → 本版升級類型：PATCH）
- **Commit**: `ff25da0` (2026-05-05 22:42)
- **分支**: feat/web-tech-app
- **作者**: Imding1211
- **影響模組**: `web/src/app/admin/dispatch-queue/page.tsx`

## 變更摘要 (WHAT)

- 拆 `fetchAll()` 為 `fetchSnapshot` / `fetchLogs` / `fetchPool` 三個獨立函式
- 各 fetch 加 5 秒 debounce 閘門（lastFetchAt ref）
- 手動「重新整理」走 `force=true` 跳過 debounce
- WS 事件依 shape 分流：
  - Case 1 snapshot 數字 → `setSnapshot` patch
  - Case 2 dispatch_log → prepend logs[]（去重，保留 50 筆）
  - Case 3 work_order → pool[] add / remove
  - 未知 shape → 三個 debounced fetch 兜底

## 背景與動機 (WHY)

v1.8.0 初版實作收到 WS 事件就 `fetchAll()` 觸發 3 個並行請求。高頻派工情境下（每秒多筆事件）造成後端壓力與不必要的 spinner。對齊 AsyncAPI `DispatchQueueSnapshotData` 直接帶 KPI 數字的設計，前端應直接 patch state。

## 影響評估 (IMPACT)

- 破壞性變更：無，行為層面與原本等價但網路請求量大幅降低
- 高頻場景：N 個事件 = 原本 3N 個請求 → 改後 0 個額外請求（純 state patch），未知 shape 兜底也僅 5 秒內 3 次

| 項目 | 預期 |
|:---|:---|

| dispatch_log payload 推送 | logs 列表頂端插入該筆 |
