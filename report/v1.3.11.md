# 進度報告 v1.3.11：強化型號未知時的應答流程

## 變更摘要 (WHAT)

- `agent/prompts/system.md` 開頭新增「🚨 絕對鐵律」段落（第 3-9 行），把「型號未知時禁止請客戶描述外觀／拍照辨識」與「兩段降級流程」拉成第 0 級規則。
- 移除原 `回覆原則` 中第 32 行散落的長段重複規則，保留「請客戶提供安裝環境照片」例外條款（限新鎖安裝情境）。
- `agent/product_info/_common/troubleshoot.md` 第一步問診核心同步調整：型號詢問改為列出查找位置（說明書 / 保固卡 / 電池蓋內側 / 購買單據），仍找不到才給品牌通用步驟並聲明型號差異。

## 背景與動機 (WHY)

LINE 線上實測（`鎖市鎖印社AI客服測試`）連續多輪出現相同 regression：客戶說「找不到型號」時，AI 反覆建議「提供電子鎖的照片」「描述一下外觀，例如推拉式還是把手式、有沒有觸控螢幕」。但系統 `product_info/` 內**並無外觀↔型號對照資料**，AI 對品牌型號照片辨識率亦不足，這類追問只會徒增客戶困擾。

第一輪修正（v 未發前內部）只把規則寫在 `system.md:32` 段落中，LLM 仍照舊行為輸出。判斷是規則被埋沒在「回覆原則」清單裡、注意力分散，本次改用 emoji 標題＋條列短句拉到 prompt 最頂部。

## 影響評估 (IMPACT)

- 破壞性變更：無。純 prompt / 文件層面變動。
- 行為變更：客戶宣告「不知道型號」時，AI 第一輪只給查找位置；第二輪才給品牌通用步驟並加聲明。全程不再追問外觀／要求拍照。
- 後續動作：需 `./agent/scripts/deploy.sh` 重新 build + deploy 才會生效（system prompt 在 agent 啟動時 cache）。
- 殘留風險：LLM（Gemini 2.5 Flash）仍可能在邊界情境繞過 prompt；若觀察到再考慮啟用 `output_validator` 作為硬守門（已準備好擴充點，目前保留 `enabled = false`）。

## 驗證方式

- 部署後，在 LINE Bot 重複前述測試對話：
  1. 「請問 dormakaba 電子鎖怎麼設定指紋」 → 預期 AI 詢問型號或請查找位置，**不**主動建議拍照／描述外觀。
  2. 「我不知道型號」 → 預期 AI 列出 4 個查找位置，回覆**到此為止**。
  3. 「我都找不到」 → 預期 AI 給 Dormakaba 通用步驟並開頭聲明「實際按鍵位置可能因型號略有差異」。
- 規則違反偵測：`grep -E "提供.{0,6}照片|描述.{0,4}外觀|推拉式還是把手式" agent/prompts/system.md agent/product_info/_common/troubleshoot.md` 應為空（除「🚨 絕對鐵律」內的禁用列表外）。
