## 背景與動機 (WHY)

PR #28 的 lint workflow 是「程式碼層的守護」，但**規則背後的 why 不在 workflow 註解裡能完整解釋**。新加入的 reviewer 看到紅燈會問：

- 為什麼 skills 不能 import harness？（因為是 leaf 層）
- 為什麼 core 不能 import harness？（因為更 leaf）
- 為什麼 harness 不能 import agent？（middleware 不能反向依賴編排層）
- 為什麼某些地方可以 `# noqa: BLE001` 但其他地方不行？（範圍區分 hot-path vs scripts）

把這些 *why* 寫成 ADR，新人 onboarding 一份文件解釋清楚，未來重構也有 anchor 可參照（避免「為什麼當初要這樣」的考古學）。

選 `docs/02-design/agent-harness/` 而非 `docs/_audit/` 作為位置：
- `_audit/` 是 WBS / refactor plan / 審計快照（時點性紀錄）
- `02-design/agent-harness/` 是 architecture spec（持續維護）
- 分層規則屬後者性質

## 驗證方式

```bash
# 從 agent/ import 自動驗證三條規則
python3 -c "
import os, re
from collections import defaultdict
LAYERS = {'core': 'agent/core', 'memory': 'agent/memory', 'storage': 'agent/storage',
          'profiles': 'agent/profiles', 'llms': 'agent/llms', 'skills': 'agent/skills',
          'harness': 'agent/harness', 'quality': 'agent/quality',
          'agent_py': 'agent/agent.py', 'app_py': 'agent/app.py'}
def detect_layer(p):
    for L, prefix in LAYERS.items():
        if p == prefix or p.startswith(prefix + '/'): return L
edges = defaultdict(set)
imp = re.compile(r'^\s*(?:from|import)\s+(\w+)(?:\.\w+)?')
for root, _, files in os.walk('agent'):
    if '__pycache__' in root: continue
    for f in files:
        if not f.endswith('.py'): continue
        full = os.path.join(root, f); src = detect_layer(full)
        if not src: continue
        for line in open(full):
            m = imp.match(line)
            if m and m.group(1) in LAYERS and m.group(1) != src:
                edges[src].add(m.group(1))
violations = []
if 'harness' in edges.get('skills', set()): violations.append('skills→harness')
if 'harness' in edges.get('core', set()) or 'skills' in edges.get('core', set()): violations.append('core→harness/skills')
if 'agent_py' in edges.get('harness', set()): violations.append('harness→agent.py')
print('OK 三條規則全綠' if not violations else f'❌ {violations}')
"
```
