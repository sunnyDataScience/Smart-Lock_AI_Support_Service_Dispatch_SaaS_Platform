## 變更摘要 (WHAT)

- 共用基礎設施：
  - `web/src/lib/realtime.ts`：WebSocket client wrapper（auto-reconnect、StrictMode safe、無 base url 時 silent disabled）
  - `web/src/lib/useRealtimeChannel.ts`：React hook
  - `web/src/components/realtime/RealtimeIndicator.tsx`：6 種連線狀態指示燈
- 4 頁整合：
  - `/notifications` → `/realtime/notifications/{user_id}` 新通知插入頂端
  - `/pool` → `/realtime/pool/{tech_id}` added/taken/cancelled 同步列表
  - `/admin/dispatch-queue` → `/realtime/dispatch-queue` 收到事件 fetchAll
  - `/my-orders/[id]/reschedule` → `/realtime/work-orders/{id}` 客戶 RSVP 自動關頁

## 背景與動機 (WHY)

AsyncAPI 規格定義 10 個即時頻道，但實作端 0 個訂閱，所有監控/通知頁靠 polling 體驗差。本次建立統一 realtime 抽象 + 整合最有 ROI 的 4 頁，讓未來頻道接入成本最小化。

## 影響評估 (IMPACT)

- 破壞性變更：無。未設 `NEXT_PUBLIC_REALTIME_BASE_URL` 時所有頁面行為與之前完全相同（多一個灰色「未配置」指示）。
- 部署需求：要啟用即時功能需設 `NEXT_PUBLIC_REALTIME_BASE_URL`（例 `ws://localhost:8000/realtime` 或 `wss://api.sunnydata.example.com/realtime`）
- 後端要求：WebSocket server 需支援 query param `access_token` + `tenant_id` 認證
- 後續：
  - SSE 支援（`/realtime/diagnostics/{conv_id}` 為 SSE）
  - BroadcastChannel 跨 tab 同步（同 user 多 tab 共用連線）
  - dispatch-queue 改為 patch state（減少 server 壓力）

### 手動驗證

#### 場景 A：未設 REALTIME_BASE_URL（驗證向下相容）
1. `cd web && npm run dev`（不設環境變數）
2. 開 `/notifications`、`/pool`、`/admin/dispatch-queue`、`/my-orders/<id>/reschedule`
3. ✅ 每頁右側看到灰色「未配置」指示燈，但所有原功能正常

#### 場景 B：設 REALTIME_BASE_URL（無實際 server）
1. 在 `web/.env.local` 加 `NEXT_PUBLIC_REALTIME_BASE_URL=ws://localhost:8000/realtime`
2. 重啟 dev server
3. ✅ 指示燈顯示橘色「連線中」→ 灰色「已斷線（重試中）」（exponential backoff）
4. 開 console 不應看到大量錯誤（logErrors 預設 false）

#### 場景 C：設 echo server 驗證收訊
1. 用 `npx wscat -l 8000` 或自建 echo server
2. 從 server 推送 JSON 訊息：
   ```json
   { "type": "added", "payload": { "id": "xxx", "type": "work_order", ... } }
   ```
3. 對應頁面應即時更新（`/notifications` 列表頂端插入、`/pool` 加入工單）

### Mock server 推送
若用 Prism mock server，需另起 WebSocket mock。建議用 wscat：
```bash
# Terminal 1
npx wscat -l 8000

# 客戶端連線後手動丟訊息
> {"type":"added","payload":{"id":"abc","type":"system","severity":"info","title":"測試通知","body":"hello","source":"system","created_at":"2026-05-05T07:00:00Z"}}
```
