# 進度報告 v1.0.1：Markdown 報告改存 reports/ 子資料夾並壓時間戳

- **版本**: v1.0.1（前版：v1.0.0 → 本版升級類型：PATCH）
- **Commit**: `f52fe6d` (2026-05-01 22:04)
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `agent/quality/`

## 變更摘要 (WHAT)

- `_save_report()` 第四個參數從 `md_path` 改 `md_dir`（語意：輸出資料夾）
- `_generate_md()` 內部產檔名 `quality_report_YYYY-MM-DD_HHmm.md` 並回傳實際路徑
- 目標目錄 `agent/quality/reports/` 不存在時自動 `os.makedirs(..., exist_ok=True)`
- 內文時間戳與檔名共用同一個 `datetime.now()` 避免漂移

## 背景與動機 (WHY)

v1.0.0 的 `quality_report.md` 每次跑都被覆蓋，前後比對 / 歷史回溯只能靠 `git log`，重跑兩次間的差異就丟了。Quality 回歸測試的價值之一就是「上週通過，這週退回了」這種趨勢觀察 — 自動保留歷史是基礎需求。

## 影響評估 (IMPACT)

- **破壞性變更**: 無。`md_dir` 仍為 `Optional`，外部呼叫端不受影響
- **檔案產出位置**: 從 `agent/quality/quality_report.md` 移到 `agent/quality/reports/quality_report_<ts>.md`
- **舊檔處理**: v1.0.0 留下的 `quality_report.md` 之後不會再被寫入，可手動清掉或保留作 baseline
- **磁碟用量**: 每份 MD 約 5–30 KB，每天跑 1 次 → 月增約 1 MB，無 retention 問題（必要時再加 cleanup script）

## 驗證方式

1. 跑完整 quality_check 並確認檔名：
   ```bash
   cd agent && python -m quality.quality_check
   ls -la quality/reports/  # 應有 quality_report_2026-05-01_HHMM.md
   ```
2. 連續跑兩次，確認產生兩份不同檔名（時間差 ≥ 1 分鐘）
3. 語法檢查：`python -c "import ast; ast.parse(open('agent/quality/quality_check.py').read())"`
