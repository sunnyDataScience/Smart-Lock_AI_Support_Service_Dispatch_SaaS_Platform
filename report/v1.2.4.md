# 進度報告 v1.2.4：禁止建議客戶傳照片辨識型號

- **版本**: v1.2.4（前版：v1.2.3 → 本版升級類型：PATCH）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: agent/prompts/system.md

## 變更摘要 (WHAT)

system.md 新增禁令：當客戶找不到型號時，**禁止**回覆「請提供電子鎖照片給我」或「您可以拍照給我」之類的話。給出客戶找不到型號時的正確處理流程（查包裝盒/保固卡 → 描述外觀特徵 → 給通用步驟 + 免責聲明 / 派工）。

## 背景與動機 (WHY)

實測 Dormakaba 場景：客戶說「找不到型號欸」「我真的不知道」，agent 最後回「或是提供電子鎖的照片給我，或許能幫助我辨識型號喔」。問題：

1. 系統雖支援多模態，但**不適合**透過照片做型號辨識（誤判風險高）
2. 即使 LLM 收到照片，目前流程也沒有可靠的型號分類器
3. 鼓勵錯誤期望會讓客戶以為傳照片就能解決，實際上沒幫助

## 影響評估 (IMPACT)

- 破壞性變更：無
- output_validator 目前 `enabled=false`，本次只在 prompt 層處理；如未來啟用 validator 應同步把「拍照給我」「提供照片」加進 forbidden_phrases

## 驗證方式

重現「我的鎖是 Dormakaba / 找不到型號 / 我真的不知道」場景，確認 agent 改為引導：
- 查包裝盒/保固卡/安裝單據
- 描述外觀特徵
- 給通用步驟 + 免責聲明
- 不再出現「提供電子鎖的照片給我」

## 下一步 (NEXT)

- 觀察是否有其他類似「鼓勵客戶做不可靠操作」的回覆模式（如要求拍特定畫面、要求拆開電池蓋拍螺絲等）
- 視 quality_check 結果決定是否啟用 output_validator
