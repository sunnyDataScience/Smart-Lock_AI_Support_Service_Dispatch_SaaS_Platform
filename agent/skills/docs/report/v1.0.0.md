# 進度報告 v1.0.0：product-knowledge 加強症狀分流 + APP/手冊 routing，UAT 通過率 72%→87%

- **版本**: v1.0.0（首份報告）
- **Commit**: `e9d6f03` (2026-05-01 22:46)
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `agent/skills/`（主要）+ `agent/quality/`（baseline 同步）

## 變更摘要 (WHAT)

- `agent/skills/data/_common/product-knowledge/SKILL.md` frontmatter 新增 trigger_keywords：`APP / App / app / 遠端 / 金鑰 / 操作手冊 / 下載`，使 agent 能命中 APP 操作類問題
- 「⚠️ 故障問題請先用 troubleshoot」清單明確列出具體症狀詞：`紅燈閃爍 / 紅燈不亮 / 貓眼紅燈 / 燈號含義 / 一直嗶嗶叫 / 指紋失敗 / 人臉沒反應 / 掌靜脈不感應`，避免 agent 把症狀問題當作知識查詢
- 新增「🔑 客戶問 APP 操作 / 遠端金鑰 / Dormakaba APP 設定時」段落，明確禁止「無法提供」「請洽原廠」回覆，並指引直接貼出表格內既有的 GDrive 連結
- 同步刷新 `agent/quality/quality_report.json` / `.html` 為最新 baseline；新增 `agent/quality/reports/` 三份歷史 MD 快照（22:17 / 22:33 / 22:44）

## 背景與動機 (WHY)

UAT 跑完（67 cases）發現 6 個 FAIL，其中兩個明確的失敗（H-10、Y-4）並非知識內容缺漏，而是 routing/rejection 問題：

- **H-10「Chatlock 貓眼紅燈含義」** 回答成「電量低」（完全錯誤資訊）。實際上 `ts-face-chatlock/SKILL.md` 已有正確內容（紅燈 = 人臉/掌靜脈辨識中），但 agent 載到 product-knowledge 後就停了，沒有 redirect 到 ts-face-chatlock。
- **Y-4「Dormakaba APP 遠端金鑰」** 直接回「無法提供」。實際上 product-knowledge 表格內已有 `Dormakaba APP 遠端操作` GDrive 連結，但 trigger_keywords 沒涵蓋 APP/遠端/金鑰，agent 連這個技能都沒載入。

兩個都是 SKILL routing 層的問題，不是 SOP 內容缺漏，所以一份 SKILL.md 改動就能修，影響面最小。

## 影響評估 (IMPACT)

- **破壞性變更**: 無
- **UAT 結果（67 cases）**:
  - Pass: 48 (72%) → **58 (87%)**，+10 案例
  - Fail: 6 → 3
  - 目標案例 H-10 / Y-4 從 FAIL 全部變 PASS（keyword 命中 3/3）
  - 連帶受惠：E-1 換電池無法上鎖、E-5 推拉鎖卡住 也升級到 PASS
- **可能 regression**:
  - Y-5「AS701 遙控器設定」原本 partial → 仍 partial，但回答模式從「給操作步驟」變成「給連結」（product-knowledge 拉得稍強）。實際 keyword 命中沒退步。
  - 後續若需要修，方向是把「具體 AS701 操作步驟」明確 redirect 到 ss-dormakaba 而非 product-knowledge。

