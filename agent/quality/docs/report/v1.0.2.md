# 進度報告 v1.0.2：--retry-failed 模式補上 init_quick_reply，修復 brand inference 永遠失敗

- **版本**: v1.0.2（前版：v1.0.1 → 本版升級類型：PATCH）
- **Commit**: 待補（本次 commit）
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `agent/quality/`

## 變更摘要 (WHAT)

- `agent/quality/quality_check.py:629-633` `--retry-failed` 模式分支補上 `from harness.line_ui_factory import init_quick_reply` + `init_quick_reply(cfg.quick_reply)` 呼叫，與正常模式（line 700-702）行為對齊。

## 背景與動機 (WHY)

第 5 輪 `--retry-failed` 跑完後 Y-2 / Y-5 仍卡 `[skill] >>> 拒絕載入品牌技能: ss-dormakaba（用戶品牌未知）`。其中 Y-2 query「如何在 AS701 上新增 RFID 感應卡？」明明含 Dormakaba 獨有型號 AS701，按理 `infer_brand_from_text` 應推出 `('Dormakaba', 'AS701')`。

加 debug print 後實證 `brand=None model=None` — inference 沒生效。對比正常模式有 `init_quick_reply(cfg.quick_reply)` 初始化 `_brand_models` dict，retry-failed 模式漏掉這一步，導致 `_brand_models = {}`、所有 model match 都 miss、`infer_brand_from_text` 永遠返回 `(None, None)`。

副作用：所有未在 TestCase 寫死 `device_brand=` 的案例（如 Y-2 / Y-5 / S-7 / E-8），retry-failed 模式下品牌路由失準。對比正常模式則正常運作（因為 line 702 有初始化）。

## 影響評估 (IMPACT)

- **破壞性變更**: 無（純補回缺漏初始化）
- **修復前**: retry-failed 模式跑 Y-2 / Y-5 → `device_brand=""` → infer 返回 None → ContextVar `brand=None` → load_skill("ss-dormakaba") 被 brand gate 拒絕 → fail / partial
- **修復後**: retry-failed 模式跑 Y-2 → infer 返回 `('Dormakaba', 'AS701')` → ContextVar `brand="Dormakaba"` → ss-dormakaba 載入成功 → **PASS** (kw=2/3)
- **連帶受惠**：所有 retry-failed 流程內依賴 brand inference 的案例都恢復正常路由

## 驗證方式

```bash
cd agent && python -m quality.quality_check --retry-failed
# 觀察開頭應出現 "[Quick Reply] 品牌: [...]，型號: {...}" 確認初始化成功
# 預期 Y-2 verdict 從 fail → pass
```
