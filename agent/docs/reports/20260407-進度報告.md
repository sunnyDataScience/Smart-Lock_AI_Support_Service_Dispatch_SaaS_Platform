# 20260407 — 多模態訊息處理：圖片/音訊/影片 AI 辨識 + 媒體存儲抽象層

原系統對所有非文字 LINE 訊息（圖片、音訊、影片、貼圖）一律回傳「轉接真人表單」，不經過 LangGraph 診斷引擎。在電子鎖客服場景中，故障照片（錯誤碼、門鎖狀況）、異常聲音（嗶聲模式、馬達噪音）、操作影片都是高診斷價值的輸入，直接丟棄嚴重限制了 AI 客服的能力。

---

## 1. 多模態前處理架構

### 問題

`app.py:77-88` 的處理邏輯：

```python
if not isinstance(event.message, TextMessageContent):
    form_reply = await transfer_tool.generate_form(user_id)
    await line_bot.send_response(user_id, reply_token, form_reply)
    continue
```

所有非文字訊息一律短路，不下載、不辨識、不進 LangGraph。

### 解決方案

引入 **Gemini 2.5 Flash-Lite** 作為多模態前處理器，採用「媒體轉文字」策略：

```
LINE 媒體訊息
  → LINE Blob API 下載二進位資料
  → 本地存檔（媒體存儲抽象層）
  → Gemini Flash-Lite 提取文字描述
  → 注入 debounce buffer
  → 正常 LangGraph 診斷流程（下游零修改）
```

使用 `google-genai` 新版統一 SDK，原生支援 async 和多模態 `Part.from_bytes()`。

### 效果

- 圖片/音訊/影片轉為文字描述後進入診斷引擎，可觸發 ProblemCard、Fault Tree 推理
- 貼圖改為友善回覆（不浪費 LLM token）
- 媒體檔案持久化至本地，未來可切換雲端
- `[multimodal] enabled = false` 可一鍵關閉，回退到原行為（轉接真人）
- 下游 GraphState / nodes / agents / harness 全部零修改

## 2. Webhook 訊息分流重構

### 問題

原有判斷只有兩路：`TextMessageContent` → debounce，其他 → 轉接真人。

### 解決方案

重構為四路分流：

| 訊息類型 | 處理方式 |
|---------|---------|
| `StickerMessageContent` | 友善回覆（config 可設定文字），不進 LangGraph |
| `ImageMessageContent` / `AudioMessageContent` / `VideoMessageContent` | Flash-Lite 前處理 → debounce buffer → LangGraph |
| `TextMessageContent` | 行為不變 |
| 其他（檔案、位置等） | 轉接真人（保留原行為） |

多模態前處理以 `asyncio.create_task()` 在背景執行，webhook handler 立即返回，不阻塞 LINE 的 1 秒 timeout。

媒體描述注入 debounce buffer 後，自然與同一窗口內的文字訊息合併。例如用戶先傳故障照片、再輸入「按指紋沒反應」，兩者會在 2 秒 debounce 窗口內合併為一則完整訊息進入 LangGraph。

## 3. 媒體存儲抽象層

### 問題

媒體檔案需要持久化（故障照片作為診斷證據），但存儲目標可能隨部署環境改變（本地 → GCS → S3）。

### 解決方案

採用與 `agent/storage/` 相同的 Registry 模式：

```
core/media_storage/
  ├── __init__.py        # MEDIA_STORAGE_REGISTRY + get_media_storage()
  ├── base.py            # BaseMediaStorage（抽象介面：init / save / close）
  └── local_impl.py      # LocalMediaStorage（本地實作）
```

**本地存儲目錄結構：**
```
data/media/
  {user_id}/
    {YYYY-MM-DD}/
      {message_id}.jpg
      {message_id}.m4a
      {message_id}.mp4
```

**擴充到雲端只需三步：**
1. 新建 `core/media_storage/gcs_impl.py`（繼承 `BaseMediaStorage`）
2. 在 `__init__.py` 的 `MEDIA_STORAGE_REGISTRY` 加 `"gcs": GcsMediaStorage`
3. `config.toml` 改 `[multimodal.storage] type = "gcs"` + 填入 bucket 設定

不需修改 `multimodal.py`、`app.py` 或任何其他檔案。

## 4. config.toml 新增區塊

新增第 15 個設定區塊 `[multimodal]` + `[multimodal.storage]`：

```toml
[multimodal]
enabled = true
provider = "gemini"
model_name = "gemini-2.5-flash-lite"
temperature = 0.2
api_key_env = "GEMINI_API_KEY"

image_prompt = "你是電子鎖客服助手。請描述這張圖片的內容..."
audio_prompt = "你是電子鎖客服助手。請描述這段音檔的內容..."
video_prompt = "你是電子鎖客服助手。請描述這段影片的內容..."
sticker_reply = "收到您的貼圖了！請問有什麼關於電子鎖的問題我可以幫忙的嗎？"

max_file_size_mb = 20
download_timeout = 10
preprocessing_timeout = 30
fallback_text = "抱歉，我無法辨識您傳送的{media_type}。請用文字描述您的問題，或拍攝更清晰的照片重新傳送。"

[multimodal.storage]
type = "local"
local_path = "./data/media"
```

`core/config.py` 新增第 15 個 export：`MULTIMODAL_CONFIG`。
