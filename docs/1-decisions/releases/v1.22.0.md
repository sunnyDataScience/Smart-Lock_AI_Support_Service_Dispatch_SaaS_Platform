# 進度報告 v1.22.0：WebSocket 認證強化（JWT + tenant + RBAC）

- **版本**: v1.22.0（前版：v1.21.0 → 本版升級類型：MINOR）
- **Commit**: `3a36b6a` (2026-05-06 00:30)
- **分支**: feat/api-subflow-endpoints
- **作者**: Imding1211
- **影響模組**: `api/realtime/ws_hub.py`、`api/main.py`

## 變更摘要 (WHAT)

- `ws_hub.py` 新增 `WSAuth` dataclass、`verify_ws_token`、`authorize_channel` 三個函式
- `main.py` 9 個 WS endpoints 升級為 `_ws_authorized_subscribe`，各自指定 ACL：
  - notifications：path_user_id 必須等於 token sub
  - pool：path_tech_id 等於 sub 或 admin/ops_mgr
  - dispatch-queue / sla-alerts / inventory：admin/ops_mgr/tenant_admin
  - refunds：admin/ops_mgr/accountant
  - disputes：admin/ops_mgr/support_agent
  - rbac：任何登入者
  - work-orders：tenant 內任何登入者

## 背景與動機 (WHY)

v1.20.0 WS server 為 PoC，僅檢查 token 存在性，存在三類安全漏洞：跨 user 偷聽、跨 tenant 訂閱、技師看別人 pool。本次補完 JWT 簽章驗證 + 過期/撤銷 + tenant 隔離 + RBAC，使 WS 達生產級。

## 影響評估 (IMPACT)

- **不向下相容**：舊 PoC 假 token 連線會被 close(1008)；前端必須帶真實登入後的 access_token
- 前端不需改：v1.8.0 realtime.ts 已正確帶 access_token + tenant_id query
- 安全：滿足生產級 WS 認證

## 驗證方式

### 自動化
- ✅ 後端載入成功（118 routes，9 WS）

### 手動驗證

```bash
# 1) 假 token 連線應被拒
npx wscat -c "ws://localhost:8001/realtime/notifications/abc?access_token=invalid"
# 預期：close 1008 invalid_token

# 2) 別人 user_id 連線應被拒
TOKEN=<取得 user_id=A 的 token>
npx wscat -c "ws://localhost:8001/realtime/notifications/<其他 user_id>?access_token=$TOKEN"
# 預期：close 1008 user_id_mismatch

# 3) 跨 tenant 連線應被拒
npx wscat -c "ws://localhost:8001/realtime/dispatch-queue?access_token=$TOKEN&tenant_id=<其他 tenant>"
# 預期：close 1008 tenant_mismatch

# 4) 技師訂閱 dispatch-queue 應被拒
TECH_TOKEN=<技師 token>
npx wscat -c "ws://localhost:8001/realtime/dispatch-queue?access_token=$TECH_TOKEN"
# 預期：close 1008 role_not_allowed:technician

# 5) Admin 訂閱該技師 pool 監控
ADMIN_TOKEN=<admin token>
npx wscat -c "ws://localhost:8001/realtime/pool/<tech_user_id>?access_token=$ADMIN_TOKEN"
# 預期：成功連線
```
