`refund_requests.requires_dual_sign` 欄位 schema 已備但 service 從未利用，金額 > 100k 的退款也只需單人核准，違反業務規則。本次補完狀態機 + 同 user 不可雙簽 + UI 提示，達到 Flow 6 完整的退款審批流程。

## 影響評估 (IMPACT)

- 不向下相容：approval_chain entry 多帶 `stage` 欄位；舊紀錄不影響邏輯

- 後續可加：refund 審批逾時自動 cancel / 通知 finance 角色（P2）

## 雙簽狀態機

```
                 +----------+
                 | pending  |
                 +----------+
              /     |        \
           reject  approve  escalate
           /        |          \
          v        v           v
   +---------+  分流：             +---------+
   |rejected |  requires_dual_sign |escalated|
   +---------+   /        \        +---------+
                FALSE    TRUE
                 |         |
                 v         v
            +---------+  +-------------+
            |approved |  |csm_approved |
            +---------+  +-------------+
                            |        \
                         approve   reject
                         (不同 user)  |
                            |        v
                            v    +---------+
                         approved |rejected |
                                  +---------+
```

| 步驟 | 預期 |
|:---|:---|
| 進 `/admin/refunds` 看大額（>100k）pending 案件 | 雙簽欄位顯示「需」 |
| User A 點「核准」+ 填理由 | 狀態變 `csm_approved`（橘色「等候第二簽」）|
| User A 再次點「第二簽」 | 409 DUAL_SIGN_SAME_USER 錯誤 |
| User B 點「第二簽」+ 理由 | 狀態變 `approved`（綠色已核准）|
| 任何階段 reject | 狀態變 `rejected` |
| WS 推送 payload | 含 `requires_dual_sign` + `awaiting_second_sign` |

### Curl 測試

```bash
# 第一簽（User A）
curl -X POST http://localhost:8001/api/v1/refunds/<id>/decision \
  -H "Authorization: Bearer $TOKEN_A" -H "X-Tenant-ID: $TENANT" \
  -H "Idempotency-Key: $(uuidgen)" -H "Content-Type: application/json" \
  -d '{"decision":"approve","reason":"已查驗服務瑕疵"}'
# → status=csm_approved（若 requires_dual_sign）

# 第二簽（User B）
curl -X POST http://localhost:8001/api/v1/refunds/<id>/decision \
  -H "Authorization: Bearer $TOKEN_B" -H "X-Tenant-ID: $TENANT" \
  -H "Idempotency-Key: $(uuidgen)" -H "Content-Type: application/json" \
  -d '{"decision":"approve","reason":"財務核可"}'
# → status=approved
```
