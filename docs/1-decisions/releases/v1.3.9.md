- **Commit**: `63477c1` (2026-05-04 21:08)

- **影響模組**: `agent/agent_tools/`、`agent/harness/`（debounce + output_validator）、`agent/prompts/`

## 變更摘要 (WHAT)

- `agent/agent_tools/tools.py`：把 `_current_brand` / `_current_model` 從 ContextVar 改成 module-level dict（`_brand_by_user` / `_model_by_user`，keyed by user_id）。`user_id` 仍走 ContextVar（debounce 入口單次 set）。`set_current_brand` / `get_current_brand` / `get_current_model` API 不變。
- `agent/prompts/system.md`：刪除「請說：我這邊沒有 {brand} 的詳細資料，建議您查看說明書」這條指示，改為禁止這兩句、優先 `_common/*` 或 `transfer_to_human`。新增章節「客戶問的品牌/型號與 [用戶資料] 不同時的處理」要求先 `update_user_info` 切換再 `load_product_info`。
- `agent/harness/debounce.py`：路徑 C header 同步移除禁用語；`infer_brand_from_text` 改為每輪都跑，新增「場景 2」mismatch 強提示注入。
- `agent/harness/output_validator.py`：fast-path correction 依命中片段語意分流（說明書 / 設備型號是 / 內部機制用語）給對應指引。模組仍維持 `enabled=false`。
- `agent/config.toml`：`forbidden_phrases` 新增具體片段（「查看該產品的說明書」「因為您目前的設備型號是」等），避開寬泛詞防誤殺。

## 背景與動機 (WHY)

正式環境同時出現兩個問題：

1. **拒答話術**：客戶（已記錄 Dormakaba/AS901）詢問 Chatlock A90 掌紋設定，agent 回「我這邊沒有 Chatlock A90 的詳細資料，建議您查看該產品的說明書」。這句話被 System Prompt 與 debounce header 明文指定為標準回覆，但實際把客戶推回說明書，違反客服角色。
2. **ContextVar 跨 task 不傳遞**：LLM 已會主動呼叫 `update_user_info(brand="Chatlock", model="A90")`，但下一個 `load_product_info(name="Chatlock/A90")` 仍以 `profile=Dormakaba/A90` 被拒。Cloud Run log：

   ```
   [update_user_info] 已更新: 品牌: Chatlock, 型號: A90，品牌產品資料已解鎖
   [product_info] >>> 拒絕載入: Chatlock/A90（profile=Dormakaba/A90）
   ```

   根因：LangGraph ToolNode 在獨立 asyncio task 跑每個 tool，`ContextVar.set()` 只影響該 task 自身 context，不會傳給下一個 tool 的 task。

選擇 module dict 而非「每次重讀 DB」是為了避免每個 tool call 多一次 DB round-trip（asyncio 單一 event loop 下 dict 操作沒有 race，且 user_id 透過 ContextVar 從 parent → child 複製是 ContextVar 唯一可靠的傳遞方向）。

## 影響評估 (IMPACT)

- **破壞性變更**：無。`set_current_brand` / `get_current_brand` / `get_current_model` 公開 API 不變；ContextVar 只是退到內部從共享儲存改為 dict。
- **行為變更**：
  - 跨品牌詢問將觸發 `update_user_info` → `load_product_info` 雙呼叫流程
  - mentioned_brand 偵測為純字串掃描，「我朋友的 Chatlock 鎖」這類間接提及也會觸發場景 2 提示；**不直接寫 DB**，由 LLM 自行決定是否切換
  - `output_validator` 仍維持停用（成本/延遲考量 + multi-turn 失效問題尚未解決），這次只重整其 correction 訊息以備將來開啟
- **後續動作**：
  - 必須重新部署 Cloud Run（`./agent/scripts/deploy.sh`）才會生效，本機改 .py 不會自動同步到 image
  - 受影響模組：`agent/agent_tools`、`agent/harness`、`agent/prompts`；`data/`、`web/` 不受影響

## 驗證方式

實機回歸場景 case（部署後）：

1. 用已記錄為 Dormakaba/AS901 的測試帳號發訊「怎麼設定 Chatlock A90 掌紋」
2. 預期 log 序列：

   ```
   [update_user_info] 已更新: 品牌: Chatlock, 型號: A90，品牌產品資料已解鎖
   [product_info] >>> 載入: Chatlock/A90    ← 不再被拒
   ```

3. 預期回覆內容：直接給 Chatlock A90 掌靜脈設定步驟，不出現「查看說明書」「因為您目前的設備型號是」等字眼

對 quality_check 影響：`set_current_brand` 介面不變，現有 golden set 不需改動；下次 `python -m quality.quality_check` 應綠燈。
