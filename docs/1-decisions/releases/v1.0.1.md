- **分支**: agent-improve

## 變更摘要 (WHAT)

- 新增 `_generate_md(report, path)`：輸出帶時間戳的 Markdown 摘要，含通過率、Verdict 摘要表、分類表現表、未通過案例詳細區塊（question / expected / keywords / skills / reason / answer code block）
- `_save_report()` 簽名加入可選 `md_path` 參數，三個 call site（正常 / `--judge-only` / `--retry-failed`）統一傳入
- 輸出檔名 `agent/quality/quality_report.md`，與既有手寫 `UAT_REPORT.md` 解耦避免互覆

## 背景與動機 (WHY)

Opik 退場後 `quality_check` 是唯一仍會跑的離線品質基線，但既有輸出僅 `quality_report.json` + `.html`。要貼到 PR 描述、Slack 訊息、docs/ 還得手動整理 — 重複勞動讓人懶得跑或懶得貼，回歸測試文化反而被工具拖住。一個自動產出的 Markdown 摘要能直接 `cat` 到剪貼簿。

## 影響評估 (IMPACT)

- **破壞性變更**: 無。`md_path` 為 `Optional`，舊呼叫端（若有外部腳本直呼 `_save_report`）不受影響
- **CI / cron**: 不需改動，多輸出一個檔案不影響既有 JSON / HTML 流程
- **檔案隔離**: 自動產出固定檔名 `quality_report.md`，與手寫 `UAT_REPORT.md` 解耦

## 驗證方式

1. 跑完整 quality_check：
   ```bash
   cd agent && python -m quality.quality_check
   ls -la quality/quality_report.md  # 應存在，並有當下時間戳
   ```
2. 跑 `--judge-only` 重新評分：
   ```bash
   cd agent && python -m quality.quality_check --judge-only
   # 應同步刷新 quality_report.md 內容
   ```
3. 跑 `--retry-failed` 重測非 pass 案例：
   ```bash
   cd agent && python -m quality.quality_check --retry-failed
   # 應合併結果並更新 quality_report.md
   ```
4. 語法檢查已通過：`python -c "import ast; ast.parse(open('agent/quality/quality_check.py').read())"`
