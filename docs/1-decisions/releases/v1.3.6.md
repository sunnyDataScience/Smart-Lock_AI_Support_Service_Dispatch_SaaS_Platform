# 進度報告 v1.3.6：agent/skills/ 重命名為 agent/agent_tools/，清掉 [skills] config 區段

- **版本**: v1.3.6（前版：v1.3.5 → 本版升級類型：PATCH）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: agent/agent_tools/（原 skills/）、agent/agent.py、agent/harness/debounce.py、agent/quality/quality_check.py、agent/core/config.py、agent/config.toml、agent/config.eval.toml、agent/main.py

## 變更摘要 (WHAT)

### A. 目錄重命名
`agent/skills/` → `agent/agent_tools/`（透過 `git mv` 保留歷史）

理由：模組裡只剩 `load_product_info` / `update_user_info` / `transfer_to_human` 三個 agent tool 與 ContextVar helper，與「skills」（早期 SKILL.md 架構的命名）已無語意關聯。

### B. import 路徑同步更新
- `agent.py`: `from skills.tools import ...` → `from agent_tools.tools import ...`
- `harness/debounce.py`: 同上
- `quality/quality_check.py`: 同上（function 內 import 也改）

### C. 移除過時 config
- `config.toml` / `config.eval.toml` 刪除 `[skills]` 區段（`data_dir = "skills/data"` 已無人讀取）
- `core/config.py` `AppConfig` 移除 `skills: dict` 欄位、`load_config` 移除 `skills=data.get("skills", {})`
- 章節編號重新對齊（原 `## 5. 技能系統` 移除後，`## 5. 提示詞檔案路徑` 補位）

### D. docstring / 註解 / 變數名清理
- `core/config.py` docstring「agent_skills/」→「agent/」（2 處）
- `quality/quality_check.py` 變數 `_AGENT_SKILLS_DIR` → `_AGENT_DIR`（5 處）並改寫 sys.path 註解
- `main.py` Section 5 標題從「舊 skills/data 已清空」改為「skills/ → agent_tools/ 命名重構」並驗證新目錄存在

## 背景與動機 (WHY)

承接 v1.3.5（移除 `load_skill` 函式與 `Skill` dataclass）。資料 + 函式都退場後，`agent/skills/` 這個目錄名稱已徹底失去原意——裡面只剩 product_info / profile / transfer 三個跨領域 agent tool。保留舊名造成：

1. 新人 onboarding 看到「skills」會以為還有舊 SKILL.md 架構
2. CLAUDE.md 與其他 doc 仍用「skills」描述會誤導
3. config.toml 的 `[skills]` 區段成為廢欄位卻仍被 `load_config` 讀進 dataclass

本期一次完成：目錄改名 + 引用同步 + config 清理 + docstring 對齊。

## 影響評估 (IMPACT)

- **破壞性變更**：對外 HTTP API / LangGraph tool 名稱無影響。內部模組路徑變動：`skills.tools` → `agent_tools.tools`（外部腳本若有直接 import 需同步調整，目前 agent / web / data 三大模組無此外部 import）
- **回滾**：`git revert` 可一鍵還原（`git mv` 保留 history，blame 不會斷）
- **效能**：無變化
- **清理收益**：刪除廢欄位 `cfg.skills`、整合常數命名、目錄語意對齊
