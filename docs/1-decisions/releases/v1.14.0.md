## 變更摘要 (WHAT)

- 新增 `SlaAlertBanner` 元件，訂閱 `/realtime/sla-alerts`：
  - 三種 alert_type 各自的圖示/顏色/描述/處理連結
  - 最多保留 5 筆，含「處理」CTA / 個別忽略 / 全部已讀 / 收合
  - 無告警時顯示狀態列（含 RealtimeIndicator）
- 掛在 `/dashboard` KPI 卡之上

## 背景與動機 (WHY)

10 個 realtime 頻道中 SLA alerts 是 dashboard 唯一還沒整合的，原本管理員需手動刷新才能發現 SLA 違反。Flow 2（拒單重派）/ Flow 9（客訴升級）的觸發點都依賴此告警。

## 影響評估 (IMPACT)

- 破壞性變更：無
- 部署需求：要啟用即時告警需設 `NEXT_PUBLIC_REALTIME_BASE_URL`
- Realtime 頻道整合進度：6/10（notifications/pool/dispatch-queue/work-orders/diagnostics/sla-alerts）


| 場景 | 預期 |
|:---|:---|
| 無 base url | banner 顯示「未配置」 |
| 設 base url 但無告警 | 顯示「目前無告警」+ 綠/橘脈衝點 |
| WS 推送 quote_expiring | 黃色卡片 + 處理 CTA → `/work-orders/<id>` |
| WS 推送 dispatch_delay | 紅色卡片 + 處理 CTA → `/admin/dispatch-manual?work_order_id=<id>` |
| WS 推送 response_overdue | 橘色卡片 + 處理 CTA → `/work-orders/<id>` |
| 點 X 忽略單筆 | 從列表移除 |
| 全部已讀 | 列表清空 |
| 收合 | 隱藏列表保留 header |
