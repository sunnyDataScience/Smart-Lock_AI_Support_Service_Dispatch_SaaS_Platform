## 變更摘要 (WHAT)

- `harness/debounce.py`：自動推論條件由「brand 為空」改為「mentioned_brand 與當前 brand 不同即切換」，並在切換時清掉舊型號避免跨品牌型號污染 gating；同品牌新型號也會更新。
- `harness/output_validator.py`：新增 `_check_brand_model_mismatch` 快速正則檢查（0ms 免 LLM），偵測「{品牌名}{0-3 字元，含「的」}{他牌型號}」配對；命中即觸發重試並注入修正 correction。索引建構自 `line_ui_factory._brand_models`，與 `config.toml [quick_reply]` 同源。
- `profiles/manager.py`：新增 `clear_fact(user_id, attr_key)`（過期不寫新值，供品牌切換清舊型號用）。
- `harness/line_ui_factory.py`：新增 `get_all_brand_models()` export。
- `app.py`：init 順序調整——`init_quick_reply` 須先於 `output_validator.init`，因後者在啟動階段建立品牌型號錯配索引。
- 店家資訊：LINE 官方帳號 `@706mrped` → `@locksmart`（同步更新 `product_info/_common/store-info.md`、`data/storage/{bronze,silver}/website/scsmtw_wixsite_com_locksmartnew.{md,json}`、`quality/reports/quality_report_2026-05-03_0852.md` 樣本）。

## 背景與動機 (WHY)

實際使用者回報三輪對話中，agent 把 Chatlock A90 的指紋 SOP 套上「Dormakaba A90」標題回覆：

| 輪 | 用戶輸入 | agent 行為 |
|---|---|---|
| 1 | 怎麼設定 Chatlock A90 掌紋 | facts 寫入 Chatlock/A90，正確回覆 ✅ |
| 2 | 怎麼設定 Dormakaba 的 WiFi | `mentioned_brand=Dormakaba` 但 `not brand` 為 False → **不更新**；agent 也沒呼叫 `update_user_info`；facts 仍是 Chatlock/A90 |
| 3 | 請問 dormakaba 設定指紋 | facts 還是 Chatlock/A90 → `[可用產品資料]` 仍列出 Chatlock/A90 → LLM 載入該文件 → 把 A90 指紋步驟貼到「Dormakaba」標題下 ❌ |

根因兩個獨立 bug：
1. **B1 (`harness/debounce.py:296` 自動推論盲區)**：條件 `mentioned_brand and not brand` 假設「品牌只會從空變有，不會切換」。一旦 facts 被首輪寫入，後續換品牌只能靠 LLM 主動呼叫 `update_user_info`——這是脆弱假設。
2. **B2 (H7.5 輸出驗證盲區)**：`output_validator.py` 只檢查內部機制禁用語與 LLM 語意，沒做「品牌×型號合法性」交叉檢查，跨品牌錯配可穿透。

## 影響評估 (IMPACT)

- **破壞性變更**：無。
- **行為變動**：
  - 既有跨品牌切換對話（如 Chatlock → Dormakaba）行為改變——facts 會被自動覆寫，下一輪 agent 看到的 `[用戶資料]` 與 `[可用產品資料]` 會基於新品牌。
  - `output_validator` 多一個 retry 觸發類型（max_retries 上限不變，預設 1）；快速路徑 0ms，無延遲影響。
  - `debounce` 多一次 `update_fact` 背景 task（fire-and-forget 不阻塞回覆）。
- **店家資訊變動**：LINE ID 變更會立即影響 agent 對「LINE / 客服管道」類問題的回覆內容；evals 若有引用 LINE ID 樣本可能需重跑。
- **後續動作**：建議重跑 `quality/quality_check` 確認 LINE ID 樣本通過、跨品牌切換樣本不再出現錯配。

## 驗證方式

1. **單元層級（已驗）**：對 6 個樣本（含 `Dormakaba A90` / `Dormakaba AS701` / `Chatlock A90` / 跨品牌敘述但無 adjacency / `Dormakaba的A90` / case-insensitive `dormakaba a90`）跑 `_check_brand_model_mismatch` 行為正確。
2. **靜態層級（已驗）**：5 個編輯檔案 `ast.parse` 全部通過。
3. **整合層級（待跑）**：
   - 啟動 FastAPI（`uvicorn app:app --reload --port 8000`），用固定 user_id 跑：
     ```
     curl "http://localhost:8000/chat?q=怎麼設定 Chatlock A90 掌紋&user_id=test-switch"
     curl "http://localhost:8000/chat?q=請問 dormakaba 設定指紋&user_id=test-switch"
     ```
     第二輪應回 Dormakaba 通用內容（無 A90 字樣）；用 `python scripts/view_facts.py test-switch` 驗 facts 已切到 Dormakaba 且 model 已被清掉。
