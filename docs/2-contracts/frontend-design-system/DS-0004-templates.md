## 1. 模板使用原則

### 1.1 佈局強制規則

```
規則 1：Admin 頁面 → 必須使用 Sidebar Layout
  - 左側深色導航 240px (#1E293B)
  - 主內容區 max-width: 1200px (1440px - 240px sidebar)
  - 導航收合時 64px (Tablet)，隱藏時漢堡選單 (Mobile)

規則 2：Tech PWA 頁面 → 必須使用 Bottom Nav Layout
  - 底部導航 56px + safe-area-inset-bottom
  - 單欄 max-width: 480px
  - 底部導航永遠可見（最高 z-index: 50）

規則 3：Auth 頁面 → 無導航的全螢幕佈局
  - 不含 Sidebar 也不含 Bottom Nav
  - 獨立的 Split Layout
```

### 1.2 五種標準狀態

每個模板都必須處理以下 5 種狀態，無一例外：

| 狀態 | 說明 | 視覺處理 | 適用端 |
|------|------|---------|--------|
| **Default** | 正常載入完成，有資料 | 完整 UI 呈現 | Admin + Tech |
| **Loading (Skeleton)** | 資料載入中 | Skeleton Screen，保留佈局框架，灰色脈衝動畫 | Admin + Tech |
| **Empty** | 無資料可顯示 | 引導圖示 + 說明文字 + CTA 按鈕 | Admin + Tech |
| **Error** | API 失敗或系統錯誤 | 紅色提示橫幅 + 錯誤描述 + 建議動作 + 重試按鈕 | Admin + Tech |
| **Offline** | 網路斷線（技師外勤場景） | 灰色頂部橫幅「目前離線，資料可能不是最新」+ 快取資料顯示 | **僅 Tech PWA** |

### 1.3 模板組合規則

```
規則 4：模板是「約束」不是「裝飾」
  - 模板定義資訊架構和區塊排列
  - 視覺風格來自 00_Foundations 的 Design Tokens

規則 5：模板可嵌套
  - Dashboard 模板內嵌入 Data Table Pattern
  - Detail 模板內嵌入 Form Pattern + Timeline Pattern
  - Dispatch 模板內嵌入 Kanban Pattern + Map Pattern

規則 6：模板有 RWD 行為
  - 每個模板定義 Desktop / Tablet / Mobile 的 reflow 規則
  - Admin: 1440px → 1024px → 768px 三階段
  - Tech PWA: 480px → 768px 兩階段（少數平板場景）

規則 7：狀態色系統一
  - 工單 13 狀態 → 6 色組（詳見 Brand System 語義色系）
  - 所有模板中 StatusBadge 使用相同色碼，不得自訂
```


### KPI Card 規格

```
KPI Card 結構：
┌────────────────────────────┐
│  今日派工數                  │  ← text.body.sm (12px), color.text.secondary
│                            │
│       47                   │  ← text.kpi (36px/700), tabular-nums
│                            │     font-variant-numeric: tabular-nums
│  ↑ 12.5% vs 昨日           │  ← text.body.sm, color.success (#10B981)
└────────────────────────────┘     ↓ 時為 color.error (#EF4444)
                                   → 持平時 color.text.disabled (#94A3B8)

尺寸規格：
  - 最小寬度：200px
  - 內距：space.4 (16px)
  - 圓角：radius.lg (8px)
  - 背景：color.bg.surface (#FFFFFF)
  - 陰影：shadow.sm
  - Hover：shadow.md + cursor pointer（點擊跳轉對應列表）
  - Grid：grid-cols-4 → grid-cols-2 (tablet) → grid-cols-2 (mobile)
  - Gap：space.4 (16px)
```

| RWD | Tablet/Mobile: 全寬堆疊 | Tablet/Mobile: 全寬堆疊，排在主圖表下方 |

| 屬性 | 值 |
|------|-----|
| 顯示筆數 | 最近 10 筆 |
| 欄位 | 工單編號 / 客戶名 / 問題摘要 / 狀態 Badge / 指派技師 / 更新時間 |

### 五種狀態處理

| 狀態 | Dashboard 處理方式 |
|------|-------------------|
| Default | 完整 KPI + 圖表 + 表格 |
| Loading | 4 個 KPI Skeleton 矩形 + 2 個圖表 Skeleton + 表格 Skeleton (5 行) |
| Empty | KPI 顯示 0 值 + 圖表顯示「暫無數據」+ 表格 Empty State「目前沒有工單記錄」 |
| Error | 頂部紅色 Alert Banner「數據載入失敗，請重新整理頁面」+ 重試按鈕 |
| Offline | N/A（Admin 端不處理離線） |

### 狀態依賴的操作區塊

操作區塊的按鈕根據工單當前狀態動態變化：

| 工單狀態 | 主要操作 (CTA Amber) | 次要操作 | 備註 |
|---------|---------------------|---------|------|
| 已派工 (assigned) | 接受工單 | 拒絕工單 / 聯繫客服 | 拒絕需填理由 |
| 已接受 (accepted) | 開始前往 | 聯繫客戶 / 聯繫客服 | 觸發技師位置追蹤 |
| 進行中 (in_progress) | 確認完工 | 回報異常 / 聯繫客服 | 需上傳至少 1 張照片 |
| 範圍變更 (scope_changed) | 提交報價 | 回報異常 / 聯繫客服 | 開啟報價表單 |
| 缺料中 (material_pending) | 料件到齊 | 回報異常 / 聯繫客服 | 更新狀態 |

### 照片上傳區規格

```
照片上傳：
  - Grid: 3 columns, gap: space.3 (12px)

  - 新增按鈕: 虛線邊框 + 「+」icon, 48px 最小觸控
  - 來源: Camera API (優先) 或 File picker
  - 限制: 最多 5 張, 單張 < 5MB, JPG/PNG
  - 上傳: 選擇後立即上傳, 顯示進度條
  - 預覽: 點擊可全螢幕預覽 + pinch-zoom
  - 刪除: 長按 → 「移除此照片？」確認
```

```
E-Signature Canvas：
```
