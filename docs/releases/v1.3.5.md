# 進度報告 v1.3.5：移除 load_skill 函式與舊 skills 架構殘留引用

- **版本**: v1.3.5（前版：v1.3.4 → 本版升級類型：PATCH）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211

## 變更摘要 (WHAT)

### A. `agent/skills/tools.py` 大幅縮減
移除已死碼：
- `load_skill` tool 函式（68 行）
- `_skills` 全域 list、`_skills_section_cache`
- `set_skills()` 注入器
- `build_skills_prompt()` / `build_dynamic_skills_section()` 渲染函式
- `_SUB_SKILL_PREFIXES` / `_SUB_SKILL_EXCEPTIONS` 子技能常數
- `from . import Skill` 引用

`update_user_info` 改回傳「可用產品資料清單」（透過 product_info `filter_loadable`），不再渲染 skill section。新增私有 helper `_build_product_docs_section()`。

`transfer_to_human` 守門訊息文字由「請先用 load_skill 載入...」改為「請先用 load_product_info 載入 _common/troubleshoot、_common/dispatch 或 {brand}/{model}...」。

`_skill_loaded_this_run` ContextVar 改名為 `_doc_loaded_this_run`（語意對齊）。

### B. `agent/skills/__init__.py` 縮為 package marker
移除 `Skill` dataclass、`load_skills()`、`filter_skills()`、`_parse_skill_md()`、`_infer_brand_model()` 全部 148 行 → 5 行 docstring。

### C. `agent/agent.py` 清理 import 與啟動流程
- 移除 `from skills import load_skills`
- 移除 import 中的 `load_skill`、`set_skills`
- 刪掉註解掉的 `set_skills([])` 流程
- 移除「暫時停用 load_skill」相關註解
- docstring 由「Skill-based ReAct agent」改為「ReAct agent — 極簡版智慧鎖 AI 客服（product_info 架構）」

### D. `agent/harness/debounce.py` 清理舊架構引用
- cleanup 分支移除 `if tc.get("name") == "load_skill"` 判斷，只處理 `load_product_info`
- 變數 `skill_names` → `doc_names`
- audit `risk_level` 判斷由 `tool_name in ("load_skill", "load_product_info")` 改為 `tool_name == "load_product_info"`
- transfer guard 修正指令訊息「用 load_skill 載入」→「用 load_product_info 載入」
- docstring 與註解清理（「load_skill 回傳的完整 SOP」→「load_product_info 回傳的完整 mega-doc」等 4 處）

### E. `agent/app.py` FastAPI title 更新
`Smart Lock AI Agent — Skill-Based` → `Smart Lock AI Agent — Product Info`

## 背景與動機 (WHY)

承接 v1.3.4（刪除 67 份 SKILL.md 資料）：資料層已淨空，但程式層仍保留 `load_skill` 函式、`Skill` dataclass、skill list 渲染邏輯等死碼。雖然 v1.2.1 起 `set_skills([])` 已讓 `load_skill` 回「找不到技能」、`agent.py` 也只註冊 `load_product_info` 三件 tool，但這些殘留：

1. 對 onboarding 造成誤導（看到 `load_skill` 函式以為還在用）
2. `update_user_info` 仍呼叫 `build_skills_prompt(_skills, ...)` → 永遠回空清單，徒增認知負擔
3. cleanup / audit / transfer guard 的舊條件分支永遠走不到，純雜訊
4. `Skill` dataclass 與 frontmatter parser 完全沒人用

studio_results 分析確認 product_info 架構已 100% 取代舊 skill 內容覆蓋（v1.3.4 commit 已驗證），是時候徹底拔除。

## 影響評估 (IMPACT)

- **破壞性變更**：無對外 API 影響。`agent/skills/` package 仍存在，三個現役 tool 路徑不變
- **回滾路徑**：`git revert` 可恢復；本 commit 不刪檔，僅編輯
- **效能**：啟動時不再 walk `skills/data/`、不再 parse YAML frontmatter，省下 cold-start 數十 ms
- **後續可選**：將 `agent/skills/` 改名為 `agent/agent_tools/`（純命名語意修正，需動 5+ 處 import）
