## 變更摘要 (WHAT)

- 共用 `useBroadcast` hook + 統一 channel 常數 + 兩個事件型別 union
- 通知端三處整合（page / Bell / Drawer）— channel `smartlock.notifications`
- 工單端整合（reschedule）— channel `smartlock.work-order.<id>`

## 背景與動機 (WHY)

同 user 多 tab 時狀態各自為政：A tab 標記已讀後 B tab 仍顯示未讀紅點、同一工單兩個 reschedule tab 可能重複送出。對齊 spec 提到的 "Multi-tab Sync: WS + BroadcastChannel"。

## 影響評估 (IMPACT)

- 無破壞性：BroadcastChannel 不可用時 silent disabled
- UX 改善：跨 tab 即時同步未讀數、全部已讀、改期送出
- 後續可擴充：completed / scope-change 等工單事件

## 驗證方式

### 自動化
- ✅ `npx tsc --noEmit` exit 0
- ✅ `npx next build` 成功

### 手動驗證

```bash
cd web && npm run dev
# 登入後開兩個 tab
```

#### 通知跨 tab
1. Tab A、Tab B 都開 `/notifications`
2. Tab A 點某則「標為已讀」→ Tab B 該則消失（unread tab）/ 變灰（all tab）
3. Tab A 點「全部已讀」→ Tab B 紅點數歸 0、列表清空
4. 任一 tab 透過 WS 收到新通知 → 另一 tab 列表也插入頂端

#### 通知 Bell + Drawer
1. Tab A 開 `/dashboard`（header bell 顯示紅點 N）
2. Tab B 開 `/notifications` 標記已讀
3. Tab A header bell 紅點數 -1

#### 工單改期跨 tab
1. Tab A、Tab B 都開 `/my-orders/<id>/reschedule`
2. Tab A 選時段送出
3. Tab B 自動跳「改期請求已送出」綠 toast → 1.2 秒後返回詳情頁
