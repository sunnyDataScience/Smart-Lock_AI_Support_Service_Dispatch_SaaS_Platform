## 變更摘要 (WHAT)

新增兩個 GitHub Actions lint workflow，照既有 `db-conn-lint.yml` 同款式（純 bash + grep + noqa 例外機制）守護 RP2.2 / 2.3 / 2.6 的成果不被後續 PR 回退。

### `reverse-import-lint.yml`（RP2.2 / 2.3 守護）

掃描 `agent/**/*.py`，三條規則：
- `agent/skills/` 不可 `from harness` / `import harness`
- `agent/core/` 不可 `from/import harness` 或 `skills`（leaf 必須最乾淨）
- `agent/harness/` 不可 `from agent` / `import agent` 頂層 module（不掃 `from agent.X` 因 `agent.py` 是檔不是 package）

例外標記：`# allow-rev-import`

### `bare-except-lint.yml`（RP2.6 守護）

掃描 `agent/{harness,quality}` + `api/services` + `data/pipeline`：
- 排除 `scripts/`（CLI 工具可寬鬆）、`core/`（best-effort cleanup）
- 偵測 `^\s*except\s+Exception(\s+as\s+\w+)?\s*:`
- 違規時錯誤訊息附三組常見 typed tuple 範例（DB I/O / LLM-HTTP / JSON parse）+ noqa 語法

例外標記：`# noqa: BLE001`

## 背景與動機 (WHY)

PR #23 / #24 / #25 已 narrow 反向 import 與 bare except，但**架構約束沒有 CI 守護的話就只是「當下乾淨」，下次有人重構或加 import 很容易回歸**。RP2.1 debounce 拆分（仍待觸發）依賴 RP2.2 / 2.3 維持反向 import 為零；若這期間有人引入新的反向耦合，RP2.1 又會被卡住。

採輕量 shell-based 方案而非 ruff/import-linter：
- 對齊既有 `db-conn-lint.yml` 風格，consistency 高
- 無需新增 Python 依賴 / 沒有 ruff config 全域副作用
- 違規訊息可內嵌建議的具體修復模式（typed tuple 範例 / dependency injection 提示）
- 未來若決定全面導入 ruff，這些規則可平行存在，不衝突

## 驗證方式

```bash
# 反向 import 全綠
find agent/skills -name '*.py' | xargs grep -E '^\s*(from harness|import harness)' | grep -v allow-rev-import
find agent/core -name '*.py' | xargs grep -E '^\s*(from harness|from skills|import harness|import skills)' | grep -v allow-rev-import
find agent/harness -name '*.py' | xargs grep -E '^\s*(from agent\s+import|import\s+agent\s*$)' | grep -v allow-rev-import

# bare except 全綠
find agent/harness agent/quality api/services data/pipeline -name '*.py' \
  -not -path '*/__pycache__/*' -not -path '*/scripts/*' \
  | xargs grep -E '^\s*except\s+Exception(\s+as\s+\w+)?\s*:' | grep -v 'noqa: BLE001'
```

兩條都應回傳 0 行。
