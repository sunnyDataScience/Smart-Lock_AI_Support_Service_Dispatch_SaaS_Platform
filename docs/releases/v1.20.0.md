# 進度報告 v1.20.0：WebSocket pub-sub hub + 9 個 realtime endpoints + schedule resolved 通知

- **版本**: v1.20.0（前版：v1.19.0 → 本版升級類型：MINOR）
- **Commit**: `8e4660c` (2026-05-06 00:05)
- **分支**: feat/api-subflow-endpoints
- **作者**: Imding1211
- **影響模組**: `api/realtime/ws_hub.py`、`api/main.py`、`api/services/technician_schedule_service.py`

## 變更摘要 (WHAT)

- **新增** `api/realtime/ws_hub.py`：in-memory pub-sub hub（subscribe / unsubscribe / publish + dead conn 回收）
- **9 個 WebSocket endpoints** 加到 `main.py`，對齊 AsyncAPI 頻道：notifications / work-orders / dispatch-queue / sla-alerts / refunds / disputes / inventory / rbac / pool
- **schedule resolve 接通**：approve/reject 後 `_notify_schedule_resolved` 寫 notifications 表 + hub.publish 推給技師

## 背景與動機 (WHY)

v1.19.0 admin 審核後，技師需 polling 才能看到結果；前端 v1.8.0 WebSocket 訂閱層自從上線一直在「未配置」狀態。本次補後端 WS server，讓即時推送真正實質上線。

## 影響評估 (IMPACT)

- 後端：103 REST → 103 REST + 9 WS routes（118 total）
- 前端不需改：設 `NEXT_PUBLIC_REALTIME_BASE_URL=ws://localhost:8001/realtime` 即可連線
- 限制：
  - WS 認證僅檢查 `access_token` 存在性，不驗 JWT 內容（PoC，正式須補）
  - 單機 in-memory pub-sub，多 worker / 多容器部署需 Redis pub-sub
- 後續：所有 admin 寫入動作（refund/dispute decision、dispatch state change…）都應透過此 hub 推播

## 驗證方式

### 自動化
- ✅ 後端載入成功，9 個 WS routes 註冊
- ✅ 前端 `next build` 成功（不需改）

### 手動驗證

```bash
# 啟動後端
cd api && uvicorn main:app --reload --port 8001

# .env.local 設
echo 'NEXT_PUBLIC_REALTIME_BASE_URL=ws://localhost:8001/realtime' >> web/.env.local

# 啟動前端
cd web && npm run dev
```

| 場景 | 預期 |
|:---|:---|
| 開 `/notifications`、`/dashboard`、`/admin/refunds` 等頁面 | 各頁 RealtimeIndicator 從「未配置」灰 → 連線中橘 → 連線綠脈衝 |
| 技師登入後留在 `/account/schedule` | bell 顯示「即時連線」綠脈衝 |
| Admin `/admin/schedule-requests` 核准技師申請 | 該技師頁面立即收到通知（未讀 +1）+ 月曆休假日變黃色 |
| Console 看 `console.log` for ws message | `{ type: "notification", payload: {...} }` |

### Curl + wscat 測試

```bash
# 取得技師 user_id（從 /technicians/login 解 access_token JWT 的 sub）
# wscat 連線
npx wscat -c "ws://localhost:8001/realtime/notifications/<user_id>?access_token=<token>"

# 另開 admin 終端 approve 一個 pending request
curl -X POST http://localhost:8001/api/v1/admin/schedule-requests/<id>/approve \
  -H "Authorization: Bearer <admin_token>" -H "X-Tenant-ID: ..." \
  -H "Content-Type: application/json" -d '{"note":"已核准"}'

# wscat 該連線應收到 JSON push
```
