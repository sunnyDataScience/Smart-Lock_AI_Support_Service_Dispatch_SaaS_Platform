# 進度報告 v1.3.0：quality_check 對齊新架構 + 服務查詢規則強化 + 保固政策補強

- **版本**: v1.3.0（前版：v1.2.4 → 本版升級類型：MINOR）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: agent/quality/quality_check.py、agent/prompts/system.md、agent/product_info/_common/dispatch.md

## 變更摘要 (WHAT)

三大改動：

### A. quality_check.py 對齊 product_info 新架構
- 移除舊 `build_dynamic_skills_section` 與 `[可用技能]` 注入路徑，改用 `[可用產品資料]` 4 路徑分流（A 齊備 / B model 未知 / C 品牌無 product_info / D 全未知）
- 新增 ai_response 後處理：剝除 `[已參考: ...]` 引用標記（與 production debounce.py 一致）
- 多輪 auto_reply 案例：第二輪前跑 `_cleanup_tool_checkpoint` 模擬 production checkpoint 行為
- Quick Reply 模擬：device_brand 未設且 infer_brand 失敗時自動套 Chatlock 預設
- 工具呼叫紀錄擴充支援 `已載入產品資料:` / `已載入技能:` 雙來源
- 結果增三欄：`brand_resolved` / `model_resolved` / `quick_reply_used`
- 替換 6 題（mega-doc 缺答案）：S-2 / S-8 / S-9 / W-1 / E-5 / E-8
- 調整 5 題 keyword 對齊新 mega-doc 用詞：W-6 / B-4 / B-6 / E-2 / E-9
- 更新 4 題 expected（舊 SKILL.md 過時資訊）：Y-1 / Y-5 / Y-8 / W-7

### B. system.md 4 條 prompt 規則強化
- 拍照禁令精確化：禁「AI 靠照片辨識品牌型號」（誤判率高），允許「請客戶提供安裝環境照片給技師評估」
- multi-turn cleanup 重評估規則：`[已參考: ...]` 不代表文件還在 context，每次新訊息都要重新呼叫 `load_product_info`
- 「服務查詢必載 store-info」剛性規則：客戶問「有沒有提供 X 服務 / 賣不賣 Y 品牌」**必須先載 store-info**，禁止憑常識否認
- load_product_info 工具規則段落擴充：明確列出每類問題該載入哪個 `_common/*` 文件

### C. _common/dispatch.md 保固政策重寫
分兩種情境清楚區分：
- 情境 A：整鎖購買 + 鎖市安裝 → 整鎖保固
- 情境 B：客戶自備鎖 + 鎖市代工 → 僅安裝品質保固，產品故障需洽原購買通路
- 補強「不可承諾整鎖保固」的話術禁忌

## 背景與動機 (WHY)

v1.2.x 跑 quality_check 過程中暴露多重問題：

1. **測試套件還在用舊 `[可用技能]` 路徑**：對齊不完整，不能反映新架構真實表現
2. **LLM judge 跑出 57% pass**（vs keyword 82%）：揭露多個反向錯誤——LLM 在被問及服務（鑰匙複製、汽機車、印章）時憑常識否認，沒主動載 store-info
3. **保固題回答錯誤方向**：dispatch.md 沒寫「自備鎖代工 vs 整鎖購買」差異，LLM 統一答「有保固」誤導客戶
4. **多題 expected 是舊 SKILL.md 內容**：Y-1 / Y-5 / Y-8 等實際 mega-doc 內容已不同

## 影響評估 (IMPACT)

### 通過率變化（LLM judge）
- v5 judge: 38 pass / 17 partial / 11 fail / 1 error（57%）
- **v6 judge: 45 pass / 19 partial / 3 fail / 0 error（67%）**
- pass 率 **+10 pp**，fail 從 11 題降至 **3 題**

### 9 個重點修改題
- 8 題從 fail 變 pass（S-4 / S-8 / S-9 / W-7 / Y-1 / Y-5 / Y-8 / E-9）
- 1 題從 fail 升級 partial（W-3，LLM 回答了印章但漏名片）

### Category 大幅改善
- 報價客服 20% → 50%（+30 pp）
- APP 設定 60% → 90%（+30 pp）

### 新出現的 regression（5 題 pass→partial）
prompt 強化讓 LLM 變得更謹慎，副作用：
- W-5 / M-2 / E-5 / E-7 / B-4：從 pass 變 partial，多為 LLM 改用更保守的問訊方式而非直接給答案

### 破壞性變更
無。所有改動都是測試套件 + prompt 規則 + 知識文件補強，不影響既有對話流程。
