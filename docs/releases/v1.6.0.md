## 背景與動機 (WHY)

依使用者 workflow 盤點報告，A37 派工人工介入是 Flow 2（拒單重派）/ Flow 9（客訴升級）/ Flow 14（排班衝突）三個 Admin 流程的決策樞紐。後端 API（assign / escalate / cancel）已備但前端缺頁，導致三個流程斷鏈。本次以單頁解鎖三個流程，ROI 最高。

### 手動驗證

1. **進入點**：`/admin/dispatch-queue` → 任一工單 row 右側「人工介入」CTA
2. **A37 主頁** `/admin/dispatch-manual?work_order_id=<wo_id>`：
   - [ ] context_panel 顯示工單摘要 + 已嘗試派工次數
   - [ ] 候選列表顯示（含技師分級 / 距離 / 評分 / 可用性）
   - [ ] 熔斷技師標紅 Badge + 禁選
   - [ ] filter sidebar：切換分級 → 即時重新過濾、評分 slider 即時生效
   - [ ] 排序切換（綜合分 / 距離 / 評分）即時重排
3. **指派流程**：
   - [ ] 選技師 → 底部 CTA 顯示「指派給 X」
   - [ ] 點 CTA → 開 modal 填理由
   - [ ] 選 "other" → 補充說明欄位變必填（10-500 字）
   - [ ] 提交成功 → 綠色 toast → 1.5 秒後跳轉 /admin/dispatch-queue
   - [ ] 409 衝突（工單已被他人指派）→ 紅色 banner
   - [ ] CIRCUIT_BREAKER → 提示需雙簽（MVP 待補）
4. **升級主管**：點「升級主管」→ prompt 輸入原因 → POST escalate → toast
5. **取消工單**：點「取消工單」→ 二次確認 → POST cancel → 跳轉 A28
6. **缺 work_order_id**：直接訪問 `/admin/dispatch-manual` → 顯示引導頁回 A28
