- **Commit**: 待補（本次 commit）

- **影響模組**: `agent/skills/`（主要）+ `agent/skills/tools.py`

## 變更摘要 (WHAT)

1. **H-5 修復**：`ts-lock-tongue-chatlock/SKILL.md` 在 Step 1 之前插入 **Step 0「門關著時的緊急緩解」**，明示「禁止叫客戶先把門打開再測試」（門打不開正是問題本身），先指導推緊門板 + 拉動把手的緩解動作。
2. **H-9 修復**：`ts-dual-auth-dormakaba/SKILL.md` frontmatter 強化 — 描述新增「啟動後/會怎樣/什麼現象」描述觸發詞、trigger_keywords 新增 `雙重驗證 / 雙因子 / 啟動後 / 會怎樣 / 什麼現象 / 只有管理者密碼`，並在 `product-knowledge` 加 redirect 指引。
3. **Y-2 修復**：`ss-dormakaba/SKILL.md` 新增「**四、新增使用者（卡片/指紋/密碼）SOP**」整節（按註冊鍵 → 管理員密碼 → 選新增卡片功能 → 感應卡片 → 連續新增 → 結束），並列出 AS701 卡片支援規格（100 張、13.56MHz M1-G1）。frontmatter trigger_keywords 補上 `新增卡片 / 感應卡 / RFID / 悠遊卡 / 一卡通 / AS701` 等。
4. **product-knowledge 新增兩個 redirect block**：
   - `🔐 雙重認證/雙重驗證/雙因子/按兩次` → `load_skill("ts-dual-auth-dormakaba")`
   - `🛠️ 新增使用者/卡片/RFID/指紋/密碼/遙控器設定` → `load_skill("ss-dormakaba")` 或 `ss-chatlock`，並附「載入被拒時先呼叫 update_user_info 反推 brand 重試」的 fallback 指示
5. **`agent/skills/tools.py` `update_user_info`**：當 agent 只給 `model` 沒給 `brand` 時，從 `infer_brand_from_text(model)` 反推 brand，避免 brand 永遠未知導致後續 brand-specific skill 載入被拒。

## 背景與動機 (WHY)

baseline UAT (67 cases) 在前版 (v1.0.0) 達 87% pass，剩 3 個明確 FAIL（H-5、H-9、Y-2）+ 4 partial。本輪目標是消除這三個 FAIL，按 root cause 拆分修法：

- **H-5「鎖舌室內拉不開」**：原 SKILL Step 1 要求「在門打開狀態下測試鎖栓」，但客戶問題正是門打不開。前版直接跳派工，沒給緩解動作 → 補 Step 0 緩解 SOP。
- **H-9「Dormakaba 雙重認證啟動後現象」**：trigger keywords 沒涵蓋「啟動後/會怎樣/什麼現象」，agent 載到 `product-knowledge` 就停了，沒 redirect 到 `ts-dual-auth-dormakaba`。屬純 routing 問題。
- **Y-2「AS701 RFID 感應卡」**：是 routing + 內容雙重缺漏 — `ss-dormakaba` 沒收錄「新增卡片」按鍵步驟，且 product-knowledge 沒 redirect 到 ss-dormakaba。前版只能丟 GDrive 連結，不符合「直接給按鍵步驟」的預期方向。

debug 過程意外發現 `update_user_info(model="AS701")` 漏給 brand 時，brand 永遠不會被設定 → agent 即使想呼叫也救不回來，加 fallback 反推。

## 影響評估 (IMPACT)

- **破壞性變更**: 無（純內容擴充 + tool 容錯增強）
- **UAT 結果（67 cases）**:
  - Pass: 58 (87%) → **63 (94%)**，+5 案例
  - Partial: 6 → 3
  - Fail: 3 → 1
  - 目標案例 H-5 / H-9 / Y-2 全部從 FAIL 變 PASS（kw 命中：3/3、4/4、2/3）
  - 連帶受惠：H-7 門扇反弓 + W-6 老人指紋 也升級 PASS
- **剩餘 1 個 FAIL（E-8 訂單追蹤）**：屬於 `dispatch-guide` 內容過度籠統，無主動引導機制；不在本輪 scope。
