## 變更摘要 (WHAT)

承續 v1.22.1 checkpointer 修復，將剩餘 3 個長壽命 DB 模組統一改用連線池，並補上兩道防線阻擋未來退化：

- **Layer 1 — Pool 統一**：
  - `agent/storage/postgres_impl.py`（audit + llm_usage_log）→ `AsyncConnectionPool`
  - `agent/profiles/manager.py`（user_facts + user_soft_profiles）→ `AsyncConnectionPool`
  - `agent/harness/data_correction.py`（data_corrections）→ `AsyncConnectionPool`
  - 全部移除 `_ensure_conn()`，公開 `get_pool()` 給 health 讀
  - `agent/memory/postgres_saver.py` 補一個對稱的 `get_pool()`
- **Layer 3a — /health 主動驗證**：原本只讀 `_postgres_conn.closed/.broken` 屬性（被動，連線壞了但屬性還沒更新就抓不到），改為對 4 個 pool（含 checkpointer + data_correction）執行 `SELECT 1`，並在回應中標記 `disabled / closed / error / ok` 狀態
- **Layer 2 — CI lint**：新增 `.github/workflows/db-conn-lint.yml`，PR 若在 `agent/`（排除 `agent/scripts/`）新增 `AsyncConnection.connect(` 直接呼叫即失敗，可用 `# allow-direct-conn` 註解標記刻意例外

## 背景與動機 (WHY)

v1.22.1 修了 checkpointer 的單一 conn 問題，但仍留下 3 個同類型模組：

- `_ensure_conn()` 存在 race window — 檢查通過後到 `execute()` 之間連線可能被 CloudSQL 殺掉，`execute()` 失敗 except 只會 print log
- 對 audit / data_correction 影響有限（最差是寫入失敗），但對 **facts 模組**會在 `update_user_info` 流程丟掉品牌資訊，使用者下一輪對話 brand/model fact 直接消失，影響服務品質
- 上一輪事件 checkpointer 死掉，但 `/health` 仍回 200 — 因為 health 只看屬性不真的試連線，這是觀測盲區

選擇 pool 而非加強 `_ensure_conn()`：
- pool 內建 `check_connection` callback，checkout 時就驗證
- pool 從根本消除 race（每個操作都拿到剛驗證過的 conn）
- API 一致性高（4 個模組同模式），未來新模組複製貼上即可

CI lint 的設計原則：白名單例外而非黑名單規則 — 直接禁止關鍵字、必要時用 `# allow-direct-conn` 註解明示例外，留下審計痕跡。

## 影響評估 (IMPACT)

- **破壞性變更**：無
  - `build_*` / `close_*` / `ProfileManager` 方法簽名與行為完全不變
  - `/health` 回應 schema 微擴：新增 `checkpointer` 與 `data_correction_db` 兩鍵；`disabled` 為新狀態值（功能本來就停用 → 不算 degraded）
- **部署**：無 schema migration，Cloud Run 重啟即生效
- **依賴**：`psycopg-pool` 為 `langgraph-checkpoint-postgres` 傳遞依賴，不需動 `requirements.txt`
- **CI 行為變化**：`agent/**/*.py` 的 PR 會多跑一個 lint job

## 驗證方式

- 本機跑新 lint 規則 → `OK: no violations`
- 4 個模組匯入 + `get_pool()` 取用測試通過
- 5 個改動檔案 `ast.parse` 語法檢查通過
- 全 repo 搜 `_facts_conn` / `pm._postgres_conn` / `data_correction._conn` → 零殘留
- 全 repo 搜 `AsyncConnection.connect(`（排除 `scripts/`）→ 零殘留
- 待人工驗證：部署後測 `/health`，預期看到 4 個 pool 都回 `ok`；連續發訊息 + 等 ≥10 分鐘 idle 後再測
