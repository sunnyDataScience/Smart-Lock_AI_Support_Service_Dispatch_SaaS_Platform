# 進度報告 v1.0.9：scripts/view_llm_usage.py 改為預設顯示 Q/A 並修復 main() 旗標引用

- **版本**: v1.0.9（前版：v1.0.8 → 本版升級類型：PATCH）
- **Commit**: 待補（本次 commit）
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: `scripts/view_llm_usage.py`

## 變更摘要 (WHAT)

1. CLI 旗標從 opt-in `--show-content` 反轉為 opt-out `--no-content`；`recent_detail()` 的 `show_content` 預設值從 `False` 改為 `True`，預設執行就會印出 `Q> ...` / `A> ...` 摘要。
2. 修正 `main()` 派發點殘留的 `args.show_content` 屬性引用為 `not args.no_content`，否則 argparse 不會產生 `show_content` 屬性，腳本會直接 `AttributeError`。
3. 同步更新 docstring 範例與 `--help` 行文案。

## 背景與動機 (WHY)

v1.0.8 加上 `--show-content` 時設成 opt-in，但這支腳本的定位本來就是「快速看 Q/A 內容的 query helper」，使用者反饋「執行 `python scripts/view_llm_usage.py` 還是沒顯示使用者跟 AI 回覆」——預設不顯示違反直覺。改為預設開啟、需要關閉時才加 `--no-content`，更符合常用情境。

## 影響評估 (IMPACT)

- **破壞性變更**: 有（小幅）
  - 舊用法 `--show-content` 不再存在；之前還沒人實際靠這個旗標串 pipeline，使用者可改用 `--no-content` 反向關閉。
- **後續動作**: 無

## 驗證方式

```bash
python -m py_compile scripts/view_llm_usage.py             # ✅ pass
python scripts/view_llm_usage.py --help                    # ✅ 顯示 --no-content
python scripts/view_llm_usage.py --since 24h --limit 3     # ✅ 預設輸出 Q> / A> 兩行
```

實測輸出 26 筆呼叫、預設明細含 `Q>` / `A>` 摘要正常顯示。
