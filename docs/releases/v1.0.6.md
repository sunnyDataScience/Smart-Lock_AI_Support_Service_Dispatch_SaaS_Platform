## 背景與動機 (WHY)

舊規則「報告寫進該模組底下 `docs/report/`」帶來兩個痛點：
- 同一份 commit 跨模組時，要決定主要受影響模組才能落點，邊界模糊。
- 多個模組各自獨立版號，瀏覽全專案進度時要跑遍 N 個資料夾，難以一眼看到時間軸。

集中到根目錄 `report/` + 全域遞增版號，等於把進度報告當作專案層級的 changelog，新加入者可一眼按時間掃完。模組資訊改寫進報告內文 `**影響模組**` 欄位，不犧牲可追溯性。

## 影響評估 (IMPACT)

- **破壞性變更**: 無 — 純檔案搬移 + 規則文件更新；`git mv` 保留 rename history，`git log --follow report/v1.0.0.md` 可追溯到原始 commit。
- **後續動作**: 下一份報告編號為 `report/v1.0.6.md`（即本份）；之後一律 `+1` 至 `v1.0.7.md`、`v1.0.8.md` ...。
