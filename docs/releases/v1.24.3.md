# 進度報告 v1.24.3：客戶說「不知道型號」時禁止 AI 重複追問

- **版本**: v1.24.3（前版：v1.24.2 → 本版升級類型：PATCH）
- **Commit**: `7db7f48` (2026-05-06 10:33)
- **分支**: fix/brand-switch-and-output-validation
- **作者**: Imding1211
- **影響模組**: agent/harness/output_validator.py、agent/prompts/system.md

## 變更摘要 (WHAT)

- `harness/output_validator.py`：新增快速路徑 0a — 偵測「用戶訊息含 不知道／不曉得／找不到／不清楚／沒有型號／沒型號」且「AI 回覆命中追問型號正則」的組合 → 觸發重試，並注入兩段流程 correction（要 LLM 看 `[前情提要]` 與 history 判斷該走「三個位置」還是「通用步驟」分支）。正則於 7 個樣本驗證行為正確：4 個追問句全 hit、3 個敘述句全 miss。
- `prompts/system.md` 鐵律 2：明文加入「絕對禁止重複追問型號」並列出具體禁止句型；明定「[前情提要] 已有不知道紀錄即進入第二分支」的判斷規則。

## 背景與動機 (WHY)

實際生產對話：
```
10:14 用戶: 請問dormakaba電子鎖設定，怎麼設定指紋
10:15 bot: 請問您是哪一個 Dormakaba 的型號呢？           ← 合理（首次問型號）
10:16 用戶: 我不知道                                      ← 第一次不知道
10:16 bot: 請問您的 Dormakaba 電子鎖是什麼型號呢？        ← ❌ 應給三個標示位置
10:16 用戶: 我不知道                                      ← 第二次不知道
10:16 bot: 沒關係，型號通常會標示在這幾個地方...           ← ❌ 應給通用步驟
10:29 用戶: 不知道                                        ← 第三次不知道
10:30 bot: 以下是 Dormakaba 多數型號的通用步驟...          ← 終於對了
```

system.md 鐵律 2 已寫了兩段流程，但沒明文禁止「重複追問型號」這個具體行為——LLM 自行解讀後產生漂移，把兩階段流程拖成四階段。需要：
1. **明確禁止句型**寫進 system prompt（讓 LLM 知道不能說什麼）
2. **deterministic safety net** 在輸出層攔截重試（即使 LLM 又漂移也救得回來）

## 影響評估 (IMPACT)

- **破壞性變更**：無。
- **行為變動**：
  - 出現「客戶不知道型號 + bot 追問型號」這種模式時，輸出驗證器強制重試，最多 `max_retries` 次（預設 1）。
  - 關鍵字清單收緊到只含高信度詞（不知道、不曉得、找不到、不清楚、沒有型號、沒型號），避免「不確定／沒有／查不到」等通用詞造成誤判。
  - 仍是 best-effort 防線：LLM 跳過「三個位置」直接給通用步驟（合併兩階段）的情況本檢查不阻擋，由 system prompt 自我約束。
- **與 v1.24.1 / v1.24.2 的關係**：三者都針對「品牌型號收集流程」的不同失誤點：
  - v1.24.1：facts 已有舊品牌時切到新品牌，LLM 沒主動 update_user_info。
  - v1.24.2：首訊已有品牌型號還被 Quick Reply 重複追問。
  - v1.24.3：客戶說不知道型號還被 LLM 重複追問。
