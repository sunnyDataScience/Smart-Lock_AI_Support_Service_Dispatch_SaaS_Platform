# 進度報告 v1.2.1：暫停 load_skill，全品牌統一走 product_info 流程驗證

- **版本**: v1.2.1（前版：v1.2.0 → 本版升級類型：PATCH）
- **Commit**: 即將提交
- **分支**: agent-improve
- **作者**: Imding1211
- **影響模組**: agent/agent.py、agent/harness/debounce.py、agent/prompts/system.md

## 變更摘要 (WHAT)

- `agent.py`：`tools=[...]` 移除 `load_skill`，全品牌統一只能使用 `load_product_info`
- `debounce.py`：移除舊 `[可用技能]` 注入分支，全部統一注入 `[可用產品資料]`，依 profile 狀態分 4 條路徑（A 齊備 / B 型號未知 / C 品牌無資料 / D 全未知）
- `system.md`：重寫「知識來源」段，移除全部 `load_skill`、`troubleshoot` skill、`dispatch-guide` skill 等舊技能引用，改為 `_common/troubleshoot`、`_common/dispatch` 等 product_info 名稱

## 背景與動機 (WHY)

v1.2.0 完成全品牌 product_info 後，要驗證新流程是否能獨立運作。同時保留 `load_skill` 會讓 LLM 在新舊兩套工具間搖擺，難以隔離問題。本次暫停 load_skill 強迫全部流量走新路徑，方便觀察與診斷。

`load_skill` 程式碼與註冊保留（imports + 函式定義不變），只是不再放進 `tools=[...]` 清單，回退單一行即可。

## 影響評估 (IMPACT)

- **行為變更**：所有品牌（含 Waferlock）強制走新流程
  - Dormakaba / Chatlock / 3E：載入實質 mega-doc 內容
  - Philips / Kaadas / Milre / AiLock：載入 zero-bronze stub（資料補充中提示）
  - Waferlock（無 product_info 檔）：只能載入 `_common/*` + 「無 Waferlock 詳細資料」免責聲明
  - 全未知（首次對話）：只能 `_common/*` + 主動詢問品牌
- **回退方式**：`agent.py` 把 `tools=[load_product_info, ...]` 改回 `tools=[load_skill, load_product_info, ...]` 即可恢復雙工具
- **debounce.py 不可逆設計**：舊 `[可用技能]` 注入分支已刪除，回退需手動還原該段邏輯（或先 git revert 此 commit）
- **舊 skills 完整保留**：`agent/skills/data/` 67 份 SKILL.md 與 `skills.tools.load_skill` 函式都還在，僅停用工具註冊
