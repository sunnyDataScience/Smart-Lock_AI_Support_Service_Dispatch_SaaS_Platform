### 2. 目標 KPI（0.8.2）

**檔案名稱建議:** `target_kpis.md`

以下是系統設計的目標 KPI，請確認是否合理：

| 指標 | 目標值 | 說明 |
| :--- | :--- | :--- |
| AI 回覆準確率 | >= 80% | L1 + L2 解決方案被客戶接受的比例 |
| 首次回應時間 | < 5 秒 | AI 收到訊息到首次回覆的時間 |
| 自助解決率 | >= 60% | 不需人工介入或技師到場即可解決的比例 |
| 技師接單時間 | < 30 分鐘 | 從派工到技師確認接單的時間 |
| ProblemCard 完整率 | >= 90% | AI 自動填充問題卡所有必填欄位的比例 |
| 知識庫命中率 | >= 70% | L1 案例匹配成功找到相關案例的比例 |
| 客戶滿意度 | >= 4.5 / 5 | 服務完成後客戶評分 |
| 系統可用性 | >= 99.5% | 年度系統正常運行時間 |

> **請根據你的業務經驗調整目標值**。過高或過低的目標都會影響系統設計決策。

### 3. 告警閾值（0.8.3）

**檔案名稱建議:** `alert_thresholds.md`

以下情況需要即時通知管理員：

| 告警項目 | 閾值 | 通知方式 |
| :--- | :--- | :--- |
| 未解決案件超時 | 案件開啟超過 2 小時未解決 | LINE 推播 + 管理後台 |
| 技師未接單超時 | 派工超過 30 分鐘無人接受 | LINE 推播 + 管理後台 |
| 負面情緒激增 | 連續 3 則對話偵測到負面情緒 | 即時 LINE 推播 |
| 系統錯誤率 | API 錯誤率 > 5% 持續 5 分鐘 | 開發團隊通知 |
| AI 低信心度 | 連續 5 次 AI 信心度 < 0.5 | 知識庫審查通知 |
| 知識庫命中率下降 | L1 命中率低於 50% 持續 1 天 | PM + 技師通知 |

> **請確認這些閾值是否符合你們的營運需求**。可以根據實際狀況調整。

## 常見問題

**Q: 我們目前根本沒在追蹤這些數據怎麼辦？**
A: 給出你的經驗估計值就好。系統上線後就能自動追蹤這些指標了。

**Q: 目標 KPI 感覺很高，做不到怎麼辦？**
A: KPI 是可以調整的。先給出你覺得合理的數值，上線後根據實際數據逐步調整。

**Q: 告警太多會不會很煩？**
A: 會根據實際營運情況調整閾值。初期可能會稍微敏感一點，穩定後再放寬。
