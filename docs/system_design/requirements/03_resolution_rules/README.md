# 03 — 三層解決機制規則

> **對口窗口:** 甲方 + PM
> **最晚交付日:** Phase 1 W4
> **用途:** 定義 AI 客服的三層解決流程（L1 案例匹配 → L2 RAG 推理 → L3 轉人工/派工）的具體規則與參數

---

## 為什麼這份很重要

三層解決機制是系統的核心引擎。
沒有明確的規則，AI 不知道什麼時候該自己回答、什麼時候該查手冊、什麼時候該轉人工。
這份文件就是把你腦中「什麼情況怎麼處理」的判斷寫成系統可以執行的邏輯。

---

## 你需要準備什麼

### 1. L1 案例庫匹配規則（0.3.1）

**檔案名稱建議:** `l1_matching_rules.md`

L1 是第一層解決機制：從知識庫中搜尋相似的歷史案例。

| 參數 | 建議值 | 說明 | 你的修改 |
| :--- | :--- | :--- | :--- |
| 相似度閾值 | >= 0.85 | 低於此值不回傳結果 | |
| Top-K 結果數 | 3 | 回傳最相似的前 K 筆案例 | |
| 品牌匹配權重 | 0.3 | 品牌相同時加權 | |
| 型號匹配權重 | 0.2 | 型號相同時加權 | |
| 症狀匹配權重 | 0.4 | 症狀描述的語意相似度 | |
| 問題分類匹配權重 | 0.1 | 分類相同時加權 | |

#### 需要確認的問題

1. **如果找到相似案例但品牌/型號不同，可以用嗎？**
   - 例如：Samsung 的指紋問題解法，適用於 Yale 嗎？
   - 建議：可以參考，但需標註「此解法來自不同型號，僅供參考」

2. **什麼情況下即使 L1 命中也不該直接回覆？**
   - 例如：涉及安全風險的操作（拆機、改線路）？
   - 例如：客戶情緒明顯不好？

---

### 2. L2 RAG 管線規則（0.3.2）

**檔案名稱建議:** `l2_rag_rules.md`

L2 是第二層解決機制：從產品手冊中檢索相關段落，交由 AI 生成回答。

| 參數 | 建議值 | 說明 | 你的修改 |
| :--- | :--- | :--- | :--- |
| 手冊段落檢索數量 | 5 | 從手冊中取最相關的 5 個段落 | |
| 段落最大長度 | 500 字 | 每個段落的最大字數 | |
| LLM 溫度 | 0.3 | 較低溫度 = 更保守、更確定的回答 | |
| 最大回覆長度 | 300 字 | AI 回覆不超過此字數 | |

#### AI 回覆的護欄規則

請確認以下限制是否合理：

| 規則 | 說明 |
| :--- | :--- |
| **必須引用來源** | 每個回覆必須標註「參考來源：{手冊名稱} 第X頁」 |
| **禁止編造步驟** | 如果手冊中沒有相關內容，不可自行編造解決步驟 |
| **禁止安全風險操作** | 不可指導客戶進行拆機、改電路等可能造成危險的操作 |
| **禁止保固承諾** | 不可代替甲方承諾保固範圍或免費維修 |
| **語氣要求** | 回覆需友善、專業，避免過度技術化的用詞 |
| **不確定時要承認** | 如果無法確定答案，應明確告知並建議轉人工 |

> **請補充其他你認為 AI 不應該做的事情**。

---

### 3. L3 轉派規則（0.3.3）

**檔案名稱建議:** `l3_escalation_rules.md`

L3 是第三層：當 AI 無法解決問題時，轉交人工處理或建立派工單。

#### 自動轉人工的觸發條件

| 條件 | 說明 | 優先級 |
| :--- | :--- | :--- |
| L1 + L2 均未命中 | 知識庫和手冊都找不到相關資訊 | 高 |
| 客戶主動要求 | 客戶明確表示「我要找人工客服」或類似意圖 | 最高 |
| 負面情緒偵測 | 連續 2 則訊息偵測到憤怒/不滿情緒 | 高 |
| 危險操作判斷 | 問題可能涉及安全風險（拆機、電路等） | 最高 |
| 多輪未解決 | 同一問題來回超過 5 輪對話仍未解決 | 中 |
| 保固爭議 | 客戶對保固範圍有異議 | 高 |
| 報價需求 | 客戶要求到場維修報價 | 中（V2.0 可自動報價） |

#### 需要確認的問題

1. **轉人工後，人工客服從哪裡接手？**
   - LINE 對話直接轉接？還是另開一個對話？
   - 人工客服能看到之前的 AI 對話紀錄嗎？

2. **營業時間外收到的轉人工請求怎麼處理？**
   - 自動回覆「目前非營業時間，我們會在明天上午回覆您」？
   - 還是有人 24 小時值班？

3. **什麼情況下應該直接建立派工單（V2.0）？**
   - 例如：客戶被鎖在門外 → 緊急派工？

### 4. 解決信心度評分（0.3.4）

**檔案名稱建議:** `confidence_scoring.md`

AI 每次回覆時都會計算一個信心度分數，決定是否需要人工審核：

| 信心度範圍 | 處理方式 | 說明 |
| :--- | :--- | :--- |
| >= 0.85 | 自動回覆 | AI 有高度信心，直接回覆客戶 |
| 0.60 - 0.84 | 自動回覆 + 標記 | 回覆客戶，但標記為待人工確認 |
| 0.40 - 0.59 | 人工審核後回覆 | 先由人工確認再回覆 |
| < 0.40 | 直接轉人工 | 信心度太低，不嘗試回覆 |

#### 需要確認的問題

- 以上閾值是否合理？
- 初期上線時，是否需要更保守（例如全部先經過人工審核）？
- 穩定後再逐步放寬自動回覆的門檻？
