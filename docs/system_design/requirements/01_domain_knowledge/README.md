> **對口窗口:** 甲方資深技師（熟悉電子鎖產品與維修實務的人）
> **協作者:** 產品經理

## 你需要準備什麼

### 1. 產品目錄（0.1.1）

**檔案名稱建議:** `product_catalog.xlsx`

請提供所有服務品牌與型號的完整清單，包含：

| 欄位 | 說明 | 範例 |
| :--- | :--- | :--- |
| 品牌 | 電子鎖品牌 | Samsung, Yale, Gateman, Milre, 凱特曼, 美樂 |
| 型號 | 具體型號 | SHP-DP609, YDM-4109, A330 |
| 鎖種類型 | 指紋/密碼/卡片/人臉辨識/複合式 | 指紋 + 密碼 + 卡片 |
| 適用門類型 | 適用的門種類 | 鋁門、木門、鐵門、大門、玻璃門 |
| 常見故障類型 | 該型號最常出現的問題 | 電池耗盡、指紋辨識失靈、WiFi 斷線 |
| 安裝需求 | 特殊安裝條件 | 門厚度 38-80mm、需預留走線孔 |
| 是否仍在售 | 現售 / 已停產但仍有維修需求 | 現售 |

> **至少需要**：完整的品牌與型號清單，含每個型號的常見故障類型。已停產但仍有維修需求的型號也請列出。

### 2. 客戶分群定義（0.1.2）

**檔案名稱建議:** `customer_segments.md`

請回答以下問題：

- 客戶類型怎麼分？（例如：住宅用戶 / 商業用戶 / 社區大樓）
- 服務類型怎麼分？（例如：新裝 / 維修 / 換鎖 / 加裝）
- 保固內 vs 保固外的判斷標準是什麼？保固期多長？
- 有沒有「優先客戶」或「VIP 客戶」的概念？怎麼判定？
- 什麼情況會建議客戶直接找原廠而非你們？

> **不需要理想化的分群**。我要的是你們「現在實際在用」的分法，即使很粗糙也沒關係。

### 3. 業務術語表（0.1.3）

**檔案名稱建議:** `glossary.md`

請列出所有在電子鎖維修領域日常使用、但外人聽不懂的術語：

| 術語 | 正式定義 | 使用情境 |
| :--- | :--- | :--- |
| ProblemCard（問題卡） | 一次客服對話的結構化問題描述 | AI 問診時建立，包含品牌、型號、症狀、位置等 |
| Three-Layer Resolution（三層解決機制） | L1 案例匹配 → L2 AI 推理 → L3 轉人工 | 系統核心解決流程 |
| CaseEntry（案例條目） | 知識庫中的一筆維修案例記錄 | 含問題描述、解決步驟、品牌型號 |
| ManualChunk（手冊段落） | PDF 手冊解析後的文本段落 | 用於 RAG 檢索 |
| SOPDraft（SOP 草稿） | 從成功對話自動產生的標準作業程序 | 需經管理員審核後才能入庫 |
| WorkOrder（派工單） | 到場服務的工單 | V2.0，含問題描述、客戶資訊、指派技師 |
| Technician（技師） | 已登錄的維修技師 | 含技能、服務地區、評分 |
| PriceRule（計價規則） | 品牌 x 鎖型 x 難度的費用規則 | V2.0 報價引擎使用 |
| （其他行業術語...） | | |

> **越完整越好**。開發團隊看到不認識的詞會猜，猜錯了做出來的東西就不對。

### 4. 現行作業流程紀錄（0.1.4）

**檔案名稱建議:** `current_workflow.md` 或螢幕錄影

這是最重要的一項。請描述（或錄影示範）你們目前維修服務的完整流程：

#### A. 接單流程
- 客戶目前怎麼聯繫你們報修？（LINE 訊息？電話？其他？）
- 收到報修訊息後，誰負責處理？怎麼判斷問題？
- 你怎麼問客戶問題來診斷故障？通常要問幾個問題？
- 有沒有標準的問題清單？還是靠經驗？

#### B. 診斷與報價流程
- 判斷完問題後，怎麼報價？有沒有價目表？
- 如何判斷需要到場維修還是遠端指導就能解決？
- 哪些問題可以透過電話/LINE 指導客戶自行排除？

#### C. 派工與維修流程
- 怎麼決定派哪個技師？（就近？技能？排班？）
- 技師怎麼接收派工通知？（電話？LINE 群組？）
- 維修完成後怎麼回報？怎麼收費？
- 維修紀錄記在哪裡？（Excel？紙本？LINE 對話？）

#### D. 帳務流程
- 怎麼跟客戶收費？（現場收？匯款？）
- 怎麼跟技師結算？（月結？案件結？）
- 帳務紀錄用什麼工具？

> **最好的方式**：請錄一段 30 分鐘的影片，邊操作邊講解。
> 沒時間錄影的話，用文字寫也可以，但請盡量具體。
> 「不好意思現在很亂」也沒關係——我們就是要改善這個亂。

## 常見問題

**Q: 某些型號已經停產了，還要列嗎？**
A: 要。只要還有客戶在用、還會報修，就要列出來。

**Q: 我們現在的流程很亂，沒有標準做法怎麼辦？**
A: 這正常。請描述你自己（或你認為做得最好的那個人）的做法就好。

**Q: 有些術語我自己也說不清楚定義？**
A: 寫下你理解的版本，訪談時我們一起釐清。
