### 2. 診斷決策樹（0.4.2）

**檔案名稱建議:** `diagnosis_decision_trees.md` 或流程圖

針對 Top 10 最常見故障，請畫出診斷決策樹：

#### 範例：指紋辨識失敗決策樹

```
客戶：指紋辨識失敗
  │
  ├─ Q1: 是所有手指都失敗，還是特定手指？
  │   ├─ 所有手指 → Q2
  │   └─ 特定手指 → 建議重新登錄該手指指紋
  │
  ├─ Q2: 螢幕有沒有顯示任何訊息或閃燈？
  │   ├─ 低電量圖示 → 請先更換電池
  │   ├─ 錯誤代碼 → 查對應錯誤碼表
  │   └─ 無顯示 → Q3
  │
  ├─ Q3: 請用乾布擦拭指紋感應器後再試
  │   ├─ 成功 → 結案（感應器髒污）
  │   └─ 仍失敗 → Q4
  │
  └─ Q4: 請嘗試用密碼或卡片開鎖
      ├─ 其他方式正常 → 感應器可能故障，建議到場檢修
      └─ 其他方式也失敗 → 主板可能故障，建議到場檢修
```

> **不需要畫完美的圖**。用文字描述「你怎麼問、怎麼判斷」就好，我們會轉成系統可用的格式。

### 已確認的故障分類原則

| 類別 | 定義 | 處理方式 | 範例 |
|------|------|---------|------|
| **設定問題（不需到場）** | 可透過遠端指導解決 | AI 直接教學或引導設定 | 指紋重設、密碼修改、門關緊一點就好 |
| **真正故障（需到場）** | 硬體損壞或系統異常 | 進入工單系統由真人評估派工 | 鎖匣壞掉、整個當機死機、打不開門、上鎖不了 |

### 已確認的診斷流程

```
客戶報修
  │
  ├─ AI 先回覆（說明書查詢、設定教學）
  │   ├─ 解決 → 結案（約 70-80% 問題）
  │   └─ 未解決 → 引導客戶拍攝影片
  │
  ├─ 客戶傳影片
  │   └─ 真人客服看影片判斷
  │       ├─ 設定問題 → 繼續遠端指導
  │       └─ 硬體故障 → 確認零件（鎖匣/IC板）→ 報價 → 客戶確認 → 派工
  │
  └─ 緊急程度判斷
      ├─ 無法上鎖 / 無法開門 → 原則當天到場
      └─ 卡片不能感應等非緊急 → 可排隊安排時間
```

### 已確認的零件故障範例

- **鎖匣壞掉** → 可能是主機板 IC 板故障 → 需準備鎖匣 + IC 板
- **整個當機死機** → 需到場檢修
- **打不開門 / 上鎖不了** → 屬緊急狀況，當天到場

## 現行系統已實作內容

> 來源：`agent/skills/data/system/troubleshoot/` 中 9 個 ts-* SKILL.md

### 已實作的 8 大故障分類與嚴重度（0.4.1 大幅完成）

| 故障分類 | Skill | 嚴重度 | 可電話解決 | 需派工場景 |
|---------|-------|--------|-----------|-----------|
| **門卡死無法開啟** | `ts-door-stuck` | 5（最高） | 推門法（有馬達聲時） | 無馬達聲+鑰匙也開不了 |
| **自動上鎖失效** | `ts-auto-lock` | — | 受口片輕微偏移可自行微調 | 感測器/鎖匣故障 |
| **異常警報聲響** | `ts-alarm` | — | 更換正確電池、清除錯誤 | 馬達故障（紅閃 4 下） |
| **驗證失敗** | `ts-verification` | 3 | 清潔感應器、重新登錄、等待鎖定解除 | 所有方式+鑰匙均失敗 |
| **鎖舌問題** | `ts-lock-tongue` | — | 受口片 DIY 微調（有工具時） | 內部鎖舌故障、嚴重偏位 |
| **門扇反弓** | `ts-door-rebound` | — | 無（非電子鎖故障） | 所有案例均需派工 |
| **異常耗電** | `ts-power-drain` | — | 更換松下鹼性電池、分離 2.4G/5G | IC 板/馬達嫌疑 |
| **雙重認證誤觸** | `ts-dual-auth` | — | 引導關閉（品牌專屬步驟） | 管理員存取不可用 |

### 已實作的診斷決策邏輯（0.4.2 部分完成）

#### 門卡死（ts-door-stuck）— 嚴重度最高

```
客戶：門打不開
  │
  ├─ 聽馬達聲？
  │   ├─ 有馬達聲 → 推門法（根據門向推緊門板後解鎖）
  │   │   ├─ 成功 → 建議派工調整受口片（防復發）
  │   │   └─ 失敗 → Dormakaba？→ 擺動鎖舌特殊處理
  │   │
  │   └─ 無馬達聲 → 檢查異物/門下沉/反弓
  │       ├─ 開門狀態測試鎖舌功能
  │       │   ├─ 鎖舌正常 → 受口片/門框問題
  │       │   └─ 鎖舌不動 → 鎖匣故障 → 需派工
  │       └─ 完全無反應 → 緊急方案
  │           ├─ 機械鑰匙（底部蓋子）
  │           ├─ Type-C 緊急供電（Chainlock AI99/A90）
  │           └─ 緊急派工
```

#### 異常耗電（ts-power-drain）

```
客戶：電池很快沒電
  │
  ├─ Step 1：確認電池品牌
  │   ├─ 非松下鹼性 → 更換正確電池（最常見原因）
  │   └─ 已用松下 → Step 2
  │
  ├─ Step 2：確認 WiFi 設定
  │   ├─ 2.4G/5G 合併 → 分離頻段
  │   ├─ 使用 WiFi 6/7/8 → 換入門級 2.4G 路由器
  │   └─ WiFi 正常 → Step 3
  │
  └─ Step 3：確認機械阻力
      ├─ 門框/氣密條干擾 → 調整
      └─ 無外部原因 → IC 板/馬達嫌疑 → 派工
```

### 已實作的品牌專屬問題（0.4.3 部分完成）

#### Dormakaba 專屬問題（重點品牌，多處特殊處理）

| 問題 | 詳情 | 來源 skill |
|------|------|-----------|
| 擺動式鎖舌設計 | 推門時需先推緊門板再解鎖（與其他品牌完全不同） | `ts-door-stuck` |
| 短按註冊鍵 | 進入 Registration Mode 需短按（非長按），長按會觸發其他功能 | `ss-dormakaba` |
| 面板顯示「6」 | 表示用戶未登錄（非錯誤碼） | `ss-dormakaba`、`ts-verification` |
| 紅燈閃 4 下 | 馬達故障，需派工 | `ts-alarm` |
| 長嗶 3 秒 | 關鎖失敗 | `ts-alarm` |
| 短嗶 3 下 | 低電量警告 | `ts-alarm` |
| 連嗶 10 下 | 防盜鎖定（連續 5 次密碼錯誤） | `ts-alarm` |
| 閃 2 下 | 密碼錯誤 | `ss-dormakaba` |
| 初始化需派工 | 客戶無法自行恢復出廠，需技師到場並收費 | `ss-dormakaba` |
| 管理員密碼 vs 一般密碼 | 不同權限層級，設定功能需管理員密碼 | `ss-dormakaba` |
| 註冊模式不鎖定 | 密碼錯誤不會像正常模式一樣鎖定 | `ss-dormakaba` |
