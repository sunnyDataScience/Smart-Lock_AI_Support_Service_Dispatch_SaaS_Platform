### 4. 現行作業流程紀錄（0.1.4）

**檔案名稱建議:** `current_workflow.md` 或螢幕錄影

這是最重要的一項。請描述（或錄影示範）你們目前維修服務的完整流程：

#### A. 接單流程
- 客戶目前怎麼聯繫你們報修？（LINE 訊息？電話？其他？）
- 收到報修訊息後，誰負責處理？怎麼判斷問題？
- 你怎麼問客戶問題來診斷故障？通常要問幾個問題？
- 有沒有標準的問題清單？還是靠經驗？

#### B. 診斷與報價流程
- 判斷完問題後，怎麼報價？有沒有價目表？
- 如何判斷需要到場維修還是遠端指導就能解決？
- 哪些問題可以透過電話/LINE 指導客戶自行排除？

#### C. 派工與維修流程
- 怎麼決定派哪個技師？（就近？技能？排班？）
- 技師怎麼接收派工通知？（電話？LINE 群組？）
- 維修完成後怎麼回報？怎麼收費？
- 維修紀錄記在哪裡？（Excel？紙本？LINE 對話？）

#### D. 帳務流程
- 怎麼跟客戶收費？（現場收？匯款？）
- 怎麼跟技師結算？（月結？案件結？）
- 帳務紀錄用什麼工具？

> **最好的方式**：請錄一段 30 分鐘的影片，邊操作邊講解。
> 沒時間錄影的話，用文字寫也可以，但請盡量具體。
> 「不好意思現在很亂」也沒關係——我們就是要改善這個亂。

## 常見問題

**Q: 某些型號已經停產了，還要列嗎？**
A: 要。只要還有客戶在用、還會報修，就要列出來。

**Q: 我們現在的流程很亂，沒有標準做法怎麼辦？**
A: 這正常。請描述你自己（或你認為做得最好的那個人）的做法就好。

**Q: 有些術語我自己也說不清楚定義？**
A: 寫下你理解的版本，訪談時我們一起釐清。

#### 鎖種與開鎖方式

**開門方式分類：**
- 推拉式（解鎖後直接推拉門）
- 把手式（解鎖後需下壓把手）

**7 種解鎖方式：** 指紋（0.3 秒辨識）、密碼（6-12 位）、NFC 卡片、實體鑰匙、藍牙、遠端 APP、人臉辨識、掌靜脈（15-30cm 感應）

**鎖匣類型：**
- 全自動鎖匣：有鎖舌感應器，關門自動上鎖
- 半自動鎖匣：無感應器，需手動上提把手，3-5 秒後自動上鎖

#### 鎖體結構

三大核心部件：前部機（室外機）+ 鎖匣（門體內部核心機械）+ 後部機（室內機）
配套組件：受口片（門框上的銀色金屬片，供鎖舌卡入）

#### 技術規範

| 項目 | 規範 |
|------|------|
| 電池 | 8 顆 AA 鹼性電池（推薦 Panasonic），續航 8 個月-1 年 |
| 充電 | 5V1A 或 5V2A（禁止快充），Type-C 轉 Type-A |
| WiFi | 僅支援 2.4G（不支援 5G），不建議 WiFi 6/7/8 路由器 |
| 側板規格 | 歐規、美規、義大利規、日規、韓規（無台灣本地標準） |
| 門向判斷 | 人站門外看鉸鏈位置：右側=右開、左側=左開 |

### 已掌握的業務術語（0.1.3 部分完成）

| 術語 | 定義 | 使用情境 |
|------|------|---------|
| 自動鎖 / 半自動鎖 | 自動鎖有感應器自動上鎖；半自動需手動提把手後馬達上鎖 | 故障排除時判斷鎖匣類型 |

| 推門法 | 先推緊門板再解鎖開門的技巧 | Dormakaba 門卡死排除 |
| load_skill | AI Agent 載入特定 SOP 的工具呼叫 | 系統內部技能路由 |
| transfer_to_human | AI Agent 轉接真人客服的工具呼叫 | L3 轉派觸發 |
