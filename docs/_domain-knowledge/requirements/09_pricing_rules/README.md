# 09 — 計價規則定義

> **對口窗口:** 甲方 + PM
> **最晚交付日:** Phase 5 W19
> **用途:** 建立報價引擎的核心規則，讓系統能根據品牌、鎖型、工項自動產生一致的報價

---

## 為什麼這份很重要

報價引擎是消費者「要不要派工」的關鍵決策依據。報價不透明或不一致，消費者不接受派工；結算規則不清楚，技師不信任平台。沒有結構化的計價規則，報價引擎就是空殼。

## 0.6.1 標準報價矩陣

**檔案名稱:** `pricing_matrix.xlsx`

**格式:** 品牌 × 鎖型 × 工項 三維報價表


| 品牌      | 鎖型          | 工項   | 基礎工資 | 標準材料費 | 總價  |
| ------- | ----------- | ---- | ---- | ----- | --- |
| Samsung | DP609 指紋鎖   | 安裝   | $__  | $__   | $__ |
| Samsung | DP609 指紋鎖   | 更換面板 | $__  | $__   | $__ |
| Yale    | YDM7116 密碼鎖 | 安裝   | $__  | $__   | $__ |

| Gateman | WF-20 推拉鎖   | 安裝   | $__  | $__   | $__ |
| ...     | ...         | ...  | ...  | ...   | ... |


**要求：**

- 至少涵蓋 **5 個品牌 × 3 種鎖型 × 5 種工項 = 75 個組合**
- 每個組合的工資與材料費**分開列示**
- 包含所有目前在服務的品牌/型號

**常見工項參考：**

- 新品安裝（含基本配線）
- 維修（電路板/馬達/鎖舌更換）
- 換電池/電池座
- 更換面板
- 密碼/指紋重設（需到場）
- 門扇加工（挖孔/擴孔）

## 0.6.2 特殊加價規則

**檔案名稱:** `surcharge_rules.xlsx`


| 規則名稱 | 觸發條件        | 加價方式 | 金額/比例   | 可疊加 |
| ---- | ----------- | ---- | ------- | --- |
| 夜間加價 | 22:00–06:00 | 百分比  | +30%    | 是   |
| 假日加價 | 國定假日 / 週日   | 百分比  | +50%    | 是   |
| 遠程加價 | 距離 > 30km   | 固定金額 | +$500   | 是   |
| 高樓加價 | > 5F 且無電梯   | 每層固定 | +$200/層 | 是   |
| 急件加價 | 要求 4 小時內到場  | 百分比  | +__%    | 是   |
| 門扇加工 | 需現場挖孔/擴孔    | 固定金額 | +$__    | 是   |


**要求：**

- 至少定義 **3 條加價規則**
- 每條規則包含：觸發條件（系統可判斷）、加價方式（固定/百分比）、是否可與其他規則疊加
- 多條規則同時觸發時的**優先順序**

**需要確認的問題：**

1. 夜間/假日的定義是否與勞基法一致？
2. 遠程距離起算點是公司地址還是技師所在地？
3. 急件的定義？（4 小時？2 小時？當天？）

## 0.6.3 結算與墊款規則

**檔案名稱:** `settlement_rules.md`

**需要定義的項目：**

### A. 技師墊款流程

- 技師在什麼情況下需要墊付？（材料費？交通費？）
- 墊付後如何申請核銷？（完工報告附發票照片？）
- 審核標準是什麼？（金額上限？需要主管核准？）

### B. 結算週期

- 月結還是雙週結？
- 結算日是每月幾號？
- 從完工到入帳的天數？

### C. 結算明細

- 結算報表需要包含哪些欄位？
- 是否需要符合特定會計軟體匯入格式？（如鼎新、SAP）
- 憑證格式需求？（借方/貸方科目？）

### D. 爭議處理

- 技師對報價/結算有異議時的處理流程？
- 消費者拒付或部分支付時的處理規則？

## 允收標準

- 報價矩陣涵蓋 ≥ 75 個品牌×鎖型×工項組合
- 每個組合的工資與材料費分開列示
- ≥ 3 條特殊加價規則，含觸發條件與加價方式
- 多規則疊加的優先順序已定義
- 結算週期與墊款核銷流程經甲方與技師代表共同確認
- 結算報表格式經甲方會計確認

## 20260411 會議已確認事項

### 已確認的費用結構

| 費用類別 | 定價方式 | 說明 |
|---------|---------|------|
| 師傅出勤費 | 固定 $1,000 | 不分品牌，行情價 |
| 工資（DRAM 更換、拆門等） | 固定行情價 | 各品牌差異不大，依行情表執行 |
| 車馬費 | 固定 | 與工資同為固定成本 |
| IC 板/鎖匣等零件 | 各品牌不同 | 由公司端對接品牌商填報，非固定價 |

### 已確認的加價規則

| 規則 | 條件 | 金額 | 狀態 |
|------|------|------|------|
| 偏遠地區加價 | 依偏遠地區報價表 | 上限 $500 | ✅ 已有報價表（甲方已提供） |

### 已確認的工項清單

- DRAM 更換
- 拆門
- IC 板更換
- 鎖匣更換
- 新品安裝（含基本配線）

### 已確認的議價政策

- **客服端直接拒絕客戶的議價要求**，不提供折扣
- 原因：各品牌商定義不同，避免與客戶進行價格拉鋸
- AI 系統不處理任何報價/議價相關對話

### 已確認的爭議處理

| 情境 | 處理方式 |
|------|---------|
| 維修後仍故障 / 未修好 | 下次免收車馬費，或直接更換整台機器 |
| 客戶要求折扣 / 拒付車馬費 | 客服端直接擋掉，不予協商 |
| 高爭議案件 | 由專人接手處理，不交 AI 判斷 |

### 已確認的報價流程

```
客戶報修 → AI 引導（影片等資料收集）
  → 真人客服整理影片 → 評估故障原因
  → 確認所需零件（如鎖匣 + IC 板）
  → 出報價單（零件費 + 工資 + 車馬費）
  → 客戶確認要修 → 才啟動派工
```

### 待確認事項

- 完整的品牌×鎖型×工項報價矩陣（目標 ≥75 組合）
- 夜間加價、假日加價、急件加價的具體數字
- 結算週期（月結 or 雙週結）與入帳天數
- 技師墊款流程與核銷標準

### 已實作的報價邏輯

```
一般案件報價 = 工資 + 車馬費 + 零件費
```

- **工資、車馬費**：固定行情價（各品牌差異不大）
- **零件費（IC 板/鎖匣等）**：各品牌不同，由公司端對接品牌商後填報
- **建案/保固期案件**：⚠️ 禁止 AI 報價！涉及完工日與點交日爭議，需查詢建案資料庫，轉接人工客服

### 已實作的金流模式

- **現狀**：師傅收現金 → 公司月結 → 扣材料費後撥款
- **未來規劃**：串接虛擬帳戶

### 已實作的保固規則

| 銷售模式 | 保固範圍 | 說明 |
|---------|---------|------|
| 本店銷售 + 安裝 | 整機保固（產品 + 安裝品質） | 保固期依品牌而異 |
| 代工服務（客戶自備鎖） | 僅保障安裝品質 | 產品故障洽原購買商 |
| 不在保固範圍 | — | 人為損壞、自行拆裝、遺失鑰匙/卡片、電池耗盡、正常耗損 |

### 待收集事項（仍需甲方提供）

- 各工項的具體工資金額
- 各品牌零件的具體價格（IC 板、鎖匣、馬達等）
- 夜間/假日/急件的加價比例或金額
- Dormakaba 初始化的服務費金額
- 結算週期與入帳天數
