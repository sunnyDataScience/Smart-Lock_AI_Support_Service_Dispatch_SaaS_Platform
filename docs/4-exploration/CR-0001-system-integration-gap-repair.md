# CR-0001: System Integration Gap Repair

> **Tier**: 4-exploration → Change Impact Analysis (per-change ephemeral; archive after implementation)
> **Generated by**: Linus-style audit driven by `AI鎖匠聊天機器人系統開發藍圖_v2.xlsx` cross-check
> **Mandated by**: `.claude/rules/change-governance.md`

## 1. Change Statement

**As-is**: 多處關鍵 audit / persistence / retry 機制是 **no-op stub 或半實作**，導致流程斷鍊與「fail-soft 偽裝成正常」。具體：
- `log_tool_invocation` / `log_escalation` / `log_safety_gate` 三個 audit 方法在 postgres + sqlite 實作都是 `pass`，**所有 tool 呼叫、轉真人、安全閘事件靜默丟失**。
- `agent_outbox` 表存在且 `admin_api.py` 失敗時會寫入，**但沒有 consumer worker**，PC 失敗永遠卡 outbox 撈不出來重試。
- `transfer_to_human` 工具組好 form 直接傳 LINE 訊息，**handoff form 內容沒落地**，客服 dashboard 看不到聯絡資訊快照。
- `data_corrections` 寫進 DB 標 `status='pending'`，**沒有 admin API / Dashboard 消費 pending queue**。
- `[turn_cycle].persist=True` 硬編碼在 `turn_cycle_runner.py`，**無法 config 層關閉**，誤設 enabled=true 會立刻爆表。
- conversation ↔ ProblemCard **反向 FK 缺**；admin API 可按 conversation_id 篩 PC，conversations 表沒 `last_problem_card_id`。
- LINE webhook **無 idempotency key 保護**，業務邏輯失敗回 5xx 觸發 LINE 重送會產生重複對話記錄。
- agent 層**完全沒有 tenant_id 概念**，多租戶部署會洩漏 facts 跨租戶（API 端有檢查 X-Tenant-ID，agent 端沒做對稱）。
- memory compression 把舊訊息 `RemoveMessage` 後**沒寫入 audit / cold storage**，超過壓縮窗的訊息無法重播，藍圖 sheet 11 Archival 「完整可重播 ≥1 年」是空頭支票。
- profile_updater 抽 facts 失敗 / multimodal 下載失敗**無專用 audit 事件**。

**To-be**: 補齊三件組（**Outbox + Audit + Review Queue**）治理骨架；所有 fail-soft 路徑都有對應的 durable storage 與 consumer；agent 層加入對稱的 tenant_id；memory compression 落地 raw backup；LINE webhook 加入 idempotency 防護。

**Driver**: 
1. 對藍圖 v2 sheet 04 (Gate G5-G7) / sheet 08 (風險治理) / sheet 11 (Memory Archival) 做反向稽核，發現實作端與規格端對不上。
2. 藍圖 v2 sheet 02 標 A03/A04/A05/A06/A09/A12 為「**阻擋 PRD**」的模組，這些 gap 不修就出不了下一個 PRD。
3. Goal-mode：使用者明確要求「將所有洞都修好 過程不要忘記更新文件 避免 ai slop」。

## 10. Risks & Rollback

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| 補完 audit stub 後 audit_log 寫量爆增 | High | Medium | INSERT 在 try/except 包住、fire-and-forget；DB 加 partition by month 對 audit_log；觀察 1 週看是否需要 partition |
| outbox worker 與 agent process 共生命週期 → 部署滾動時可能有 entries 沒撈到 | Medium | Low | 寫 entries 永遠落地，worker 重啟後會撈舊 entries；max_attempts=5 + alert |
| tenant_id 加欄位 → 既有 read query 需要全部加 WHERE tenant_id | Medium | Medium | 用 `DEFAULT 'default'` + application-side ContextVar 帶；存在 query 不加 WHERE 仍能跑（all rows tenant_id='default'）；新 query 必加 |
| LINE webhook idempotency 加查 DB → 入口 latency +5-10ms | Low | Low | LINE 1 秒回應限制充裕；webhook_idempotency 表 primary key lookup O(1) |
| memory raw backup 每次壓縮 dump → audit_log 寫量再增 | Medium | Low | event_type='memory_compressed' 用 partition 隔離；壓縮頻率本來就低（>12 msg 才觸發） |
| profile_updater 失敗 audit → 噪音多 | Low | Low | 只在 retry 全失敗才寫，常見抽不到不寫 |

**Rollback plan**: 每個 Phase 獨立 commit；任何 Phase 出包可單獨 revert。Phase A 純 code 無 schema 可秒 rollback；Phase B/C/D 的 schema migration 都用 `IF NOT EXISTS` + DEFAULT NULL，反向兼容；webhook_idempotency 表可 drop 不影響業務（最壞情況回到「無 idempotency 保護」現狀）。
