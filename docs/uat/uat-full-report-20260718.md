## 🔴 P1 — 功能壞死/流程斷頭(4)

### P1-1 電話進線無法在 UI 手建問題卡——核心開單流程斷頭
- **角色/頁**:品牌客服/`/problem-cards`、`/admin/cases`、對話詳情
- **現象**:問題卡列表無「新增」鈕;進線案件代客建案只建 Case、無接續建卡動線;唯一建卡入口藏在「對話詳情且該對話 0 張卡」時才顯示。客服接**電話**報修(非 LINE)完全無路可走
- **佐證**:來源篩選明明有「客服手建」選項=此情境是預期功能;API `ProblemCardCreateRequest` 存在,測試被迫用 API 直建才能繼續流程
- **判讀**:UI 缺口(後端能力在)。補「手建問題卡」入口屬 user flow 變更 → 需 CIA+裁決入口放哪(問題卡列表?進線案件接續?)

### P1-2 急件開單後仍被報價 gate 擋派工,UI 無 override 途徑——急件流程卡死
- **角色/頁**:品牌客服/工單詳情指派 Modal
- **現象**:急件 carve-out 開單成功(系統自建補審佔位報價)→ 指派技師 → 409「派工前須有已同意的報價…主管可帶 override_reason 強制派工」;**前端指派請求根本沒有 override_reason 可帶**(API query param 實測 admin 帶參可過)
- **判讀**:前端缺欄位。指派 Modal 對 409 補「強制派工原因」欄(admin only)即通;佔位報價是否該視同「已同意」屬規則面,可一併裁決

### P1-3 師傅上線/離線切換完全壞掉(CORS/ERR_FAILED)
- **角色/頁**:師傅/`/home` 上線切換鈕
- **現象**:PATCH availability 瀏覽器端一律 `net::ERR_FAILED`+CORS error,顯示「連線失敗」;**同一 PATCH 用 curl(含 preflight)正常、從對帳頁原生 fetch 也通(401)**——疑 `/home` 請求路徑(帶 auth header 或經 sw.js)才炸
- **判讀**:需查根因(懷疑與 PWA service worker 或 preflight 組合有關——我本週交付的 SW 是嫌疑人之一,誠實列入)

### P1-4 已指派的工單仍出現在案件池、可被再接單,且地址未遮蔽
- **角色/頁**:師傅/`/pool`、`/pool/{id}`
- **現象**:工單已指派給林師傅且已回報到場,案件池仍列「可接」含完整地址「台北市信義區測試路1號5樓」+可點的「接受工單」鈕(未點,避免弄壞狀態)
- **判讀**:pool 查詢沒濾已指派單(後端 filter bug)+接單前隱私遮蔽在此路徑失效(先前 UAT 裁決「接單前不顯示客戶資訊」被繞過)
