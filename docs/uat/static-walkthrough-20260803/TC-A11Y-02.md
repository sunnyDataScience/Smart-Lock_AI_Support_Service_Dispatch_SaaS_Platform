## Event Storming

本案例為前端呈現與無障礙屬性，無 domain event。改列四個面向的檢核點與其可判定性：

| 面向 | 檢核點 | 靜態可判定的部分 | 需執行期的部分 |
|---|---|---|---|
| 對比 | CSS 變數值 | token 值與其對比可計算（步驟 1） | 元件內硬編顏色、疊圖、半透明實際渲染結果 |
| 觸控目標 | 元素尺寸 | class 中的顯式 `min-h-[44px]` / `h-[44px]` | padding + line-height 推得的實際 box 尺寸 |
| 鍵盤 | focus ring、tab 順序、Escape | `:focus-visible` 規則、`.skip-link`、原生控件 vs `div+onClick`、`onKeyDown` 命中 | 實際 tab 順序、焦點是否被 modal 困住 |
| aria-live | live region 屬性 | `aria-live` / `role="alert"` / `role="status"` 的存在與位置 | 螢幕閱讀器是否真的播報 |

## 逐層走查

### 步驟 1 — 對比：既有 token 層檢核與離線重算

`web/tech-portal/tests/unit/themeContrast.test.ts` 是 repo 內唯一的對比檢核，其檔頭（`:1-14`）自述來由與邊界：

```ts
/**
 * 師傅站主題對比度回歸測試（2026-07-31）。
 *
 * 背景：業主回報「師傅站卡片背景色跟文字顏色太像」。用瀏覽器逐節點量測後發現
 * 深色模式多處低於 WCAG AA——最嚴重的是 teal 文字鋪在 teal 底上只有 2.97:1。
 *
 * 為什麼寫成「解析 globals.css 算對比」而不是端到端 a11y 測試：
 *   - 這類劣化的**根因幾乎都在 token 定義**（某人調了一個 --primary 就全站受影響），
 *     在 token 層擋住最便宜也最準。
 *   - 不需要瀏覽器 / 不需要跑起服務，任何人改 globals.css 都會立刻被擋。
 *
 * 它擋不住什麼（誠實說明邊界）：元件裡新硬編的顏色（如 text-[#059669]）不在
 * token 層，這裡看不到。那類要靠 code review 或瀏覽器稽核。
 */
```

門檻常數與金額案例（`:80`、`:91-108`）：

```ts
const AA_BODY = 4.5;

describe("師傅站語意彩字（金額 / 完成 / 待補）對比度", () => {
  const cases: Array<[string, string]> = [
    ["--text-money", "金額"],
    ["--text-success", "已完成"],
    ["--text-warning", "待補齊"],
  ];

  it.each(cases)("%s（%s）淺色模式鋪在白底 / 頁底都要過 AA", (token) => {
    for (const bg of ["#FFFFFF", lightEffective["--bg-page"]]) {
      expect(contrast(lightEffective[token], bg)).toBeGreaterThanOrEqual(AA_BODY);
    }
  });
```

四站台 `node_modules` 未安裝，本次未跑 vitest；改以該檔 `:25-78` 的同一套解析與計算演算法離線重算 `--text-money`：

### 步驟 4 — aria-live 與錯誤訊息

共用元件 `web/brand-portal/src/components/ui/LiveRegion.tsx:28-45`（四站台各有一份同內容檔）：

```tsx
export default function LiveRegion({
  children,
  politeness = "polite",
  atomic = true,
  visuallyHidden = true,
  className = "",
}: Props) {
  return (
    <div
      role="status"
      aria-live={politeness}
      aria-atomic={atomic}
      className={`${visuallyHidden ? "sr-only" : ""} ${className}`}
    >
      {children}
    </div>
  );
}
```

檔頭（`:6-15`）自述對應 WCAG 4.1.3，並示範 `{error && <LiveRegion politeness="assertive">{error}</LiveRegion>}` 的用法。

實際使用端：

```

web/brand-portal/src/app/dashboard/page.tsx:222:          <LiveRegion politeness="polite">
web/brand-portal/src/app/dashboard/page.tsx:231:          </LiveRegion>
```

即四份元件檔中只有 brand-portal 那份有一個使用點，且該用法為 `polite`（狀態播報），非 TC 所指的錯誤訊息。

其餘 `aria-live` 的直接命中只有一處：`web/brand-portal/src/components/conversations/ChatTimeline.tsx:157-165`

```tsx

      ref={scrollRef}
      role="log"
      aria-label="對話訊息列表"
      aria-live="polite"
      aria-relevant="additions"
```

錯誤訊息的主要標記是 `role="alert"`（隱含 `aria-live="assertive"`），命中數：brand-portal 15、tech-portal 8、landing 5、platform-console 10。

錯誤文案來源集中於 `web/brand-portal/src/lib/apiError.ts:109-123`：

```ts
export function friendlyError(e: unknown): string {
  if (e instanceof ApiError) {
    if (looksUserFriendly(e.message)) return e.message;
    const mapped = CODE_MESSAGES[e.errorCode];
    if (mapped) return mapped;
    return fallbackByStatus(e.status);
  }
  if (e instanceof Error) {
    if (e.name === "AbortError") return "請求已取消。";
    // fetch 連線失敗（後端未啟動／網路中斷）
    if (e.name === "TypeError" && /fetch/i.test(e.message)) return "連線失敗，請檢查網路後再試。";
    if (looksUserFriendly(e.message)) return e.message;
  }
  return "操作失敗，請稍後再試。";
}
```

該檔檔頭（`:4-13`）自述目的是把英文錯誤碼與 HTTP 狀態碼轉為繁中單行訊息。
