## 事實結論

1. repo 內無 LIFF 前端專案：`web/*/package.json` 對 `liff` 零命中，`web/` 內 `liff` 僅出現於文案與註解。
2. `LIFF_TOKEN_EXPIRED` 只存在於 `api/openapi.yaml`（5 處），`api/routers` 與 `api/services` 零命中。
3. 客戶確認流程在程式碼中的實體落點是 brand-portal 四支 token 公開頁，於 `AuthGuard.tsx:42-47` 列為永遠可看的公開前綴。
4. 四支頁面皆有 `<main>` 與 `<h1>`，錯誤區皆帶 `role="alert"`，載入骨架皆帶 `aria-busy` + `aria-label`。
5. 確認／拒絕／送出皆為原生 `<button>`；同意書勾選為 `<label>` 隱式包住 `<input type="checkbox">`。
6. 成功態只有 `scope-change/[token]:339` 帶 `role="status"`，其餘三頁為一般 `<div>`。
7. skip link 目標 `#main-content` 在 brand-portal 僅三頁定義，四支客戶頁不在其中。
8. 全 repo 無 axe 或其他自動化 a11y 掃描設定。
9. NVDA / VoiceOver 朗讀結果與 n=10 任務成功率屬執行期量測，本次未取得。
