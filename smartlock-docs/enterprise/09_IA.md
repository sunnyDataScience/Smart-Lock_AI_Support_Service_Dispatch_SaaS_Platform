# 資訊架構 — Smart Lock AI 客服與派工 SaaS 平台（web 多 portal）

> 本文件給前端、設計系統、導覽 / 權限設計者：多 portal 的頁面組織、導覽結構、角色隔離、命名分類與 token 公開頁組成。
> 逐頁 UI 規格屬 [10_UI_Spec](./10_UI_Spec.md)；流程分支見 [08_User_Flow](./08_User_Flow.md)。

---

## 1. IA 總覽

web 前端採**單一 codebase → 多 portal 分站模型**（web ADR-001）：一份 Next.js codebase 以 build-time 旗標 `NEXT_PUBLIC_APP_MODE` 塑出 4 個對外 portal，共用元件庫、gate 邏輯、api client、型別與設計系統（單一真相源，零重複）。

```
單一 codebase（smartlock-admin）
 ├── APP_MODE=dispatch  → 品牌營運後台   :3000（per-brand bundle 內）
 ├── APP_MODE=tech      → 師傅工作台     :3001（歸屬 technician-platform，跨品牌一套）
 ├── APP_MODE=platform  → 平台 console   :3003（平台中央部署）
 ├── APP_MODE=landing   → 導入行銷頁     :3002（公開）
 └── 客戶 token 公開頁（跨 portal，無登入態）
```

部署歸屬（ADR-P005）：**dispatch portal 屬 per-brand bundle**（每品牌一套物理隔離）；**師傅端屬技師共享池（technician-platform）跨品牌一套**；**platform console 由平台中央部署**。師傅 web 與品牌 bundle 的物理拆分 🔜 規劃中（sitemap 結構已按此歸屬組織）。

## 2. Portal 分站與角色映射

| Portal | Port | 服務角色（四方模型） | 後端 api surface | 登入 |
|---|---|---|---|---|
| dispatch | 3000 | 品牌營運（派工小編・租戶 Admin） | dispatch api :8001（REST + WS） | Casdoor OIDC |
| tech（師傅 web） | 3001 | 簽約師傅（跨租戶身分） | tech api :8002（WS 經 :8001 即時 hub） | Casdoor OIDC（技師身分） |
| platform | 3003 | 平台管理員（Super Admin） | platform api :8003 | Casdoor OIDC（平台身分） |
| landing | 3002 | 潛在加盟品牌 / 潛在師傅（訪客） | :8001 + 品牌申請直打 :8003 | 無登入態 |
| token 公開頁 | 隨 portal | 終端客戶 | :8001 | 無登入（簽章 token） |

每個 portal 獨立 origin、token 各自隔離；portal 之間以絕對 URL 互導（跨端 CTA 集中解析：`techRegisterHref` / `dispatchLoginHref` / `brandApplyHref`）。

## 7. 客戶 token 公開頁群（跨 portal，無登入態）

終端客戶不持帳號，跨出 LINE 的操作走**簽章 token 公開頁**（URL 含一次性簽章 token，免登入、過期失效）：

| 路由 | 用途 | 對應流程 |
|---|---|---|
| `/track/[token]` | 工單進度追蹤（師傅 ETA / 狀態） | [08 §5](./08_User_Flow.md) |
| `/quotes/[token]` | 報價明細檢視 + 確認（僅總額 / 實收） | 08 §4 |
| `/consent/[token]` | 免責 / 個資同意簽署 | 08 §6 |
| `/scope-change/[token]` | 現場加價（範圍變更）同意 | 08 §6、§8.3 |

設計約束：頁內金額與明細**只在此呈現**（LINE 訊息不含數字）；成本拆分欄位不出現在客戶面。

## 8. 導覽與 gate 模型

三層 client gate 疊加（皆為 **UX 分站 / 導覽層**，真正授權在 api `role_required` deny-by-default enforce）：

| 層 | 元件 | 職責 |
|---|---|---|
| 1. 分站 gate | `appMode.crossModeRedirect` | 判定當前 portal build 是否服務此路徑，否則導向對方 portal（路由範圍表見 [08 §2](./08_User_Flow.md)） |
| 2. 認證 gate | `AuthGuard`（掛 root layout） | 公開頁判定 + 登入態檢查；未登入導 OIDC 登入；角色來源 = Casdoor OIDC role claim（🔜 全面接線規劃中） |
| 3. 角色 gate | `rolePolicy.canAccessRoute` | route → roles 對應表（longest-prefix-wins）；**未登記路由一律拒絕（deny-by-default）**，新增頁面強制登記 |

導覽同源：Sidebar 導覽項過濾與路由 gate **共用同一份 rolePolicy 表**，避免「看得到進不去」或「看不到但打 URL 能進」的漂移。無權限時導向該角色安全落點（fail-closed，不渲染半成品頁）。

## 9. 角色 × 頁面可見性隔離矩陣（四方模型）

矩陣原則：**context-aware visibility**（同一資源在不同生命週期階段可見性不同）+ **fail-closed**（矩陣未列 = 拒絕）。角色權威 = ADR-P006 四方模型。

| 頁群（資源域） | 終端客戶 | 派工小編 | 租戶 Admin | 簽約師傅 | Super Admin |
|---|:--:|:--:|:--:|:--:|:--:|
| token 公開頁（track/quotes/consent/scope-change） | ✅（限自己案件 token） | — | — | — | — |
| dashboard / conversations / problem-cards | — | ✅ | ✅ | — | — |
| work-orders / dispatch-queue / material-requests | — | ✅ | ✅ | ➖（僅自己被派的，經師傅 web 投影） | — |
| quotes / quote-catalog / customers | — | ✅ | ✅ | ➖（僅自己工單的報價摘要） | — |
| accounting / refunds / payout-rules / inventory | — | ➖（發起，不可核准高額） | ✅ | ➖（僅自己的 statement） | — |
| knowledge-base（cases/manuals/sop-drafts/family-reviews） | — | ✅（讀 + 草稿提交） | ✅（審核） | — | — |
| reports / kpi / technician-ranking / revenue | — | ➖（唯讀） | ✅ | — | — |
| admin/roles / staff / config-governance / audit-events | — | — | ✅ | — | — |
| 師傅 web（home/pool/my-orders/account） | — | — | — | ✅ | — |
| platform（brand-applications / technician-approvals） | — | — | — | — | ✅ |
| 跨租戶資料 | — | — | — | ✅（自身跨品牌身分資料） | ✅（治理面） |

註記：

- ✅ 完整存取；➖ 受限存取（唯讀或限自身範圍）；— 不可見。
- **細格權威在 api**：每格背後對應 api resource-level `role_required`（資源 × 操作 CRUD 展開後逐端點 enforce）；前端矩陣僅為導覽鏡像，兩者以後端為準對齊。
- **租戶隔離**：所有品牌側頁面隱含 `tenant_id` 邊界（一品牌一庫物理隔離）；無有效租戶上下文的請求一律拒絕並導登入，不退回任何預設租戶。
- **技師跨租戶**：師傅在師傅 web 見到的是跨品牌彙整的**自身**資料（工單投影欄位最小化：摘要 / 地址 / 狀態 / 時窗），不見任何品牌內部營運資料。

## 10. 命名與分類法

| 類型 | 慣例 | 範例 |
|---|---|---|
| 路由目錄 | `kebab-case`，依**業務域**組織（非依頁面類型） | `work-orders/`、`dispatch-queue/`、`knowledge-base/` |
| 動態路由段 | `[camelCase]` | `[id]`、`[token]` |
| React 元件 | `PascalCase.tsx` | `AuthGuard.tsx`、`DataTable.tsx`、`TechShell.tsx` |
| Hook | `use{名稱}.ts` | `usePaginatedFetch.ts`、`useRealtimeChannel.ts` |
| lib 工具 | `camelCase.ts`（橫切關注單一真相源） | `appMode.ts`、`rolePolicy.ts`、`api.ts` |
| 生成型別 | `*.generated.ts`（由 OpenAPI 契約生成，勿手改） | `api.generated.ts` |

### 模組化頁群分類骨架

頁群依業務域聚類，與後端限界上下文對齊：

| 業務域 | 頁群 | 對應上下文 |
|---|---|---|
| 進線與對話 | conversations、problem-cards、sentiment-alerts | CustomerSupport（agent） |
| 工單與派工 | work-orders、dispatch-queue、dispatch-manual、material-requests、technicians | DispatchOperations（api） |
| 報價與金流 | quotes、quote-catalog、accounting、refunds、payout-rules、disputes、warranty-claims | DispatchOperations 金流軌 |
| 知識 | knowledge-base（cases/manuals/sop-drafts/family-reviews） | Knowledge（knowledge-refinery + pgvector 語料） |
| 治理 | roles、staff、config-governance、audit-events、exceptions、vendor-approvals | PlatformGovernance |
| 師傅端 | home、pool、my-orders、account | Technician（technician-platform） |
| 平台 | platform/* | PlatformGovernance（跨租戶） |

新增頁面規則：先歸業務域再開路由；同域頁共用該域 `components/{domain}/` 元件；跨域共用元件放 `components/ui/`；新路由必須同步登記 rolePolicy（deny-by-default，漏登記即無人可見）。
