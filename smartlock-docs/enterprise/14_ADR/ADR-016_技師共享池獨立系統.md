# ADR-016: 技師共享池獨立系統（跨租戶單一真相）

| 欄位 | 內容 |
|---|---|
| 狀態 | Accepted |
| 層級 | 平台級 |
| 關聯 ADR | [ADR-002](./ADR-002_per-brand授權部署.md) · [ADR-017](./ADR-017_技師平台佣金邊界與工單CQRS投影.md)（refines 本 ADR）· [ADR-006](./ADR-006_即時高併發骨幹_Kafka_Redis_讀寫分離.md) · [ADR-004](./ADR-004_Casdoor統一IdP租戶License.md) |

## Context（背景與問題）

**技師是跨品牌身分**：一個鎖匠可服務多個品牌。但平台部署模型為 per-brand 物理隔離（[ADR-002](./ADR-002_per-brand授權部署.md)）——若把技師切進單一品牌 bundle，同一技師在多品牌重複、無單一真相；若把技師庫綁在某一品牌的 api 內，跨品牌一致性只能靠跨庫雙寫，脆弱且與物理隔離矛盾。

## Decision（決策）

**Technician Platform 為獨立系統（跨租戶共享技師池）**：

1. **職責**：技師身分、技能、品牌授權、認證（KYC / certification）、排班、評分、佣金結算主體（精確界定見 [ADR-017](./ADR-017_技師平台佣金邊界與工單CQRS投影.md)）；**含獨立師傅 web**（師傅上線註冊 / 工作台 / 技師後台）——師傅端不放進品牌 bundle，讓品牌可獨立部署整套單體。
2. **資料**：技師平台自有庫 `lock_tech` 為技師身分**單一真相源**（[ADR-020](./ADR-020_三庫物理隔離租戶模型.md)）；品牌側以 API 讀取 / 事件訂閱取得投影（唯讀），不直連技師庫。
3. **邊界**：各品牌的派工 / 工單平台（api）經 **OHS API + 事件（Kafka）** 串接技師平台（Customer-Supplier / ACL 模式）——技師查詢 / 媒合 / 排班走 OHS API，技師狀態變更走事件。
4. **身分**：技師認證接 Casdoor（跨租戶身分，[ADR-004](./ADR-004_Casdoor統一IdP租戶License.md) / [ADR-005](./ADR-005_四方RBAC模型與enforce.md)）。
5. **部署**：技師平台為**跨品牌集中共用元件**（非 per-brand，[ADR-002](./ADR-002_per-brand授權部署.md)）。

## Alternatives（考量的選項）

- **A：技師切進各品牌部署** — 違反「技師跨品牌共享」，同一技師多品牌重複、無單一真相。
- **B：技師共享庫綁在品牌 api（跨庫雙寫 mirror）** — 耦合深，per-brand 部署下 mirror 複雜且無 ACID 保證。
- **C：技師獨立成一套系統（共享池），由工單平台串接（採用）** — 清晰邊界，跨租戶單一真相。

## Consequences（後果）

**正面**：技師跨品牌共享、單一真相；邊界清晰；per-brand 隔離與共享技師不再矛盾。
**風險**：新增系統邊界 + 跨系統整合成本；派工需經 contract 呼叫技師平台（延遲 / 可用性依賴）→ 契約測試（consumer-driven）+ 快取緩解。
**影響範圍**：technician-platform 系統文件集（見 [../technician-platform/](../../technician-platform/)）；api 技師相關端點改為串接；`lock_tech` 為技師平台自有庫。
**重評觸發**：若最終只單一品牌營運 → 技師平台可退化為 api 內模組。
