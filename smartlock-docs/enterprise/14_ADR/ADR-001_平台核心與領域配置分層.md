# ADR-001: 平台核心 vs 領域配置分層（TRIZ 按系統層級分離）

| 欄位 | 內容 |
|---|---|
| 狀態 | Accepted |
| 層級 | 平台級 · 奠基性 |
| 關聯 ADR | [ADR-009](./ADR-009_Model_Orchestration_Layer.md) · [ADR-013](./ADR-013_Flow-as-Blocks宣告式DSL.md) · [ADR-014](./ADR-014_AI_Onboarding_Compiler_Block_Ontology.md) · [ADR-002](./ADR-002_per-brand授權部署.md) |

## Context（背景與問題）

本平台以智慧鎖（locksmith）為首個垂直產業，但「同時需要工單派工 + AI 客服」的藍領產業是跨產業的真實市場。核心矛盾（TRIZ 物理矛盾）：平台須**同時通用**（跨產業重用）**又專用**（藍領垂直做深）。若為貼合垂直深度而抽象不足，每個新產業都要 fork code；若為通用而過度抽象，垂直體驗做不深。

## Decision（決策）

以 TRIZ「按系統層級分離」化解矛盾：**核心層通用、配置層專用，兩層不在同一處競爭。**

### 可重用平台核心（FDE 永不動）

工單引擎（狀態機執行器）· 客服 agent runtime（LockCore，[ADR-008](./ADR-008_Agent核心採LockCore.md)）· 金流/對帳/結算軌 · 身分/RBAC/租戶/License（Casdoor，[ADR-004](./ADR-004_Casdoor統一IdP租戶License.md)）· 事件/即時骨幹（Kafka/Redis，[ADR-006](./ADR-006_即時高併發骨幹_Kafka_Redis_讀寫分離.md)）· 可觀測性（SigNoz + OPIK，[ADR-007](./ADR-007_可觀測性分層_SigNoz_OPIK.md)）· 技師共享池（[ADR-016](./ADR-016_技師共享池獨立系統.md)）· 共用 UI 元件庫 · provisioning。

### 領域配置層（FDE 每產業調的 4 配置面）

| # | 配置面 | 承載 |
|---|---|---|
| ① | 診斷系統 | 知識核心 + model 編排（[ADR-009](./ADR-009_Model_Orchestration_Layer.md)）+ api 調用效率 |
| ② | 知識精煉 | 產業事實語料 + skill 行為（[ADR-018](./ADR-018_知識精煉獨立服務.md) / [ADR-010](./ADR-010_知識分層_Skill行為驅動_RAG-via-MCP.md)）|
| ③ | 工單/金流 flow | flow DSL + 積木（[ADR-013](./ADR-013_Flow-as-Blocks宣告式DSL.md)）|
| ④ | 後台 UI 組裝 | 共用元件庫組裝畫面 + 自訂 panel |

### 三大地基（工單維運後台通用化）

- **領域模型**：通用核心欄 + JSONB 屬性 + `field_metadata`（產業欄位語義驅動表單/清單/驗證）。
- **後台呈現分兩層**：欄位層配置驅動（`DynamicForm` / `DynamicTable` 吃 metadata）、畫面層元件組裝（+ 自訂 panel）。
- **產業配置打包**：**Vertical Pack 產業包**（`field_metadata` + flow DSL + catalog + knowledge + ui_composition + blocks，版本化）；品牌（租戶）從產業包實例化。locksmith 為首個產業包。

## Alternatives（考量的選項）

- **A：每產業 fork code** — 貼合垂直，但變 N 份分岔，違反重用，維護成本隨產業數線性爆炸。
- **B：一套超集寫死所有產業** — 複雜臃腫，每個垂直都做不深。
- **C：核心通用 + 領域配置分層（採用）** — 垂直深度活在**可組合配置**（深積木、深知識包），非 fork code。

## Consequences（後果）

**正面**：新產業落地 = 裝一個 Vertical Pack + 輕組裝，核心零改碼；重用與垂直深度不再 trade-off（深度活在深積木裡）。
**風險**：抽象化有前置成本；配置層若做淺會退回「通用但不好用」→ 靠深度藍領積木 + 逃生艙（[ADR-013](./ADR-013_Flow-as-Blocks宣告式DSL.md)）緩解；FDE 每產業多一件「UI 組裝」工作。
**影響範圍**：工單/金流/UI 皆依核心 + 配置雙層設計；細部設計於 [15_SDS](../15_SDS.md)。
**重評觸發**：某產業需求根本超出核心原語 → 擴充核心層（而非 fork）。
