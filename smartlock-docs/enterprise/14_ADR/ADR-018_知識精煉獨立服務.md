# ADR-018: 知識精煉獨立服務（draft → HITL 審核 → 寫入）

| 欄位 | 內容 |

## Context（背景與問題）

平台的核心知識資產來自兩處：**每一次與用戶的診斷過程**（LINE 對話 + 客服問題卡）與**產品素材**（YouTube / 影片 / 官網 / 手冊）。設計意圖是把隱性知識**顯性系統化**——融入 AI agent、提煉成 skill 與經驗，且擁有獨立頁面與 UI。LLM 提煉會有品質風險，未經人審直接寫入知識庫等於讓幻覺污染生產客服。

## Decision（決策）

**knowledge-refinery 為獨立容器服務 + 自有 web 操作介面**，且為 **License 開通的附加系統**（非基礎部署必備，[ADR-002](./ADR-002_per-brand授權部署.md) 集中共用元件）。五步管線：

1. **輸入**：診斷對話（LINE `line_chat` + 客服 `problem_cards`）+ 產品素材（YouTube / 影片 / 官網 / 手冊），沿 Medallion `raw→bronze→silver`（[ADR-019](./ADR-019_Medallion分層數據架構.md)）。
2. **提煉（分兩類產物，對齊 [ADR-010](./ADR-010_知識分層_Skill行為驅動_RAG-via-MCP.md) 分工）**：LLM 把 silver 語料分流為——(a) **事實**（逐型號手冊 `manual_chunks` / 案例史 `case_entries`）、(b) **行為 / 精選**（skill 規範、domain-safety、檢索程序）。append-only，不刪改既有。
3. **審核（human-in-the-loop）**：兩類產物皆進 **UI**（diff 檢視、核可、拒絕、退回重煉）。
4. **落地**：核可後——**事實 chunk + embed 灌入 pgvector 唯一事實語料**；**行為 / 精選更新 skill 行為層**（`locksmith-*` 的 SKILL.md / `_common` / `_brand` / domain-safety，git-tracked 可 review / 回溯）。
5. **來源治理**：`pgvector` 為唯一事實語料（agent 經 RAG-via-MCP 取、後台 web/api 查同一語料）；`bronze` 為該語料的來源治理層（bronze-only sourcing）。

## Alternatives（考量的選項）

- **A：離線批次 script（無 UI、無人審）** — 成本低，但無 human-in-the-loop、無法「顯性系統化」，LLM 品質風險直達生產。
- **B：掛進現有 web/api（加 refinery portal + surface）** — 重用骨架，但審核流與離線 LLM 提煉和營運後台耦合，邊界不清。
- **C：獨立服務 + UI（draft → 人審 → 寫入，採用）** — 乾淨解耦、可審計。

## Consequences（後果）

**正面**：隱性知識顯性系統化 + human-in-loop 品質閘門；輸出可審計、可回溯；bronze 單源消除知識漂移。
**風險**：多一個服務的維運成本；UI 需接 Casdoor OIDC（[ADR-004](./ADR-004_Casdoor統一IdP租戶License.md)）；提煉品質仍依賴 LLM，審核閘門為品質防線。
**影響範圍**：knowledge-refinery 系統（見 [../knowledge-refinery/](../../knowledge-refinery/)）；pgvector 語料 ingestion；skill 行為層更新流。
**重評觸發**：審核工作量過大 → 評估自動核可信心門檻 + 抽樣人工審。
