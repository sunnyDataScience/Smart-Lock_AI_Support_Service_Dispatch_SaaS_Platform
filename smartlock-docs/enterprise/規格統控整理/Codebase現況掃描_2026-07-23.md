## 1. 結論

本次主要修正不是新增 FR，而是把原本混在「實作路徑／規劃狀態」的一欄拆成：

1. **需求狀態**：來自 SRS / Roadmap，表示需求定版、階段或待確認。
2. **Code reality**：只表示目前 repo 的 AS-BUILT / PARTIAL / TO-BE。
3. **實作證據路徑**：能回查到實際程式、migration 或部署設定。

統控基線後的主要產品差異為：報價 postback 精確錯誤話術、受保護媒體 `AuthImage`、問題卡序號/照片/客戶資訊承接、免責同意簽署連結，以及 Chatlock-only 樣本圖。ADR-033 另已廢止「三輪未釐清才轉真人」硬計數，改採情境式缺項與紅線即轉。

## 3. 架構勘誤

### 3.1 Technician Platform

舊文件寫「獨立 technician-platform codebase 待確認」，與程式不符。

- 邏輯與資料權威：獨立，真相庫為 `lock_tech`。
- 部署：可用 `web/tech-portal/docker-compose.yml` 形成 `tech-db + tech-api + tech-web` 獨立 stack。
- Codebase：後端共用 `api/`，以 `api/main.py` 的 `API_SURFACE=tech` 塑形；不是另一個 repository。
- 現行媒合：`api/services/dispatch_service.py` 直接透過三庫路由讀 tech authority。
- 目標邊界：OHS / MatchingService；目前仍是 To-Be，不得在 BOM 標成已完成。
- 事件投影：`api/core/event_bus.py`、`api/realtime/event_consumer.py` 與 `SQL/tech_authority/Schema_cqrs_projection.sql` 已存在，但需 `KAFKA_BOOTSTRAP`。

### 3.2 Web

Web 不是單一 codebase 以 APP_MODE 產四站，而是四個獨立 Next.js 專案。各站各自持有：

- `src/components/layout/AuthGuard.tsx`
- `src/lib/{appMode,rolePolicy,api,cache,realtime}.ts`
- `src/types/api.generated.ts`
- lockfile、Dockerfile、docker-compose

`AuthImage / AuthImageLightbox` 位於 `web/brand-portal/src/components/media/AuthImage.tsx`，用 Bearer + `X-Tenant-ID` fetch 受保護媒體後建立 Blob URL，避免裸 `<img src>` 得到 401。

### 3.3 Data / RAG / Refinery

- RAG runtime 在 `agent/rag/rag/`，不在 refinery。
- Medallion 有 `source_to_raw`、`raw_to_bronze`、`bronze_to_silver`、`silver_to_knowledge`。
- 2026-07-17 corpus 報告：facts 862、behavior 0、quarantine 19、missing_bronze 0（`knowledge-pipeline/storage/corpus/_report.json`）。
- Refinery 行為軌目前先產 `behavior patch artifact`；`apply_behavior.py` 預設送 `/internal/skills/ingest` 建 LiveSkill draft，再由品牌後台人工發布。git 落檔只是缺 internal token 時的 fallback。

## 5. 受控元件標籤

`SAD_SDS元件標籤字典.md` 與四份 Excel 已重新由同一份 `COMPONENT_GLOSSARY` 生成。新增或校正的關鍵標籤包括：

- Agent：Photo Guide resolver、Quote postback message mapper、WebhookIdempotencyStore、ReplyGuard、SentimentClassifier、SkillSync。
- API：API_SURFACE router filter、Three-DB Connection Router、DBPoolScopeMiddleware、EventBusProducer、EventConsumerWorker、PG Advisory Cron Leader、Consent link service、Conversation media collector、個資密鑰/盲索引/清除 ledger。
- Web：AuthImage / AuthImageLightbox、ConsentPanel、PIIScrubSpanProcessor。
- Refinery：Casdoor reviewer auth、behavior patch artifact、LiveSkill DB ingest。
- Technician：Tech DB router + mirror、dispatch candidate scoring、technician workorder/commission projections、technician settlement services。
- Platform：License Entitlement Gate、M18 Config Registry、Skill Revision Registry。

每個正式標籤都有「白話定義、責任邊界、Code reality、SAD/SDS 定位、實作證據路徑」。L2 能力群只是顯示分組，不再冒充實際元件。

## 6. 尚未閉環的外部／部署證據

以下不能只靠本次 repo 掃描宣稱完成：

1. `consents:send-link` 已出現在 runtime router 與 generated TS types，但 `smartlock-docs/enterprise/16_API_Spec.yaml`、`api/openapi.yaml` 尚未回填，仍有契約 SSOT 漂移。
2. SigNoz collector、Kafka/Redis/四站/refinery 的 production IaC 與實際部署狀態不在 repo；只能標 PARTIAL 或 deployment-unverified。
3. Refinery compose 尚未完整提供 Casdoor、License、internal skill ingest 與 OTel 所需設定。
4. Tech projection 與完整跨品牌 settlement 需在 Kafka 開啟環境做 SIT/reconcile，不能由 schema/consumer 檔案存在推定通過。
5. `api/core/db.py` 仍允許非 strict fallback；正式 surface 應以 `DB_URI_STRICT=1` 啟動並做三庫負向測試。

這些缺口已保留在 Code reality 欄，不以「需求定版」或「已有程式檔」誤標為完成。
