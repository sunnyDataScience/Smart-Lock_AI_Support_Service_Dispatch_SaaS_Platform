# Plane 模組關係圖（PM 視角）

> **定位**：只講**模組間的關係**，不講欄位。欄位級細節在
> [`PLANE_PRIMITIVES_FIELD_MANUAL.md`](PLANE_PRIMITIVES_FIELD_MANUAL.md)。
>
> 建立：2026-07-28 ｜ status: `active` ｜ 依據：同上手冊（fork 原始碼 + LOCK live 實打）
>
> **一句話**：六大原語只有兩種關係 —— **擁有**（改變卡片歸屬）與**引用**（不改變卡片）。
> 分清這兩種，就能判斷一個變更會不會動到別人的看板。

---

## 1. 容器層級：誰在誰裡面

**巢狀＝歸屬。** 最容易踩的雷是**四個原語其實住在 workspace 而不是專案裡** ——
它們跨專案共享，改了會影響同 workspace 的其他專案（本實例有 `LOCK` 與 `ACMEG` 兩個）。

```
WORKSPACE  acme-god-damn          ← 跨專案共享層，改這裡會波及其他專案
│
├─ Initiative ................... 跨專案戰略成果，掛專案而非掛卡
├─ Work Item Type ............... 卡的種類（is_epic 為真者即 Epic）
│                                 🟥 資料層存在，但 UI 完全不呈現（見 §7）
├─ Label ........................ 可 workspace 共用，也可專案私有
├─ Page ......................... 天生 workspace 級，可同時掛多個專案
│
└─ PROJECT  LOCK
   │
   ├─ 擁有卡片・分組容器
   │  ├─ Cycle .................. 時間盒
   │  ├─ Module ................. 範疇
   │  └─ Milestone .............. 交付閘
   │
   ├─ 定義卡片形狀
   │  ├─ State .................. 工作流（5 個）
   │  ├─ Work Item Property ..... 自訂欄位（11 個）
   │  └─ Intake ................. 收件匣
   │
   └─ 不擁有卡片・只呈現
      ├─ View ................... 存起來的篩選器
      ├─ Page ................... 文件（從 workspace 掛進來）
      └─ Testing ................ 獨立品質資產（見 §3）
```

## 2. Work Item 是關係中心

**所有箭頭都指向 Work Item，但語義不同**：
左側是**掛載** —— 動了會改變卡片歸屬與看板數字；右側是**引用** —— 只是讀取，不影響卡片本身。

```
── 掛載：動了會改變卡片歸屬，看板數字跟著變 ─────────────────────

   Cycle                  ──1:1──▶ ┐
   Module                 ──1:N──▶ │
   Milestone              ──1:1──▶ ├──▶  WORK ITEM
   State                  ──1:1──▶ │     LOCK · 237 張
   Work Item Type         ──1:1──▶ │
   Work Item Property     ──N:N──▶ ┘     ← 關係中心，唯一的真相載體

── 引用：只讀取，不影響卡片本身 ─────────────────────────────────

   View                   ──讀取──▶ ┐    存起來的篩選器
   Page                   ──引用──▶ │    文件內嵌卡片，可反查
   Test Case              ──追溯──▶ ├──▶  WORK ITEM
   Test Result            ──回報──▶ │    缺陷連結
   Test Run               ──切面──▶ ┘    可掛 Cycle / Module 出品質報表

                                          ↑ Test* 三者寫入時強制同專案

── Work Item 自身 ──────────────────────────────────────────────

   父子巢狀（父刪連帶刪子）／ 卡對卡關聯 6 型・8 方向（blocking、relates_to…）
   Assignee N:N ／ Label N:N ／ Comment・Link・Attachment 1:N ／ Activity 稽核 1:N
```

| 記號 | 意思 |
|---|---|
| `1:1` | 一張卡只能歸一個 |
| `1:N` | 一張卡可歸多個 |
| `N:N` | 雙向多對多 |
| `◀` | 引用，不改變卡片 |

## 3. Testing 是獨立資產鏈，不是卡片

測試案例**刻意不做成 Work Item** —— 卡片會被關閉、封存、改狀態，而測試資產要跨迭代重複使用
並保住當時執行的內容（fork ADR 0001）。整條鏈的樞紐是**釘版本**：測試庫改版後，
舊的執行紀錄仍呈現當時那一版。

```
── 測試庫：可編輯，但「編輯」＝開新版，永不改舊版 ────────────────

   Test Folder ................. 目錄樹 · 63
        │                        目錄刪除時案例不刪（SET_NULL）
        ▼
   Test Case ................... 身分與序號 · 130
        │                        編輯發佈＝新增一個版本
        ▼
   Test Case Version ........... ⚑ 建立後不可變
        │
        ▼
   Test Step ................... ⚑ 隨版本一起凍結

── 執行紀錄：只增不改 ───────────────────────────────────────────

   Test Run .................... 一次執行 · 19
        │                        建立時把每張案例「釘」在當時的版本
        ▼
   Test Run Case ............... ⚑ 指向某一版，不是指向案例
        │                        ← 這就是舊 run 內容不會變的原因
        ▼
   Test Result ................. 結果 · 重測＝遞增新增，不覆寫前次失敗
        │
        ▼
   缺陷卡 ──────▶ WORK ITEM .... 失敗才連
```

| PM 關心的問題 | 由誰回答 |
|---|---|
| 需求覆蓋率怎麼算出來的 | Test Case ↔ Work Item 追溯連結。LOCK 實測 130 案例、128 已連需求、**覆蓋率 98.5%** |
| 為什麼規格卡與測試庫必須同專案 | 追溯連結寫入時**強制同專案**（`TestCaseWorkItemLink`），跨專案掛不上 |
| 為什麼舊 run 的內容不會變 | `TestRunCase` 釘的是 **version** 而非 case |

## 4. 四種分組原語的分工

這四個都能「把卡片圈成一組」，但回答的是**不同問題**。混用會讓看板失去意義 ——
最常見的錯誤是**拿 Module 當迭代用**。

| 原語 | 回答什麼問題 | 一張卡能歸幾個 | 層級 | PM 用途 |
|---|---|---|---|---|
| **Cycle** | 什麼時候做 | 1 | 專案 | 迭代 / sprint 容量與燃盡 |
| **Module** | 屬於哪一塊 | N | 專案 | 子系統 / 功能領域進度 |
| **Milestone** | 過哪一道閘 | 1 | 專案 | 對外承諾的交付檢查點 |
| **Initiative** | 為了哪個目標 | 跨專案 | **Workspace** | 戰略層，掛專案而非掛卡 |
| **Work Item Type** | 這是什麼種類的卡 | 1 | **Workspace** | Epic / Story / 需求分層 |
| **Label** | 自由標記 | N | 兩者皆可 | 臨時切面，不建議承載流程 |

## 5. 哪些模組能自動化

規劃任何自動化或報表前先看這張。**三個原語目前完全無法用 API 金鑰操作**，只能人工進 UI 點。

| 模組 | REST API | MCP 工具 | PM 影響 |
|---|---|---|---|
| **Work Item** 及其子資源 | ✅ | ✅ | 可全自動化 |
| **State · Label** | ✅ | ✅ | 可全自動化 |
| **Cycle · Module · Milestone** | ✅ | ❌ 壞 | 要寫腳本走 REST，不能靠 MCP |
| **Initiative** | ✅ | ❌ 壞 | 同上 |
| **Work Item Property** 自訂欄位 | ✅ | ⚠️ **回空** | MCP 靜默回空陣列，比報錯危險 |
| **Testing** 全部 | ✅ | ❌ 無工具 | 品質報表只能走 REST |
| **View** | ❌ 無 | ❌ 無 | **只能手動建，無法納入自動化** |
| **Page** | ❌ 無 | ❌ 壞 | **只能手動建**，文件無法程式化同步 |
| **Estimate** 估點 | ❌ 無 | ❌ 壞 | **只能手動設**，卡片點數無法批次匯入 |

## 6. PM 需要記住的三件事

**① Work Item 是唯一的真相載體，其他都是它的切面。**
Cycle / Module / Milestone 只是不同的圈選方式，進度數字全是即時從卡片的**狀態分組**算出來的，
不是各自記一份。所以改一張卡的狀態，三個看板的數字會同時動。

**② Workspace 層的四個原語是跨專案共享的。**
Initiative、Work Item Type、Label、Page 住在 workspace。改它們會波及同 workspace 的其他專案。

**③ View 與 Page 進不了自動化，排流程時要當人工步驟。**
它們沒有可用 API 金鑰的介面（內部 API 只吃 session cookie，實測 401）。任何
「自動產生視圖 / 自動同步文件」的規劃在這個實例上做不到，除非改後端 —— 屬架構變更，須走 CIA。

## 7. 🟥 Work Item Type 在 UI 上看不到

**這個實例的 web UI 沒有任何 work item type 的呈現面**，資料只活在 API 與報表裡。

| 你期待看到的地方 | 實際 |
|---|---|
| 建卡表單選型別 | 元件 return `<></>`，**沒有下拉** |
| 卡片篩選器按型別篩 | return `null`，**篩選器沒這一項** |
| 卡號旁的型別圖示 | 型別變體 return `<></>`，**只印 `LOCK-241`** |
| 卡片詳情切換型別 | 降級為只顯示卡號，**不能切** |
| 活動紀錄顯示型別變更 | return `<></>`，**不記錄** |
| 專案設定開關 | 「功能」頁只有 cycles / modules / views / pages / intake **5 個**，沒有型別開關 |

**原因**：型別是上游 Plane 的付費版（EE）功能。`@/plane-web/*` 別名指向 `./ce/*`，
repo 內**沒有 `ee/` 目錄**，跑的一定是 CE stub，而 CE stub 全部回空。
fork 的 commit `feat: add CE work item extensions` 加的是 **API**，沒有補 UI。

**PM 影響**：拿 type 做 Epic／需求分層是可行的，但**分層只在 API、報表、匯出看得到**。
人進 UI 既看不到也改不了型別 —— 若要讓人在看板上分辨卡的種類，
現階段只能改用 **Label**（UI 完整支援）或標題前綴。要補 UI 屬架構變更，須走 CIA。

### 🟥 自訂欄位（Work Item Property）同樣沒有 UI

`apps/web/core/hooks/use-issue-properties.tsx` 是 **16 行空實作**，收下參數後直接 `return;`。
所以匯入時寫進 `custom_properties` 的 11 個欄位（`canonical_id`、來源檔名、負責角色…）
**人在 UI 一個都看不到**，只有 API 與報表讀得到。

### 結論：這個版本「機器可讀 ＋ 人看得見」的軸只剩五種

| 機制 | UI | API | 適合拿來表達 |
|---|---|---|---|
| **Label** | ✅ | ✅ | 旅程歸屬、節點標記、任意切面 |
| **Milestone** | ✅ | ✅ | 驗收閘（1 卡 1 個）|
| **Cycle** | ✅ | ✅ | 迭代（1 卡 1 個）|
| **父子巢狀** | ✅ | ✅ | 工作包切細後的子卡 |
| **關聯 relations** | ✅ | ⚠️ 只有 8 種型別 | 卡與卡的追溯（無 `implements`，只能用 `relates_to`）|
| ~~Work Item Type~~ | ❌ | ✅ | 僅 API／報表 |
| ~~自訂欄位~~ | ❌ | ✅ | 僅 API／報表 |
