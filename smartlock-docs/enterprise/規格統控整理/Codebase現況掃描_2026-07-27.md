1. **需求狀態**仍由 SRS / Roadmap 決定。

## 3. 與前次快照相比的已驗證變更

### 3.1 Agent：交接兜底不再以整句關鍵字判斷

`line_gateway` 的「LLM 承諾轉人卻未呼叫工具」兜底，已改為：

- marker 前才會抑制的條件／評估語氣；
- 子句級否定判定；
- 徵詢客戶同意的問句判定；
- 真承諾但句尾有「可能需要一點時間」時仍必須接住。

這修正兩種相反風險：條件句被誤判會把對話翻成人工接管、造成 AI 靜音；真承諾被漏判則造成案件蒸發。語料回歸與兩個端對端案例已進 `agent/tests/test_line_gateway.py`。這是 **AS-BUILT 的程式／測試證據**，不是客服營運品質已被 production 驗收的聲明。

### 3.2 API 安全：已補跨面與敏感讀取守衛，但需部署驗證

- CR-0182 在 token 加入 portal claim，`get_current_user` 以 `ALLOWED_TOKEN_PORTALS` 阻絕技師、品牌、平台 token 跨 API surface；SSO token 缺 claim 時由角色推導。未設環境變數時維持本機／測試相容行為。
- CR-0183 為同面敏感 GET 補 `role_required`，並再補 legacy `/api/v1` 孿生端點與明細／stats 漏洞；`scripts/ci/endpoint-guard-audit.py` 防止日後只修 v2 而留下繞過路徑。
- 品牌登入 decorator、技師／平台 CORS 與 API base 對映、platform surface 缺 `TECH_POSTGRES_URI` 導致的技師權威庫 split-brain，均已有程式修正與對應測試／deploy script。

這些修正降低已發現的權限與部署風險，但 Cloud Run 實際環境是否已帶齊 `ALLOWED_TOKEN_PORTALS`、三庫 URI 和重建後的 Web bundle，仍需 production smoke / SIT 證據。

### 3.3 資料與稽核：三庫治理能力已增加

- migration registry 現到 **116**；115 將報價有效期與 confirm token TTL 統一為 7 天且 expired 單保留；OpenAPI runtime、靜態 `api/openapi.yaml`、四站 generated types 已同步此變更。
- 116 建立 audit hash-chain checkpoint，verify 可從受核准的歷史基準後檢查並回報所有後續斷點；不是刪改舊 audit event。
- `apply-schema-routed.sh` 依 `migrate-targets` 分流至品牌、技師、平台庫；drift check 已能逐庫比對。這補強「三庫 schema 不能只靠品牌庫 migration 水位」的治理能力。
- 技師鏡射私有加密欄、忘記密碼缺表、授／撤證 CHECK 與平台核准技師寫錯投影庫等已修正，防止註冊 500、鏡射靜默漂移與核准後仍不能登入。

任何環境是否已套 migration 115/116、三庫 ledger 是否一致，仍只能由該環境 `schema_migrations` 與實際操作證據判定。

### 3.4 本機品質閘與隔離測試能力已補強，但不替代 SIT/UAT

- `reply_guard` 新增中文數字價格與非單一品牌型號的確定性守門；型號清單與 knowledge references 的回歸測試綁定，避免新增產品時無聲漏守。它是 agent redline 的程式／測試證據，需重新部署才會改變線上行為。
- 四個 web portal 均有 ESLint 9 flat config 與 CI matrix 的 `tsc --noEmit + eslint`；目前警告保留為可見技術債、退出碼 0，不可把「CI 可跑」說成前端 UX／安全已驗收。
- `scripts/db/make-test-db.sh` 以 dump + migration 建立拋棄式 scratch DB，避免 DB component tests 污染手動 UAT 庫；它解除本機完整 pytest 的環境封鎖，但產出仍屬 RD/QA 測試結果，不是 SIT 或業務 UAT 簽核。

## 4. 仍未閉環：不要因本次程式更新而誤標完成

1. **靜態契約漂移（本次已回填）**：`consents:send-link` 已在 runtime router、四站 generated types、`api/openapi.yaml` 與 `16_API_Spec.yaml` 同步；仍須於 SIT 由 runtime OpenAPI export 確認 operationId 與回應實際契約，不能以 YAML 更新替代環境驗證。
2. **部署／SIT 證據**：Redis、Kafka、RAG、Casdoor、Refinery、SigNoz 都有 opt-in 或 code-present 成分；尚無 repo 內證據可宣稱 production 已啟用、可告警或完成回復演練。
3. **Web 安全過渡**：前端未列路由預設放行、預設 tenant fallback、localStorage token 過渡仍存在。前端本來就不是安全邊界，但這些 UX／資料指向行為應以 ACT-01～03 關閉，不能當成永久設計。
4. **技師平台目標邊界**：現行程式仍有共用 API codebase、interim mirror 與 opt-in Kafka；OHS / MatchingService、完整 CQRS 和跨品牌 settlement 不能標為已完成。
5. **驗收不是程式掃描**：SC × TC 的 V2/V7/V9/V10 缺口、P0 無 UAT 腳本、NFR 實測門檻，須由 QA／業務 Owner 以案例與簽核閉環。
